Before you start

This lesson builds on:

  • Lesson 4: Probability & Statistics — Probabilities run from 0 to 1. Bayes' theorem turns $P(B\mid A)$ into $P(A\mid B)$. Mean and standard deviation summarise data; the z-score $(x-\mu)/\sigma$ standardises it.
  • Lesson 6: Linear Regression — Linear regression predicts $\hat{y} = \mathbf{w}\cdot\mathbf{x} + b$ and chooses the weights that minimise the mean squared error (least squares). $R^2$ measures the share of variance explained.
  • Lesson 7: Gradient Descent — Gradient descent trains almost any model: compute the gradient of the loss, step against it, repeat. The learning rate controls the step size; too large diverges. Mini-batches make it fast on big data.

Where this fits: Moves from predicting numbers to predicting categories. A logistic regression is also exactly what a single neuron in a neural network computes.

1.From numbers to categories

So far we've predicted numbers. Many of the most useful questions are yes/no: Is this email spam? Will this customer cancel? Is this tumour malignant? Will this student pass? These are binary classification problems: the label $y$ is either $1$ ("yes", the positive class) or $0$ ("no", the negative class).

Logistic regression is the standard first model for this. Despite its name it is a classifier. It doesn't just say yes or no; it outputs a probability — "83% likely to pass" — which is far more useful for real decisions.

Running example: predict whether a student passes an exam ($y=1$) from the hours they studied ($x$).

Hours $x$0.511.522.533.544.55
Passed $y$0001010111

More study generally helps, but it isn't a guarantee — exactly the kind of uncertainty probabilities describe.

2.Why not just use linear regression?

We could fit a straight line to the 0s and 1s and call anything above 0.5 a "pass". It works poorly:

  • A line goes on forever, so it predicts values like $1.4$ or $-0.3$ — meaningless as probabilities.
  • One student who studied 40 hours would drag the whole line flatter, shifting the decision point for everyone.
  • The squared-error loss isn't the right way to measure the quality of yes/no predictions.

We need a function that takes any number and squashes it into the range 0 to 1.

3.The sigmoid function

The sigmoid (or logistic) function does exactly that:

$$\sigma(z) = \frac{1}{1 + e^{-z}}$$

where $e \approx 2.718$. Some values:

z−4−2−10124
σ(z)0.0180.1190.2690.50.7310.8810.982
  • Large positive $z$ → close to 1. Large negative $z$ → close to 0.
  • $\sigma(0) = 0.5$ exactly: the point of maximum uncertainty.
  • Symmetry: $\sigma(-z) = 1 - \sigma(z)$.
  • Its derivative has a neat form: $\sigma'(z) = \sigma(z)\,\big(1 - \sigma(z)\big)$. We'll use this shortly.
Picture it

The sigmoid is an S-shaped curve: flat near 0 on the far left, a smooth climb through 0.5 in the middle, flat near 1 on the far right. It turns an unlimited "score" into a "confidence".

Step-by-step derivationDerive the sigmoid's derivative $\sigma'(z) = \sigma(z)(1 - \sigma(z))$
  1. $$\sigma(z) = (1 + e^{-z})^{-1}$$

    Write the sigmoid as a power.

  2. $$\sigma'(z) = -(1 + e^{-z})^{-2}\cdot(-e^{-z}) = \frac{e^{-z}}{(1 + e^{-z})^2}$$

    Chain rule: outside $u^{-1}$, inside $u = 1 + e^{-z}$, whose derivative is $-e^{-z}$.

  3. $$= \frac{1}{1 + e^{-z}}\cdot\frac{e^{-z}}{1 + e^{-z}}$$

    Split into two fractions.

  4. $$\frac{e^{-z}}{1 + e^{-z}} = \frac{(1 + e^{-z}) - 1}{1 + e^{-z}} = 1 - \sigma(z)$$

    Rewrite the second fraction.

  5. $$\sigma'(z) = \sigma(z)\,\big(1 - \sigma(z)\big)$$

    The first fraction is $\sigma(z)$. This tidy result is why the log-loss gradient simplifies to $p - y$.

4.The logistic regression model

Take the linear model from Lesson 6 and pass its output through the sigmoid:

$$z = \mathbf{w}\cdot\mathbf{x} + b \qquad\qquad p = \hat{y} = \sigma(z) = \frac{1}{1 + e^{-(\mathbf{w}\cdot\mathbf{x} + b)}}$$

$z$ is a score (any number); $p$ is the predicted probability that the example belongs to class 1: $p = P(y = 1 \mid \mathbf{x})$.

Worked example — using a trained model

Trained on the study data (we'll see how below), the model is $z = 1.354\,x - 3.723$.

A student who studied 2 hours: $z = 1.354\times2 - 3.723 = -1.015$, so $p = \sigma(-1.015) = \frac{1}{1+e^{1.015}} \approx 0.27$. A 27% chance of passing.

A student who studied 4 hours: $z = 1.354\times4 - 3.723 = 1.693$, so $p \approx 0.84$. An 84% chance.

Make sense of it

The situation: A tutor uses past results to tell each student their chance of passing from how many hours they studied.

What the result tells you: 27% and 84% are probabilities, not grades: among many students who study 2 hours, about 27 in 100 pass.

What if…?

  • No study at all: $p = \sigma(-3.723) \approx$ 2%.
  • The 50% point is where $z = 0$: $x = 3.723/1.354 \approx$ 2.75 hours. That's the decision boundary at a 0.5 threshold.
  • 6 and 8 hours: about 99% and 99.9%. The curve flattens — extra hours add less and less probability.

Why it matters in ML: The sigmoid turns any score into a probability between 0 and 1. The threshold that turns it into a yes/no decision is a separate choice, set by the cost of each kind of mistake (Lesson 9).

  • p — predicted probability of class 1

  • w · x + b — a linear score, exactly as in linear regression

5.From probability to a decision: the decision boundary

To output a class, pick a threshold, usually 0.5: predict 1 if $p \ge 0.5$, else 0. Since $\sigma(z) \ge 0.5$ exactly when $z \ge 0$, the rule is simply:

$$\text{predict } 1 \iff \mathbf{w}\cdot\mathbf{x} + b \ge 0$$

The set of points where $\mathbf{w}\cdot\mathbf{x} + b = 0$ is the decision boundary. For the study data: $1.354x - 3.723 = 0 \Rightarrow x \approx 2.75$ hours. Below that we predict "fail", above it "pass".

With two features the boundary is a straight line; with three, a plane. Logistic regression is therefore a linear classifier — it separates classes with a straight boundary. (Curved boundaries need extra features, or models like those in Lessons 11–15 and 18.)

The threshold is a choice

For cancer screening you might flag anyone with $p \ge 0.1$, accepting more false alarms to miss fewer real cases. For a spam filter you might require $p \ge 0.9$ so real emails are rarely lost. Lesson 9 shows how to measure this trade-off.

6.Interpreting the weights: odds

In plain wordsEach weight tells you how a feature changes the odds: a positive weight makes class 1 more likely, a negative weight less likely, and bigger weights mean stronger effects.

The odds of an event are $\frac{p}{1-p}$: a probability of 0.8 is odds of $0.8/0.2 = 4$ ("4 to 1"). Solving the model for $z$ gives:

$$\ln\!\left(\frac{p}{1-p}\right) = \mathbf{w}\cdot\mathbf{x} + b$$

So logistic regression is a linear model for the log-odds (also called the logit). That gives the weights a clean meaning: increasing feature $x_j$ by 1 multiplies the odds by $e^{w_j}$.

Worked example

With $w = 1.354$: $e^{1.354} \approx 3.87$. Each extra hour of study multiplies a student's odds of passing by about 3.9. A negative weight would shrink the odds instead.

Make sense of it

The situation: Odds are how bookmakers talk: 3 to 1 means three times as likely to happen as not.

What the result tells you: A weight of 1.354 means each extra hour multiplies the odds of passing by $e^{1.354} \approx 3.87$. The probability doesn't go up by a fixed amount, but the odds do go up by a fixed factor.

What if…?

  • From 2 to 3 hours: odds go from 0.36 (p = 0.27) to $0.36 \times 3.87 \approx 1.40$ (p = 0.58).
  • A weight of 0 gives a factor of $e^0 = 1$: the feature doesn't change the odds at all.
  • A weight of −0.5 gives a factor of 0.61: each unit reduces the odds by about 39%.

Why it matters in ML: This is how logistic-regression results are reported in medicine and credit scoring: "each extra year of age multiplies the odds of default by 1.05". Remember it's an association in the data, not proof of cause.

7.The loss: log loss (cross-entropy)

In plain wordsLog loss measures how good the predicted probabilities are. It gives a tiny penalty for being confident and right, and a huge penalty for being confident and wrong.

How do we measure how wrong a probability is? If the truth is $y = 1$, we want $p$ close to 1; if $y = 0$, we want $p$ close to 0. The standard loss for one example is log loss, also called binary cross-entropy:

$$\ell(p, y) = -\big[\,y\ln p + (1 - y)\ln(1 - p)\,\big]$$

Only one of the two terms is active at a time:

  • If $y = 1$: $\ell = -\ln p$.
  • If $y = 0$: $\ell = -\ln(1 - p)$.
Worked example — how log loss punishes confident mistakes

True label $y = 1$:

Predicted $p$Loss $-\ln p$Meaning
0.90.105confident and right — tiny loss
0.50.693unsure — moderate loss
0.12.303confident and wrong — big loss
0.014.605very confident and wrong — huge loss

As $p \to 0$ the loss goes to infinity. Log loss strongly discourages being confidently wrong.

Make sense of it

The situation: A weather app says "1% chance of rain" and it pours. How embarrassed should it be? Log loss puts a number on it.

What the result tells you: The loss is small when the model gives high probability to what actually happened, and grows without limit as that probability approaches zero.

What if…?

  • p = 0.001 on something that happens: loss 6.91.
  • One disaster among many successes: 99 predictions at 0.9 (loss 0.105 each) plus one at 0.001 average to 0.173 — that single confident miss raises the average loss by about 65%.

Why it matters in ML: Log loss rewards honest probabilities, not just correct labels. Training with it pushes models away from overconfidence — and it's the same cross-entropy loss used to train neural networks and language models.

The training loss is the average over all $n$ examples:

$$L(\mathbf{w}, b) = -\frac{1}{n}\sum_{i=1}^{n}\big[\,y_i\ln p_i + (1 - y_i)\ln(1 - p_i)\,\big]$$
Where does this formula come from?

From probability (Lesson 4). The model says example $i$ has label 1 with probability $p_i$. The probability of observing its actual label is $p_i^{\,y_i}(1-p_i)^{1-y_i}$ (this equals $p_i$ if $y_i = 1$ and $1-p_i$ if $y_i = 0$). Multiply over all examples to get the likelihood of the data. Taking the log turns the product into a sum, and minimising the negative log-likelihood is exactly minimising log loss. So we're choosing the weights that make the observed labels most probable — a principle called maximum likelihood. Unlike MSE with a sigmoid, this loss is convex: one bowl, one minimum.

Advanced · optionalWhere log loss comes from, and why its gradient is so simple

Treat each label as a coin flip with $P(y=1) = p$. The likelihood of one observation is $p^{y}(1-p)^{1-y}$, so the negative log-likelihood of the data is

$$-\sum_i \big[y_i\ln p_i + (1-y_i)\ln(1-p_i)\big],$$

which is exactly the log loss: minimising it is maximum likelihood estimation. For the gradient, use $\sigma'(z) = \sigma(z)(1-\sigma(z))$ and the chain rule on one example with $p = \sigma(z)$, $z = \mathbf{w}\cdot\mathbf{x}$:

$$\frac{\partial \ell}{\partial z} = -\frac{y}{p}\,p(1-p) + \frac{1-y}{1-p}\,p(1-p) = p - y, \qquad \frac{\partial \ell}{\partial \mathbf{w}} = (p-y)\,\mathbf{x}.$$

The Hessian is $\sum_i p_i(1-p_i)\,\mathbf{x}_i\mathbf{x}_i^\top$, a sum of positive semi-definite matrices, so log loss is convex: gradient descent cannot get stuck in a bad local minimum.

8.The gradient — surprisingly simple

In plain wordsTraining uses gradient descent again. The gradient turns out to be very simple: (predicted probability − true label) × input — the same shape as for linear regression.

There's no closed-form solution here, so we use gradient descent (Lesson 7). Let's derive the gradient for one example with the chain rule. The loss depends on $p$, which depends on $z$, which depends on $w_j$:

$$\frac{\partial \ell}{\partial w_j} = \frac{\partial \ell}{\partial p}\cdot\frac{\partial p}{\partial z}\cdot\frac{\partial z}{\partial w_j}$$
  1. $\frac{\partial \ell}{\partial p} = -\frac{y}{p} + \frac{1-y}{1-p}$ (derivative of $\ln$ is $1/\cdot$).
  2. $\frac{\partial p}{\partial z} = p(1-p)$ (the sigmoid's derivative).
  3. $\frac{\partial z}{\partial w_j} = x_j$.
  4. Multiply the first two: $\left(-\frac{y}{p} + \frac{1-y}{1-p}\right)p(1-p) = -y(1-p) + (1-y)p = p - y$.

So everything collapses to:

$$\frac{\partial L}{\partial w_j} = \frac{1}{n}\sum_{i=1}^{n}(p_i - y_i)\,x_{ij} \qquad\qquad \frac{\partial L}{\partial b} = \frac{1}{n}\sum_{i=1}^{n}(p_i - y_i)$$

"Prediction minus truth, times the input" — the same shape as linear regression's gradient. The update is $w_j \leftarrow w_j - \eta\,\frac{\partial L}{\partial w_j}$, as always.

Worked example — one gradient step

One student: $x = 2$ hours, passed ($y = 1$). Start with $w = 0$, $b = 0$, learning rate $\eta = 0.5$.

$z = 0$, $p = \sigma(0) = 0.5$. Loss $= -\ln 0.5 = 0.693$.

Gradients: $\frac{\partial \ell}{\partial w} = (0.5 - 1)\times2 = -1$, $\ \frac{\partial \ell}{\partial b} = 0.5 - 1 = -0.5$.

Update: $w = 0 - 0.5\times(-1) = 0.5$, $\ b = 0 - 0.5\times(-0.5) = 0.25$.

Now $z = 0.5\times2 + 0.25 = 1.25$, $p = \sigma(1.25) \approx 0.777$, loss $= -\ln 0.777 \approx 0.252$. The model became more confident in the right answer.

Make sense of it

The situation: The model sees one student who studied 2 hours and passed, and adjusts itself.

What the result tells you: Its prediction was 0.5 (no idea). The error $p - y = -0.5$ says "too low", so both $w$ and $b$ move up and the new prediction is 0.777.

What if…?

  • A second step on the same student: $p$ rises to about 0.859 and the loss falls to 0.152. Each step helps a little less, because the error $p - y$ is shrinking.
  • If the student had failed ($y = 0$): the error is $+0.5$, the weights move down to $w = -0.5,\ b = -0.25$, and $p$ falls to 0.223.

Why it matters in ML: The gradient for logistic regression is just (prediction − truth) × input. Big mistakes cause big updates; correct, confident predictions barely change anything.

10.More than two classes

For $K$ classes (e.g. digits 0–9) there are two common approaches:

  • One-vs-rest: train $K$ binary classifiers ("is it a 3, or not?") and pick the most confident.
  • Softmax (multinomial) regression: compute a score $z_k = \mathbf{w}_k\cdot\mathbf{x} + b_k$ for each class, then turn the scores into probabilities that sum to 1:
$$P(y = k \mid \mathbf{x}) = \frac{e^{z_k}}{\sum_{j=1}^{K} e^{z_j}}$$
Worked example — softmax

Scores for three classes: $z = (2, 1, 0)$. Exponentials: $e^2 \approx 7.39$, $e^1 \approx 2.72$, $e^0 = 1$; total $\approx 11.11$.

Probabilities: $7.39/11.11 \approx 0.665$, $2.72/11.11 \approx 0.245$, $1/11.11 \approx 0.090$. They sum to 1, and the highest score gets the highest probability.

Make sense of it

The situation: An image model scores a photo as cat 2, dog 1, rabbit 0 and has to turn the scores into probabilities.

What the result tells you: Softmax gives 66.5% cat, 24.5% dog, 9% rabbit. The probabilities always add to 1 and keep the order of the scores.

What if…?

  • Bigger gaps (4, 2, 0): 86.7%, 11.7%, 1.6% — more confident.
  • Add 10 to every score (12, 11, 10): exactly the same probabilities. Only differences between scores matter.
  • Equal scores (2, 2, 2): one-third each.

Why it matters in ML: Softmax is the last layer of nearly every classifier and of every language model, where the "classes" are possible next words. Making scores more spread out (or using a lower "temperature") makes the model more decisive.

Softmax with cross-entropy loss is also the standard output layer of neural network classifiers (Lesson 18).

11.In Python

From scratch on the study-hours data:

import numpy as np

x = np.array([0.5, 1, 1.5, 2, 2.5, 3, 3.5, 4, 4.5, 5])
y = np.array([0, 0, 0, 1, 0, 1, 0, 1, 1, 1])

def sigmoid(z):
    return 1 / (1 + np.exp(-z))

w, b, lr = 0.0, 0.0, 0.1
for step in range(5000):
    p = sigmoid(w * x + b)
    w -= lr * np.mean((p - y) * x)      # dL/dw = mean((p - y) x)
    b -= lr * np.mean(p - y)            # dL/db = mean(p - y)

p = sigmoid(w * x + b)
loss = -np.mean(y * np.log(p) + (1 - y) * np.log(1 - p))
print(round(w, 3), round(b, 3), round(loss, 3))   # 1.353 -3.721 0.434
print(round(-b / w, 2))                           # decision boundary: 2.75 hours

On a real medical dataset with scikit-learn — 569 breast tumours, 30 measurements each, labelled malignant or benign:

from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline

X, y = load_breast_cancer(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, stratify=y, random_state=0)

model = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
model.fit(X_train, y_train)

print(round(model.score(X_test, y_test), 3))      # accuracy on unseen tumours
print(model.predict_proba(X_test[:3]).round(3))   # [P(class 0), P(class 1)] for 3 tumours

12.Running example: Chennai Homes

Can we predict which houses sell fast? Both weights are negative (on standardised features): farther and older houses are less likely to sell fast. A new 5-year-old house 3 km from the centre gets an 88% chance; a 25-year-old one 20 km out, just 3%.

Where this is used
  • Credit scoring and loan default risk
  • Medical risk prediction
  • Click-through prediction for ads
  • A strong, explainable baseline classifier

Choose it when: You need probabilities, interpretability and speed; classes are roughly linearly separable.

Think twice when: Boundaries are highly non-linear and you can't engineer suitable features.

Misconceptions to unlearn

MythLogistic regression is a regression model.

RealityIt's a classifier — the name comes from regressing the log-odds.

MythA probability of 0.7 means the model is right 70% of the time.

RealityOnly if the model is well calibrated. Always check predicted probabilities against actual outcomes on held-out data.

Responsible AI · Decisions about people need explanations

Logistic regression is common in credit scoring, where regulations in many countries (for example the EU's GDPR and the US Equal Credit Opportunity Act) give people rights to information about automated decisions that affect them. Its weights are relatively easy to explain. Remember too that the decision threshold is a policy choice: moving it changes who is approved, and it may affect different groups differently.

13.Questions beginners often ask

Why is it called regression if it classifies?

Historical naming: it regresses (fits) the log-odds of the class with a linear function. It's used as a classifier.

Are its probabilities trustworthy?

Often reasonably well calibrated, especially compared with many other models — but always check on held-out data.

What if classes aren't linearly separable?

Add features (squares, products) or use a non-linear model: trees, kNN, SVM kernels or neural networks.

Common mistakes to avoid
  • Using MSE instead of log loss for classification.
  • Reading the weight as a change in probability — it changes the log-odds.
  • Assuming 0.5 is always the right threshold; the costs of each mistake should decide it.
Interview corner

Don't confuse

  • Probability vs odds vs log-odds (logit) — 0.5 probability = odds 1 = log-odds 0.
  • Sigmoid vs softmax — Sigmoid for two classes, softmax for many.
  • Log loss vs cross-entropy — Two names, one formula.
  • Multi-class vs multi-label — Pick one vs tick all that apply.

Hidden questions — answer in your head first, then open.

Why is it called logistic regression if it's used for classification?

The trap: Thinking it's a misnomer.

It is a regression on the log-odds: $\ln\frac{p}{1-p} = \mathbf{w}\cdot\mathbf{x} + b$. The classification comes from thresholding the predicted probability.

Why use log loss rather than MSE for logistic regression?

The trap: "MSE works for everything."

MSE through a sigmoid gives a non-convex loss with tiny gradients when the model is confidently wrong, so learning stalls exactly when it should be fastest. Log loss is convex for logistic regression and punishes confident mistakes heavily.

Is the decision boundary of logistic regression linear?

The trap: "No, the sigmoid is curved."

Yes. The boundary is where $p = 0.5$, i.e. $\mathbf{w}\cdot\mathbf{x} + b = 0$ — a straight line or flat plane. The sigmoid only bends the probabilities, not the boundary. Curved boundaries need extra features or another model.

What happens to logistic regression on perfectly separable data without regularisation?

The trap: Expecting a clean, finite answer.

The weights grow without limit: making them larger always makes the probabilities more confident and the log loss smaller, approaching but never reaching 0. Regularisation (sklearn's default C = 1.0) keeps them finite.

14.Key takeaways

  • Logistic regression predicts $p = \sigma(\mathbf{w}\cdot\mathbf{x} + b)$, the probability of class 1; $\sigma(z) = 1/(1+e^{-z})$.
  • Predict class 1 when $p \ge$ threshold (often 0.5), i.e. when $\mathbf{w}\cdot\mathbf{x} + b \ge 0$: a linear decision boundary.
  • Each weight multiplies the odds by $e^{w_j}$ per unit increase of its feature.
  • Trained by minimising log loss (maximum likelihood), which heavily punishes confident mistakes.
  • Gradient: $\frac{1}{n}\sum(p_i - y_i)\,\mathbf{x}_i$. Multi-class uses softmax.

15.Check your understanding

1. What is $\sigma(0)$?

$\sigma(0) = 1/(1 + e^0) = 1/2$.

2. A model has $z = 2x - 6$. Where is the decision boundary (threshold 0.5)?

The boundary is where $z = 0$: $2x - 6 = 0 \Rightarrow x = 3$.

3. The true label is 1. Which prediction gives the largest log loss?

$-\ln 0.05 \approx 3.0$, much larger than $-\ln 0.5 \approx 0.69$ or $-\ln 0.95 \approx 0.05$. Confident and wrong is punished most.

4. A feature has weight $w = \ln 2 \approx 0.693$. Increasing that feature by 1…

The odds are multiplied by $e^{w} = e^{\ln 2} = 2$. The probability itself changes by a varying amount.

5. For one example, $p = 0.8$, $y = 0$, $x = 3$. What is $\partial\ell/\partial w$?

$(p - y)\,x = (0.8 - 0)\times3 = 2.4$. Positive, so gradient descent decreases $w$, lowering $p$ for this example.
