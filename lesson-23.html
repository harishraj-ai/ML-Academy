1.Parameters vs hyperparameters

A model has two kinds of numbers. Parameters are learned from the data during training: the weights of a linear model, the split points of a tree. Hyperparameters are chosen before training and control how learning happens: the regularization strength $\lambda$ (Lesson 10), the number of neighbours $k$ (Lesson 11), a tree's maximum depth (Lesson 13), the SVM's $C$ and $\gamma$ (Lesson 15), the learning rate (Lesson 7).

Good hyperparameters often matter more than the choice of algorithm. But every time you try a setting and look at a score, you learn a little about the evaluation data, so careless tuning produces scores that are too good to be true. This lesson covers how to search well (grid, random, Bayesian and successive halving), how to report honestly (nested cross-validation), and how to choose between models.

The core idea

Tuning is itself a learning process, so it needs its own unseen data. Choose hyperparameters using cross-validation on the training set only, search the space efficiently, and keep a final test set (or an outer cross-validation loop) that no tuning decision ever touched.

2.Seeing one hyperparameter at a time: validation curves

A validation curve shows training and cross-validated scores as one hyperparameter changes. It makes underfitting and overfitting visible. Here the RBF SVM's $\gamma$ (how local each training point's influence is) varies on the breast-cancer data:

import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import validation_curve
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.svm import SVC

X, y = load_breast_cancer(return_X_y=True)
model = make_pipeline(StandardScaler(), SVC())
gammas = [0.0001, 0.001, 0.01, 0.1, 1]
train, val = validation_curve(model, X, y, param_name="svc__gamma", param_range=gammas, cv=5)
for g, a, b in zip(gammas, train.mean(axis=1), val.mean(axis=1)):
    print(f"gamma {g:<6}: train accuracy {a:.3f}   cross-validated accuracy {b:.3f}")

Output:

gamma 0.0001: train accuracy 0.794   cross-validated accuracy 0.796
gamma 0.001 : train accuracy 0.951   cross-validated accuracy 0.947
gamma 0.01  : train accuracy 0.978   cross-validated accuracy 0.968
gamma 0.1   : train accuracy 0.990   cross-validated accuracy 0.960
gamma 1     : train accuracy 1.000   cross-validated accuracy 0.631

At $\gamma = 0.0001$ both scores are low (0.794 and 0.796): the boundary is too smooth, so the model underfits. At $\gamma = 1$ training accuracy is perfect but cross-validated accuracy collapses to 0.631: each point's influence is tiny, so the model memorises. The best region is in between ($\gamma = 0.01$, 0.968). Values span orders of magnitude, so always try hyperparameters like this on a log scale.

3.Grid search

Grid search tries every combination of a list of values for each hyperparameter, scores each with cross-validation, and keeps the best. Scikit-learn's GridSearchCV then refits the best setting on all the training data. Hyperparameters of a step inside a pipeline are named step__parameter, as in svc__C.

from sklearn.model_selection import GridSearchCV, train_test_split

X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)
grid = {"svc__C": [0.1, 1, 10, 100], "svc__gamma": [0.0001, 0.001, 0.01, 0.1]}
search = GridSearchCV(model, grid, cv=5).fit(X_tr, y_tr)
print("settings tried:", len(search.cv_results_["params"]))
print("best settings:", search.best_params_)
print("best cross-validated accuracy:", round(search.best_score_, 3))
print("test accuracy of the refitted best model:", round(search.score(X_te, y_te), 3))

Output:

settings tried: 16
best settings: {'svc__C': 100, 'svc__gamma': 0.001}
best cross-validated accuracy: 0.988
test accuracy of the refitted best model: 0.958
Worked example — how much work is a grid search?

The grid above has 4 values of $C$ and 4 values of $\gamma$: $4 \times 4 = 16$ settings.

Each is scored with 5-fold cross-validation, so $16 \times 5 = 80$ models are trained, plus 1 final refit of the best setting: 81 fits.

Add a third hyperparameter with 5 values and it becomes $16 \times 5 \times 5 + 1 = 401$ fits. With 5 hyperparameters of 5 values each it's $5^5 \times 5 + 1 = 15{,}626$ fits. The grid's size multiplies with every hyperparameter you add: the curse of dimensionality again (Lesson 11).

The best cross-validated accuracy is 0.988, but the refitted model scores 0.958 on the untouched test set. Part of that gap is chance, because the test set has only 143 cases, and part is the optimism of picking the best of 16 settings (Lesson 5's "Going deeper").

4.Random search

Random search samples each hyperparameter from a distribution, typically loguniform for anything that spans orders of magnitude. With the same budget it usually matches or beats a grid, because in most problems only one or two hyperparameters really matter: a 4×4 grid tries just 4 values of each, while 16 random draws try 16 different values of every one (Bergstra and Bengio, 2012).

from sklearn.model_selection import RandomizedSearchCV
from scipy.stats import loguniform

dists = {"svc__C": loguniform(0.01, 1000), "svc__gamma": loguniform(1e-5, 1)}
rs = RandomizedSearchCV(model, dists, n_iter=16, cv=5, random_state=0).fit(X_tr, y_tr)
print("best settings:", {k: round(float(v), 4) for k, v in rs.best_params_.items()})
print("best cross-validated accuracy:", round(rs.best_score_, 3), "  test accuracy:", round(rs.score(X_te, y_te), 3))

Output:

best settings: {'svc__C': 1.313, 'svc__gamma': 0.017}
best cross-validated accuracy: 0.981   test accuracy: 0.951

Sixteen random draws find a setting with cross-validated accuracy 0.981 and test accuracy 0.951, about the same as the grid. On this problem both work; random search's advantage grows as you add hyperparameters, because its budget doesn't multiply.

6.Smarter searches: Bayesian optimisation and successive halving

Bayesian optimisation uses the results so far to choose what to try next. It fits a cheap surrogate model of "score as a function of hyperparameters" (often a Gaussian process or, in Optuna's TPE, density estimates of good and bad settings), then picks the next setting that best balances exploitation (near the current best) and exploration (where the surrogate is uncertain). It shines when each training run is expensive. This lesson's "Going deeper" builds a tiny version.

Successive halving saves time differently: start many candidates on a small budget (few rows, few epochs or few trees), keep the best third, give them three times the budget, and repeat:

from sklearn.experimental import enable_halving_search_cv  # noqa: F401  (switches the feature on)
from sklearn.model_selection import HalvingRandomSearchCV

hs = HalvingRandomSearchCV(model, dists, n_candidates=48, factor=3, cv=5, random_state=0).fit(X_tr, y_tr)
for it, (n_cand, n_res) in enumerate(zip(hs.n_candidates_, hs.n_resources_)):
    print(f"round {it + 1}: {n_cand:2d} candidates, each trained on {n_res} rows")
print("best cross-validated accuracy:", round(hs.best_score_, 3))

Output:

round 1: 48 candidates, each trained on 20 rows
round 2: 16 candidates, each trained on 60 rows
round 3:  6 candidates, each trained on 180 rows
best cross-validated accuracy: 0.978

48 candidates start on just 20 rows each; 16 survive to 60 rows; 6 reach 180 rows, and the best scores 0.978 in cross-validation. Most of the 48 cheap first-round fits used tiny data, so the whole search costs far less than training 48 candidates fully. Hyperband runs several halving schedules with different starting budgets, and early stopping in boosting and neural networks (Lesson 10's "Going deeper") applies the same idea within a single run.

7.Reporting honestly: nested cross-validation

The best score found during a search is optimistic, because it's the best of many tries on the same folds. To report how well "tune, then fit" works on new data, wrap the whole search inside an outer cross-validation loop (Lesson 5's "Going deeper"):

from sklearn.model_selection import cross_val_score, KFold

inner, outer = KFold(5, shuffle=True, random_state=1), KFold(5, shuffle=True, random_state=2)
tuned = GridSearchCV(model, grid, cv=inner)
nested = cross_val_score(tuned, X, y, cv=outer)
print("nested CV accuracy:", round(nested.mean(), 3), "+/-", round(nested.std(), 3))

Output:

nested CV accuracy: 0.979 +/- 0.007

Nested CV estimates 0.979 accuracy (±0.007 across the outer folds) for the complete tuning procedure. Use it, or a single held-out test set used once, as the number you report. The model you actually deploy is still produced by running the search once on all the training data.

8.Choosing between models: the simplest good one

Cross-validated scores are noisy, so the setting with the very highest mean is often not truly better than its neighbours. The one-standard-error rule picks the simplest model whose score is within one standard error of the best. Simpler models are cheaper, easier to explain, and usually more robust when the data shifts.

from sklearn.tree import DecisionTreeClassifier

# The one-standard-error rule: prefer the simplest model within 1 SE of the best
depths = list(range(1, 11))
res = GridSearchCV(DecisionTreeClassifier(random_state=0), {"max_depth": depths}, cv=10).fit(X_tr, y_tr).cv_results_
mean, se = res["mean_test_score"], res["std_test_score"] / np.sqrt(10)
best = int(np.argmax(mean))
simplest = next(i for i in range(len(depths)) if mean[i] >= mean[best] - se[best])
print("best depth by score:", depths[best], " CV accuracy", round(mean[best], 3), " SE", round(se[best], 3))
print("simplest depth within 1 SE:", depths[simplest], " CV accuracy", round(mean[simplest], 3))

Output:

best depth by score: 5  CV accuracy 0.941  SE 0.012
simplest depth within 1 SE: 4  CV accuracy 0.929

Depth 5 scores highest (0.941), with a standard error of 0.012, but depth 4 scores 0.929, within one standard error, so the rule prefers the shallower tree. Other things to weigh when picking a final model: prediction speed and cost, calibration (Lesson 8's "Going deeper"), fairness across groups (Lesson 21), and how easy it will be to maintain and retrain.

9.In Python: a tuning recipe

A pattern that works for most projects: put all preprocessing in a pipeline, use random search with log-scale distributions and stratified folds, and report on a test set used once.

from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import RandomizedSearchCV, StratifiedKFold, train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from scipy.stats import loguniform

X, y = load_breast_cancer(return_X_y=True)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)
pipe = make_pipeline(StandardScaler(), LogisticRegression(max_iter=5000))
search = RandomizedSearchCV(pipe, {"logisticregression__C": loguniform(1e-3, 1e3)},
                            n_iter=30, cv=StratifiedKFold(5, shuffle=True, random_state=0),
                            scoring="roc_auc", random_state=0).fit(X_tr, y_tr)
print("best C:", round(float(search.best_params_["logisticregression__C"]), 4))
print("CV ROC-AUC:", round(search.best_score_, 4), "  test ROC-AUC:", round(search.score(X_te, y_te), 4))

Output:

best C: 0.3483
CV ROC-AUC: 0.9954   test ROC-AUC: 0.9943

scoring="roc_auc" makes the search optimise the metric you care about (Lesson 9); search.score then uses the same metric on the test set. Libraries such as Optuna add Bayesian optimisation, pruning of bad trials and dashboards, and follow the same pattern.

Where this is used
  • Getting the most out of gradient boosting, SVMs and neural networks
  • Fair comparisons between candidate models before deployment
  • AutoML systems, which automate exactly this search

Choose it when: Whenever a model has settings that strongly affect its accuracy, which is almost always.

Think twice when: the dataset is tiny: heavy tuning on little data mostly fits noise, so prefer simple models with sensible defaults.

Misconceptions to unlearn

MythThe best cross-validated score from a search is what the model will achieve.

RealityIt's the best of many tries, so it's optimistic. Report nested CV or an untouched test set.

MythGrid search is more thorough than random search.

RealityIt's exhaustive only over the few values you listed. For the same budget random search tests many more values of each hyperparameter.

MythMore tuning always helps.

RealityOn small datasets heavy tuning fits the noise in the validation folds. Gains below the CV standard error are usually not real.

Responsible AI · Tune for the right objective

A search optimises exactly the metric you give it and nothing else. If the overall score improves while performance for a small group gets worse, the search won't notice. Include subgroup metrics and calibration in the final comparison (Lesson 21), and record what was tried, so results can be reproduced and checked.

10.Questions beginners often ask

Which hyperparameters should I tune first?

The ones with the biggest effect: regularization strength (λ, C), learning rate and the number of iterations or trees (with early stopping), and model capacity (depth, number of leaves, k, γ). Library defaults for the rest are usually fine.

How many random-search trials do I need?

A useful fact: with 60 random trials, there's a 95% chance at least one lands in the best 5% of the search space (because $1 - 0.95^{60} \approx 0.95$). Start with 20–60 and increase if results are still improving.

Is it OK to tune on the test set if I'm careful?

No. Any decision based on test results makes them optimistic. Tune with cross-validation on training data and look at the test set once, at the end.

Should I tune the preprocessing too?

Yes, if it matters: imputation strategy, the number of PCA components or polynomial degree can all go in the same search, using pipeline names like pca__n_components.

Common mistakes to avoid
  • Choosing hyperparameters by looking at test-set scores.
  • Searching learning rates or penalties on a linear scale instead of a log scale.
  • Scaling or selecting features outside the cross-validation loop, so tuning leaks.
  • Reporting the best search score as the final performance.
  • Picking a complex model for a gain smaller than the score's standard error.
Interview corner

Hidden questions — answer in your head first, then open.

What's the difference between a parameter and a hyperparameter?

The trap: Using the words interchangeably.

Parameters are learned from data during training (weights, split points). Hyperparameters are set before training and control the learning (λ, k, depth, learning rate, number of trees). Hyperparameters are chosen by validation, not by the training loss, since the training loss would always prefer the most flexible setting.

Why does random search often beat grid search?

The trap: "Randomness explores better" with no mechanism.

Usually only a few hyperparameters really matter. A grid with $m$ values per dimension tests only $m$ distinct values of the important ones however large it gets, whereas $n$ random trials test $n$ distinct values of each. Random search also scales to many hyperparameters without the multiplicative blow-up, and any number of trials can be run.

Your tuned model scored 0.95 in grid search but 0.90 on the test set. Why might that be?

The trap: Only saying "overfitting".

The best search score is optimistically biased: it's the maximum over many noisy estimates on the same folds. The test set is also a finite sample with its own noise. Other causes: leakage inside the search (preprocessing fitted outside the pipeline), or a test set from a different period or distribution. Use nested CV for an honest estimate and check the score's confidence interval.

How does Bayesian optimisation decide what to try next?

The trap: Saying it's "like random search but smarter".

It fits a surrogate model of the validation score as a function of the hyperparameters (a Gaussian process, a tree ensemble or TPE's densities) and maximises an acquisition function, such as expected improvement, that rewards both a high predicted score and high uncertainty. Each new result updates the surrogate. It pays off when each trial is expensive.

11.Key takeaways

  • Hyperparameters are set before training and control how a model learns; they're chosen with cross-validation on training data only.
  • Validation curves show underfitting and overfitting as one hyperparameter changes. Search scale-type hyperparameters on a log scale.
  • Grid search grows multiplicatively with each hyperparameter; random search covers important hyperparameters far better for the same budget.
  • Bayesian optimisation chooses the next try from past results; successive halving gives many candidates a small budget and the best ones more.
  • The best search score is optimistic: report nested CV or a test set used once.
  • Prefer the simplest model within about one standard error of the best.

13.Going deeper: Bayesian optimisation from scratch

In plain wordsBayesian optimisation built from scratch: a Gaussian process predicts the validation score and how unsure it is for every setting, and expected improvement picks the next trial by balancing a high predicted score against high uncertainty. On a narrow peak it beats random search once it has about 10 trials.

Intermediate · skip on a first read

This lesson described Bayesian optimisation in words. Here it is in about fifteen lines: a Gaussian process surrogate that predicts the validation score and its uncertainty for any setting, and the expected improvement rule that decides where to try next. Then we measure whether it actually beats random search.

You'll need: this lesson, the normal distribution from Lesson 4 and kernels from Lesson 15.

The surrogate: a Gaussian process

A Gaussian process (GP) is a probability distribution over smooth functions. Given a few observed points, it predicts a mean $\mu(x)$ and a standard deviation $\sigma(x)$ at every other point: close to observed points it's confident, far from them it's uncertain. How smooth it assumes the function to be is set by a kernel, the same idea as the SVM's kernels (Lesson 15). Here we use the common Matérn kernel, and the GP learns its length scale from the data.

Choosing the next trial: expected improvement

Let $f^*$ be the best score found so far. At a candidate $x$, the GP says the score is roughly normal with mean $\mu$ and standard deviation $\sigma$. The expected improvement is the average amount by which it would beat $f^*$, counting no improvement as zero:

$$\text{EI}(x) = (\mu - f^*)\,\Phi(z) + \sigma\,\phi(z), \qquad z = \frac{\mu - f^*}{\sigma}$$

where $\Phi$ and $\phi$ are the standard normal CDF and density. The first term rewards a high predicted score (exploitation); the second rewards high uncertainty (exploration). Each round: fit the GP to all results so far, pick the $x$ with the largest EI, evaluate it, and repeat.

Below, the "validation score" is a made-up curve over $\log_{10}(\text{learning rate})$ from $-5$ to $0$ with a narrow peak. Both methods start fresh 20 times, and we report the average gap between the best score found and the true best:

import numpy as np
import warnings
warnings.filterwarnings("ignore")          # the GP optimiser warns about its bounds on tiny data
from scipy.stats import norm
from sklearn.gaussian_process import GaussianProcessRegressor
from sklearn.gaussian_process.kernels import Matern, ConstantKernel

# A made-up "validation score vs log10(learning rate)" curve with its peak near x = -2.3
f = lambda x: np.exp(-(x + 2.3) ** 2 / 0.3) * 0.3 + 0.65 + 0.02 * np.sin(5 * x)
grid = np.linspace(-5, 0, 501)[:, None]

def bayes_opt(n_iter, seed):
    rng = np.random.default_rng(seed)
    X = rng.uniform(-5, 0, size=(3, 1)); y = f(X[:, 0])               # 3 random starting points
    kernel = ConstantKernel(1.0, (1e-3, 1e3)) * Matern(length_scale=0.5, length_scale_bounds=(0.05, 5), nu=2.5)
    gp = GaussianProcessRegressor(kernel, alpha=1e-6, normalize_y=True, n_restarts_optimizer=3, random_state=0)
    for _ in range(n_iter - 3):
        gp.fit(X, y)
        mu, sd = gp.predict(grid, return_std=True)
        z = (mu - y.max()) / np.maximum(sd, 1e-9)
        ei = (mu - y.max()) * norm.cdf(z) + sd * norm.pdf(z)             # expected improvement
        x_next = grid[np.argmax(ei)]
        X = np.vstack([X, x_next]); y = np.append(y, f(x_next[0]))
    return y.max()

def random_search(n_iter, seed):
    return f(np.random.default_rng(seed).uniform(-5, 0, n_iter)).max()

best = f(grid[:, 0]).max()
for n in [5, 10, 15]:
    bo = np.mean([best - bayes_opt(n, s) for s in range(20)])
    rs = np.mean([best - random_search(n, s) for s in range(20)])
    print(f"{n:2d} trials: average gap to the best score, Bayesian {bo:.4f}   random {rs:.4f}")

Output:

 5 trials: average gap to the best score, Bayesian 0.1297   random 0.1190
10 trials: average gap to the best score, Bayesian 0.0103   random 0.0510
15 trials: average gap to the best score, Bayesian 0.0000   random 0.0261

With only 5 trials, Bayesian optimisation is no better than random (0.130 against 0.119): 3 of those trials are random starting points, and two guided steps aren't enough. By 10 trials it is five times closer to the best (0.0103 against 0.0510), and by 15 it finds the peak every time, while random search is still 0.026 away. That's the pattern in practice: Bayesian optimisation helps most when trials are expensive and you can afford only tens of them, in a low-dimensional space.

In practice

  • Dimensions. GPs work best with up to about 10–20 hyperparameters. Optuna's default, TPE (tree-structured Parzen estimator), copes better with many hyperparameters and with categorical and conditional ones (for example "number of layers", then a width per layer).
  • Noise. Validation scores are noisy, so the surrogate should model noise (a white-noise kernel term, or alpha), or it will chase lucky trials.
  • Parallelism. Random search parallelises trivially; Bayesian optimisation is sequential by nature, and needs tricks to propose several trials at once.
  • Pruning. Combining a smart sampler with early stopping of bad trials (Optuna's pruners, or Hyperband) usually gives the biggest savings.
Interview corner · intermediate

Hidden questions — answer in your head first, then open.

Explain expected improvement and the exploration–exploitation trade-off it encodes.

The trap: Describing it only as "pick the best predicted point".

Given the surrogate's normal prediction $(\mu, \sigma)$ and the best score $f^*$, EI is the expected amount by which a trial beats $f^*$: $(\mu - f^*)\Phi(z) + \sigma\phi(z)$ with $z = (\mu - f^*)/\sigma$. The first term favours points predicted to be good (exploitation); the second favours uncertain points (exploration). Points with a low mean but high uncertainty can still be chosen, which prevents getting stuck near an early lucky result.

When would you choose Optuna's TPE over a Gaussian-process optimiser?

The trap: "TPE is always better."

When there are many hyperparameters, categorical or conditional ones (a choice of model with its own settings), or many trials: TPE scales to these, while GP cost grows cubically with the number of trials and GPs struggle beyond about 20 dimensions. A GP can be more sample-efficient for a few continuous hyperparameters and very expensive trials.

Check your understanding: going deeper

1. What does a Gaussian process surrogate predict at an untried setting?

The uncertainty is what lets Bayesian optimisation explore sensibly.

2. In expected improvement, the term $\sigma\,\phi(z)$ rewards…

It grows with the uncertainty $\sigma$, so unexplored regions get tried.

3. When does Bayesian optimisation help most compared with random search?

Each trial's information matters most when trials are scarce.

4. Why is basic Bayesian optimisation hard to run in parallel?

Random search's trials are independent; Bayesian optimisation is sequential by design.

5. If the best so far is $f^* = 0.90$ and a candidate has $\mu = 0.90$, $\sigma = 0.02$, its expected improvement is about…

With $z = 0$: EI $= 0 + 0.02 \times \phi(0) = 0.02 \times 0.399 \approx 0.008$.
