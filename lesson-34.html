Before you start

This lesson builds on:

  • Lesson 3: Derivatives & Gradients — A derivative is a slope; the gradient $\nabla L$ collects all partial derivatives and points uphill. Gradient descent steps the other way: $\mathbf{w} \leftarrow \mathbf{w} - \eta\nabla L$. The chain rule differentiates functions inside functions.
  • Lesson 11: k-Nearest Neighbours — kNN predicts from the $k$ most similar training examples, so it depends on distances — features must be scaled, and it struggles in very high dimensions.
  • Lesson 16: Clustering — Clustering groups unlabelled data. k-means alternates assigning points to the nearest centroid and moving each centroid to the mean of its points.

Where this fits: Uses matrices and eigenvectors (Lesson 3), nearest-neighbour similarity (Lesson 11) and clustering (Lesson 16) on data made of connections.

1.When the connections are the data

Some data is about relationships: who follows whom, which accounts send money to which, which papers cite which, which products are bought together, which roads connect which junctions. Treating each row on its own throws away the most useful information. A fraudster's account looks ordinary on its own, but it's connected to a ring of other new accounts; a customer's churn risk rises when their friends leave.

A graph (or network) represents this: nodes (people, accounts, pages) joined by edges (friendships, payments, links). This lesson covers the classical toolkit: representing graphs, measuring how important a node is, finding communities, predicting missing links, and turning graph structure into features for ordinary models. Graph neural networks, which learn these features automatically, build on the same ideas.

The core idea

Who you're connected to says a lot about you. Important nodes are linked to by other important nodes, communities are groups with many edges inside and few between, and two nodes with many shared neighbours are likely to be connected too.

2.Representing a graph

The adjacency matrix $A$ has $A_{ij} = 1$ if nodes $i$ and $j$ are connected, otherwise 0. For an undirected graph it's symmetric. A node's degree is its number of edges, the row sum of $A$. Large real graphs are stored as edge lists or sparse matrices, because almost all entries are 0. Here is a simulated social network of 100 people in three hidden communities, where people are 20 times more likely to know someone in their own community:

import numpy as np
rng = np.random.default_rng(2)
sizes = [40, 35, 25]                                            # three hidden communities
group = np.repeat([0, 1, 2], sizes); n = len(group)
p_in, p_out = 0.20, 0.01
P = np.where(group[:, None] == group[None, :], p_in, p_out)
A = np.triu(rng.random((n, n)) < P, 1).astype(int); A = A + A.T   # undirected, no self-loops
deg = A.sum(axis=1)
print("nodes", n, " edges", A.sum() // 2, " average degree", round(deg.mean(), 2))
print("edges inside communities:", int((A * (group[:, None] == group[None, :])).sum() // 2), "  between:", int((A * (group[:, None] != group[None, :])).sum() // 2))

Output:

nodes 100  edges 357  average degree 7.14
edges inside communities: 332   between: 25

Of 357 edges, 332 are inside communities and only 25 cross between them. In real data the communities aren't given; finding them is one of the tasks below.

3.Who matters? Centrality

  • Degree centrality: how many connections a node has.
  • PageRank: a node is important if important nodes link to it. Imagine a random surfer who follows a random edge with probability $d$ (usually 0.85), or jumps to a random node otherwise; PageRank is the share of time spent at each node. It's the leading eigenvector of the surfer's transition matrix (Lesson 3's "Going deeper"), found by repeated multiplication.
  • Closeness: how near a node is, on average, to everyone else (reciprocal of the mean shortest-path distance, found by breadth-first search).
  • Betweenness: how often a node lies on the shortest paths between others, so it acts as a bridge.

$$r_j = \frac{1-d}{n} + d \sum_{i \to j} \frac{r_i}{\text{out-degree}(i)}$$

def pagerank(A, d=0.85, iters=100):
    n = len(A); out = A.sum(axis=1)
    M = np.where(out[:, None] > 0, A / np.maximum(out[:, None], 1), 1 / n)   # row-stochastic transitions
    r = np.full(n, 1 / n)
    for _ in range(iters):
        r = (1 - d) / n + d * r @ M
    return r
def closeness(A):
    n = len(A); c = np.zeros(n)
    for s in range(n):                                          # breadth-first search from each node
        dist = np.full(n, -1); dist[s] = 0; frontier, d = [s], 0
        while frontier:
            d += 1
            nxt = {v for u in frontier for v in np.nonzero(A[u])[0] if dist[v] < 0}
            for v in nxt: dist[v] = d
            frontier = list(nxt)
        reach = dist[dist > 0]; c[s] = len(reach) / reach.sum() if len(reach) else 0
    return c
pr, cl = pagerank(A), closeness(A)
for name, score in [("degree", deg), ("PageRank", pr), ("closeness", cl)]:
    top = np.argsort(-score)[:3]
    print(f"{name:9s} top nodes {top.tolist()}  (communities {group[top].tolist()})")
print("correlation of PageRank with degree:", round(np.corrcoef(pr, deg)[0, 1], 3))

Output:

degree    top nodes [41, 29, 78]  (communities [1, 0, 2])
PageRank  top nodes [41, 78, 29]  (communities [1, 2, 0])
closeness top nodes [15, 41, 29]  (communities [0, 1, 0])
correlation of PageRank with degree: 0.986

On this undirected network, PageRank and degree agree closely (correlation 0.986), and the same hubs top both lists. Closeness picks node 15 first, a node near the middle of the whole network rather than the busiest in its group. The measures answer different questions: degree for activity, PageRank for influence, closeness for reach, betweenness for brokerage. On directed graphs, such as web links or payments, PageRank differs much more from degree.

5.Finding communities

Community detection groups nodes that are densely connected among themselves. A common score is modularity: the fraction of edges inside groups minus the fraction expected if edges were placed at random with the same degrees:

$$Q = \frac{1}{2m}\sum_{ij}\Big(A_{ij} - \frac{k_i k_j}{2m}\Big)[c_i = c_j]$$

where $m$ is the number of edges, $k_i$ the degrees and $c_i$ the groups. Values above about 0.3 indicate clear structure. Methods include greedy modularity optimisation (the Louvain and Leiden algorithms) and spectral clustering, which clusters nodes using the eigenvectors of the graph, the graph version of Lesson 16's clustering:

from sklearn.cluster import SpectralClustering
from sklearn.metrics import adjusted_rand_score
def modularity(A, labels):
    m, k = A.sum() / 2, A.sum(axis=1)
    same = labels[:, None] == labels[None, :]
    return float(((A - np.outer(k, k) / (2 * m)) * same).sum() / (2 * m))
found = SpectralClustering(3, affinity="precomputed", random_state=0).fit_predict(A)
print("adjusted Rand index against the true communities:", round(adjusted_rand_score(group, found), 3))
print("modularity: found", round(modularity(A, found), 3), "  true", round(modularity(A, group), 3), "  random labels", round(modularity(A, rng.integers(0, 3, n)), 3))

Output:

adjusted Rand index against the true communities: 0.971
modularity: found 0.573   true 0.574   random labels -0.01

Spectral clustering recovers the three communities almost perfectly (adjusted Rand index 0.971, where 1 is a perfect match), and the modularity of its grouping, 0.573, equals the true grouping's. Random labels score about 0. In real networks, communities overlap and have no single right answer, so judge them by modularity and by whether they make sense to people who know the domain.

6.Predicting missing links

Link prediction scores pairs of unconnected nodes by how likely they are to be connected: friend suggestions, products to recommend together, missing interactions in biology. Classic scores:

  • Common neighbours: how many neighbours the two share.
  • Adamic–Adar: shared neighbours, each weighted by $1/\log(\text{degree})$, so a shared friend with few friends counts more than a shared celebrity.
  • Preferential attachment: the product of the degrees, since busy nodes gain more links.

To evaluate, hide 10% of the edges, score them alongside an equal number of truly unconnected pairs, and compute ROC-AUC:

from sklearn.metrics import roc_auc_score
edges = np.argwhere(np.triu(A, 1)); rng.shuffle(edges)
hidden = edges[: len(edges) // 10]                               # hide 10% of the edges
A_obs = A.copy(); A_obs[hidden[:, 0], hidden[:, 1]] = A_obs[hidden[:, 1], hidden[:, 0]] = 0
non = np.argwhere(np.triu(1 - A, 1)); non = non[rng.choice(len(non), len(hidden), replace=False)]
pairs, truth = np.vstack([hidden, non]), np.r_[np.ones(len(hidden)), np.zeros(len(non))]
k_obs = A_obs.sum(axis=1)
common = np.array([(A_obs[u] & A_obs[v]).sum() for u, v in pairs])
adamic = np.array([sum(1 / np.log(k_obs[w]) for w in np.nonzero(A_obs[u] & A_obs[v])[0] if k_obs[w] > 1) for u, v in pairs])
pref = np.array([k_obs[u] * k_obs[v] for u, v in pairs])
for name, s in [("common neighbours", common), ("Adamic-Adar", adamic), ("preferential attachment", pref)]:
    print(f"{name:24s} AUC {roc_auc_score(truth, s):.3f}")

Output:

common neighbours        AUC 0.613
Adamic-Adar              AUC 0.605
preferential attachment  AUC 0.384

Common neighbours (AUC 0.613) and Adamic–Adar (0.605) do better than chance; preferential attachment does worse than chance (0.384), because here connections depend on communities, not on popularity: the busiest nodes in different communities rarely connect. Neighbourhood scores are weak in this sparse network (an average of 7 connections), where many truly connected pairs share no neighbour at all. On denser real networks they're often much stronger, and a classifier combining several scores does better still. Always check which mechanism fits your graph.

7.Graph features for ordinary models

The easiest way to use a graph in machine learning is to compute features from it and add them to a normal model: a node's degree, PageRank, community, clustering coefficient, and averages of its neighbours' features or labels. This uses homophily, the tendency of connected nodes to be similar. Here each person has a weak, noisy signal of being in community 0; adding the average signal of their contacts:

from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score
# Each person has a noisy personal signal; predict whether they're in community 0.
target = (group == 0).astype(int)
signal = target + rng.normal(0, 1.2, n)
neigh_mean = (A @ signal) / np.maximum(deg, 1)                    # average signal of their contacts
for name, feats in [("own signal only", np.c_[signal]), ("plus contacts' average", np.c_[signal, neigh_mean])]:
    acc = cross_val_score(LogisticRegression(), feats, target, cv=5).mean()
    print(f"{name:23s} accuracy {acc:.3f}")

Output:

own signal only         accuracy 0.630
plus contacts' average  accuracy 0.720

Accuracy rises from 63.0% to 72.0%: contacts' signals average out each person's noise. This is the core idea behind graph neural networks too: each layer replaces a node's features with a learned combination of its own and its neighbours' features. One caution: when computing neighbour features from labels, use only labels that would be known at prediction time, and split train and test carefully, because connected nodes leak information to each other (Lesson 5).

9.In Python: a graph from an edge list

Real graph data usually arrives as a table of edges. Here a small table of payments between accounts becomes an adjacency matrix, and a few lines compute each account's degree, PageRank and connected component:

import numpy as np
import pandas as pd

pay = pd.DataFrame({"from": ["A", "A", "B", "C", "D", "E", "F", "F", "G", "H"],
                    "to":   ["B", "C", "C", "A", "E", "F", "D", "G", "H", "G"]})
nodes = sorted(set(pay["from"]) | set(pay["to"])); idx = {v: i for i, v in enumerate(nodes)}
A = np.zeros((len(nodes), len(nodes)))
for a, b in zip(pay["from"], pay["to"]):
    A[idx[a], idx[b]] = A[idx[b], idx[a]] = 1                  # treat payments as undirected links
comp, c = -np.ones(len(nodes), int), 0
for s in range(len(nodes)):                                    # connected components by search
    if comp[s] < 0:
        stack = [s]
        while stack:
            u = stack.pop()
            if comp[u] < 0:
                comp[u] = c; stack += list(np.nonzero(A[u])[0])
        c += 1
M, r = A / A.sum(axis=1, keepdims=True), np.full(len(nodes), 1 / len(nodes))
for _ in range(100):
    r = 0.15 / len(nodes) + 0.85 * r @ M
print(pd.DataFrame({"account": nodes, "degree": A.sum(axis=1).astype(int), "pagerank": r.round(3), "component": comp}).to_string(index=False))

Output:

account  degree  pagerank  component
      A       2     0.125          0
      B       2     0.125          0
      C       2     0.125          0
      D       2     0.120          1
      E       2     0.120          1
      F       3     0.177          1
      G       2     0.133          1
      H       1     0.075          1

Accounts A–C form one tight triangle and D–H another group, with no payments between them: two separate components. A sudden new component of fresh accounts paying each other in a ring is exactly the kind of pattern fraud teams look for. In the first group all three accounts are equal (PageRank 0.125); in the second, F has the highest PageRank (0.177) and the only degree of 3, because it joins the D–E–F triangle to G and H. H, with one link, is the least central.

10.Running example: Chennai Homes

Turn the 12 homes into a similarity network: link each home to its 2 most similar homes on standardised size, distance, age and price. Of the 18 links, only 6 join homes in the same area: similar homes often sit in different areas, which shows that a graph built from features can reveal groupings that the area label misses. Homes 7, 2 and 4 are the most connected: typical homes that many others resemble.

Same 12 houses as Lesson 1. With so little data, treat the numbers as an illustration of the method, not as reliable estimates.

import pandas as pd
import numpy as np
df = pd.read_csv("houses.csv")   # download it from Lesson 1
from sklearn.preprocessing import StandardScaler
from sklearn.metrics.pairwise import euclidean_distances
Z = StandardScaler().fit_transform(df[["size_m2", "dist_km", "age_yrs", "price_lakh"]])
D = euclidean_distances(Z); np.fill_diagonal(D, np.inf)
A = np.zeros_like(D)
for i, row in enumerate(D):                          # link each home to its 2 most similar homes
    for j in np.argsort(row)[:2]: A[i, j] = A[j, i] = 1
same_area = (df.area.to_numpy()[:, None] == df.area.to_numpy()[None, :])
print("similarity links:", int(A.sum() // 2), " of which within the same area:", int((A * same_area).sum() // 2))
print("most connected homes (id):", df.id[np.argsort(-A.sum(axis=1))[:3]].tolist())

Output:

similarity links: 18  of which within the same area: 6
most connected homes (id): [7, 2, 4]
Where this is used
  • Fraud rings and money laundering in payment networks
  • Friend, follower and product suggestions
  • Supply chains, citation networks and biological interaction networks

Choose it when: Whenever relationships between entities carry information that single rows don't.

Think twice when: the entities really are independent: then a graph adds complexity without information.

Misconceptions to unlearn

MythThe most connected node is always the most important.

RealityImportance depends on the question: influence, reach and brokerage are measured differently.

MythCommunities are a fixed property of the network.

RealityDifferent methods and resolutions give different, equally valid groupings.

MythNodes can be split into train and test like ordinary rows.

RealityConnected nodes share information, so random splits can leak.

Responsible AI · Guilt by association

Graph features judge people by their connections: friends, family, neighbours, contacts. That can be powerful for fraud detection and harmful elsewhere, penalising someone for whom they know or where they live, and it amplifies existing segregation. Be explicit about which relationships a model may use, test whether graph features act as proxies for protected attributes, and give people a way to contest decisions.

11.Questions beginners often ask

What's the difference between PageRank and degree?

Degree counts links; PageRank also weighs where they come from, so a link from an important node counts more. On directed graphs they can differ greatly.

Which community detection algorithm should I use?

Louvain or Leiden for large graphs (fast modularity optimisation); spectral clustering when you know roughly how many groups there are. Check results make sense to domain experts.

When do I need graph neural networks?

When node features and structure both matter and you have lots of labelled nodes. Start with graph features in an ordinary model: it's a strong baseline.

How do I store a large graph?

As an edge list or a sparse matrix, never a dense adjacency matrix; graph databases help when queries follow paths.

Common mistakes to avoid
  • Storing a large graph as a dense matrix.
  • Using neighbours' labels that wouldn't be known at prediction time.
  • Treating edges as undirected when direction matters, such as payments.
  • Assuming preferential attachment fits every network.
  • Reporting communities without checking modularity or whether they make sense.

Hidden questions — answer in your head first, then open.

How would you use a transaction network to detect fraud?

The trap: "Train a classifier on each transaction separately."

Build a graph of accounts linked by payments, devices or addresses; compute features such as degree, PageRank, community membership, distance to known fraud and neighbours' fraud rates (using only information available at decision time); look for dense new communities or rings; add these features to the transaction model, and split train/test by time and community to avoid leakage.

Why does PageRank use a damping factor?

The trap: Saying it's just a tuning knob.

Without it, the random surfer can get stuck in dead ends or loops, and the stationary distribution may not be unique. Teleporting to a random node with probability 1 − d makes the matrix strictly positive, guaranteeing a unique positive PageRank vector and fast convergence of power iteration (errors shrink by about d per step).

How does spectral clustering work on a graph?

The trap: Calling it "k-means on the adjacency matrix".

Build the Laplacian L = D − A (or its normalised form), compute the eigenvectors for its k smallest eigenvalues, use them as new coordinates for each node, and run k-means there. Small eigenvalues correspond to smooth vectors that vary little across edges, so nodes in the same dense community get similar coordinates. The number of near-zero eigenvalues hints at the number of well-separated communities.

12.Key takeaways

  • A graph of nodes and edges is stored as an adjacency matrix or edge list.
  • Centrality measures importance: degree, PageRank, closeness, betweenness.
  • Communities are dense groups; measure them with modularity, find them with Louvain or spectral clustering.
  • Link prediction scores pairs by shared neighbours; check which mechanism fits the graph.
  • Graph features (degree, PageRank, neighbour averages) improve ordinary models through homophily.

14.Going deeper: PageRank as an eigenvector, and the graph Laplacian

In plain wordsPageRank is the eigenvector of the random surfer's matrix with eigenvalue 1, which repeated multiplication finds in a few dozen steps, and the second eigenvector of the graph Laplacian splits a graph into its two communities.

Intermediate · skip on a first read

The linear algebra behind two of this lesson's methods: why PageRank is an eigenvector and why repeated multiplication finds it, and how the eigenvectors of the graph Laplacian split a graph into communities.

You'll need: this lesson and eigenvectors from Lesson 3's "Going deeper".

PageRank is an eigenvector

The random surfer's moves form a matrix $G = \frac{1-d}{n}\mathbf{1}\mathbf{1}^\top + d M$, where $M$ follows links. PageRank is the vector $r$ with $r G = r$: an eigenvector with eigenvalue 1. Because every entry of $G$ is positive, the Perron–Frobenius theorem guarantees this eigenvalue is the largest and the eigenvector is unique and positive, which is why power iteration (multiplying by $G$ again and again) converges to it. Here on a random directed graph of 60 nodes:

import numpy as np
rng = np.random.default_rng(3)
n = 60
A = (rng.random((n, n)) < 0.08).astype(float); np.fill_diagonal(A, 0)      # a directed graph
out = A.sum(axis=1, keepdims=True)
M = np.where(out > 0, A / np.maximum(out, 1), 1 / n)
G = 0.15 / n + 0.85 * M                                                     # the "Google matrix"
vals, vecs = np.linalg.eig(G.T)
lead = np.real(vecs[:, np.argmax(np.real(vals))]); lead = lead / lead.sum()
r = np.full(n, 1 / n)
for it in range(1, 101):
    r_new = r @ G
    if np.abs(r_new - r).sum() < 1e-10: break
    r = r_new
print("largest eigenvalue:", round(float(np.max(np.real(vals))), 6), "  power iteration converged in", it, "steps")
print("max difference from the eigenvector:", f"{np.abs(r - lead).max():.1e}")
print("correlation with in-degree:", round(np.corrcoef(r, A.sum(axis=0))[0, 1], 3), "  with out-degree:", round(np.corrcoef(r, A.sum(axis=1))[0, 1], 3))

Output:

largest eigenvalue: 1.0   power iteration converged in 27 steps
max difference from the eigenvector: 3.6e-12
correlation with in-degree: 0.724   with out-degree: -0.208

The largest eigenvalue is exactly 1, power iteration converges in 27 steps, and its answer matches the eigenvector to $10^{-11}$. The damping factor sets the speed: errors shrink by a factor of about $d$ each step. On this directed graph, PageRank correlates with in-degree (0.724), not out-degree (−0.208): links to a node count, links from it don't.

The graph Laplacian

The Laplacian is $L = D - A$, where $D$ holds the degrees on its diagonal. For any vector $f$, $f^\top L f = \sum_{\text{edges } ij}(f_i - f_j)^2$: small when connected nodes get similar values. Its smallest eigenvalue is always 0 (a constant vector), and the eigenvector of the second-smallest, the Fiedler vector, is the smoothest non-constant way to give nodes values, which tends to split the graph along its weakest cut:

sizes = [30, 30]; grp = np.repeat([0, 1], sizes)
P = np.where(grp[:, None] == grp[None, :], 0.25, 0.03)
B = np.triu(rng.random((60, 60)) < P, 1).astype(float); B = B + B.T
L = np.diag(B.sum(axis=1)) - B                                              # graph Laplacian
w, v = np.linalg.eigh(L)
fiedler = v[:, 1]                                                           # second-smallest eigenvector
split = (fiedler > 0).astype(int)
acc = max((split == grp).mean(), (split != grp).mean())
print("smallest Laplacian eigenvalues:", np.round(w[:3], 3).tolist())
print("splitting by the sign of the second eigenvector recovers the groups for", f"{acc:.0%}", "of nodes")

Output:

smallest Laplacian eigenvalues: [-0.0, 2.091, 3.272]
splitting by the sign of the second eigenvector recovers the groups for 100% of nodes

The eigenvalues start at 0, then 2.091; splitting the nodes by the sign of the Fiedler vector recovers the two planted communities exactly. Spectral clustering does this with several eigenvectors and k-means. The same Laplacian appears in label spreading (Lesson 32) and in graph neural networks, where a layer smooths node features over neighbours.
