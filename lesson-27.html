1.What recommender systems do

Every streaming service, online shop and social feed decides, for each person, which few items out of millions to show next. That's a recommender system, and it's one of the most commercially important uses of ML: a large share of what people watch and buy online comes from recommendations.

The data is usually a huge, mostly empty table of users × items. Most users have interacted with a tiny fraction of the items, and the task is to fill in the blanks: which unseen items would each user like? This lesson builds the main approaches from scratch: popularity baselines, content-based filtering, collaborative filtering (neighbours) and matrix factorisation, then covers how to evaluate rankings and the practical traps of cold start and feedback loops.

The core idea

People who agreed in the past tend to agree in the future. Collaborative filtering exploits this without knowing anything about the items themselves; matrix factorisation makes it scale by describing every user and item with a few hidden "taste" numbers learned from the ratings.

2.Explicit and implicit feedback

  • Explicit feedback: users tell you what they think (star ratings, thumbs up/down). Clear but scarce.
  • Implicit feedback: what users do (clicks, plays, purchases, watch time). Plentiful but noisy, and with no negatives: an unclicked item may be disliked, or simply never seen.

Most real systems run on implicit feedback. We'll use simulated star ratings so we can measure accuracy precisely: 300 users and 60 films, built from 3 hidden tastes per user and film, with each user having rated about 15% of the films.

import numpy as np
import pandas as pd

# 300 users, 60 films. Each user and film has 3 hidden "tastes"; users rate about 15% of films
rng = np.random.default_rng(0)
n_users, n_items, k = 300, 60, 3
U, V = rng.normal(size=(n_users, k)), rng.normal(size=(n_items, k))
popularity = rng.normal(0, 0.5, n_items)
true = 3.2 + U @ V.T * 0.6 + popularity + rng.normal(0, 0.4, (n_users, n_items))
R = np.clip(np.round(true), 1, 5)
mask = rng.random((n_users, n_items)) < 0.15
ratings = pd.DataFrame([(u, i, R[u, i]) for u, i in zip(*np.nonzero(mask))], columns=["user", "item", "rating"])
print(ratings.head(4).to_string(index=False))
print("ratings:", len(ratings), " share of the matrix filled:", round(mask.mean(), 3))

Output:

 user  item  rating
    0     0     3.0
    0     2     2.0
    0    10     4.0
    0    21     4.0
ratings: 2747  share of the matrix filled: 0.153

2,747 ratings fill just 15.3% of the 18,000 cells. Real systems are far sparser: often well under 1%.

3.Baselines: averages and biases

We hold out one rating per user to test on and measure the root mean squared error (RMSE) of the predicted ratings. The simplest predictors use averages:

# Hold out one rating per user (for evaluation) and train on the rest
test = ratings.groupby("user").sample(1, random_state=0)
train = ratings.drop(test.index)
mu = train.rating.mean()
item_mean = train.groupby("item").rating.mean()
user_bias = (train.rating - mu).groupby(train.user).mean()
rmse = lambda p: np.sqrt(np.mean((test.rating.to_numpy() - p) ** 2))
print("global mean      RMSE:", round(rmse(np.full(len(test), mu)), 3))
print("item average     RMSE:", round(rmse(test.item.map(item_mean).fillna(mu).to_numpy()), 3))
print("item + user bias RMSE:", round(rmse((test.item.map(item_mean).fillna(mu) + test.user.map(user_bias).fillna(0)).to_numpy()), 3))

Output:

global mean      RMSE: 1.077
item average     RMSE: 1.024
item + user bias RMSE: 1.057

Predicting the global average gives RMSE 1.077; each film's own average does better (1.024), because some films are simply better liked. Naively adding a "user bias" (how much each user rates above average) makes things worse here (1.057): with only about 9 ratings per user, that bias is noisy, and it double-counts the film effect (a user who happened to rate good films looks generous). Biases must be learned jointly and with regularization, which is exactly what matrix factorisation below does.

4.Collaborative filtering: neighbours

User-based collaborative filtering predicts your rating of a film from the ratings of users similar to you. Item-based filtering predicts it from your ratings of films similar to that film, where "similar films" are ones the same users rated alike. Similarity is usually cosine or Pearson correlation computed on centred ratings (each user's ratings minus their own average), so a harsh rater and a generous rater with the same tastes look alike:

$$\hat{r}_{ui} = \bar{r}_u + \frac{\sum_{j \in N(i)} \text{sim}(i, j)\,(r_{uj} - \bar{r}_u)}{\sum_{j \in N(i)} |\text{sim}(i, j)|}$$

# Item-item collaborative filtering: films are similar if the same users rate them alike
M = np.full((n_users, n_items), np.nan)
M[train.user, train.item] = train.rating
centred = M - np.nanmean(M, axis=1, keepdims=True)            # remove each user's personal scale
C = np.nan_to_num(centred)
norms = np.linalg.norm(C, axis=0) + 1e-9
S = (C.T @ C) / np.outer(norms, norms)                         # cosine similarity between films
np.fill_diagonal(S, 0)

def predict_item_item(u, i, k=10):
    rated = np.flatnonzero(~np.isnan(M[u]))
    top = rated[np.argsort(S[i, rated])[::-1][:k]]
    w = S[i, top]
    base = np.nanmean(M[u])
    return base + (w @ centred[u, top]) / (np.abs(w).sum() + 1e-9) if len(top) else mu

p_ii = np.array([predict_item_item(u, i) for u, i in zip(test.user, test.item)])
print("item-item CF     RMSE:", round(rmse(p_ii), 3))

Output:

item-item CF     RMSE: 1.012

Item-item collaborative filtering reaches RMSE 1.012: a little better than the baselines. With so few ratings per film (about 46), similarities between films are noisy; neighbour methods shine with much denser data. Item-based CF has been widely used in practice ("customers who bought this also bought…") because item similarities are stable and can be computed in advance.

6.Matrix factorisation

Instead of comparing users directly, matrix factorisation gives every user a vector $\mathbf{p}_u$ and every item a vector $\mathbf{q}_i$ of $k$ hidden factors, plus a bias each, and predicts

$$\hat{r}_{ui} = \mu + b_u + b_i + \mathbf{p}_u\cdot\mathbf{q}_i$$

The factors are learned by minimising squared error on the known ratings, with L2 regularization (Lesson 10) to stop the many parameters from overfitting:

$$\min \sum_{(u,i)\ \text{known}} \big(r_{ui} - \hat{r}_{ui}\big)^2 + \lambda\big(\lVert\mathbf{p}_u\rVert^2 + \lVert\mathbf{q}_i\rVert^2 + b_u^2 + b_i^2\big)$$

It's the low-rank idea from the SVD (Lesson 2's "Going deeper"), adapted to a matrix with missing entries. The factors often end up meaning something ("action vs romance", "mainstream vs art-house") even though nobody labelled them. Below it's trained with stochastic gradient descent (Lesson 7), one rating at a time:

# Matrix factorisation with SGD: learn a vector for every user and film so that rating ≈ mu + b_u + b_i + p_u · q_i
def factorise(train, k=3, epochs=40, lr=0.02, reg=0.05, seed=0):
    g = np.random.default_rng(seed)
    P, Q = g.normal(0, 0.1, (n_users, k)), g.normal(0, 0.1, (n_items, k))
    bu, bi = np.zeros(n_users), np.zeros(n_items)
    data = train[["user", "item", "rating"]].to_numpy()
    for ep in range(epochs):
        for u, i, r in data[g.permutation(len(data))]:
            u, i = int(u), int(i)
            e = r - (mu + bu[u] + bi[i] + P[u] @ Q[i])
            bu[u] += lr * (e - reg * bu[u]); bi[i] += lr * (e - reg * bi[i])
            P[u], Q[i] = P[u] + lr * (e * Q[i] - reg * P[u]), Q[i] + lr * (e * P[u] - reg * Q[i])
    return P, Q, bu, bi

P, Q, bu, bi = factorise(train)
p_mf = mu + bu[test.user] + bi[test.item] + np.sum(P[test.user] * Q[test.item], axis=1)
print("matrix factorisation RMSE:", round(rmse(p_mf), 3))

Output:

matrix factorisation RMSE: 0.715
Worked example — one SGD update

Suppose $\mu = 3.5$, $b_u = 0.2$, $b_i = -0.1$, $\mathbf{p}_u = (0.5, 0.1)$, $\mathbf{q}_i = (0.4, -0.2)$, and the true rating is $r = 4$.

Prediction: $3.5 + 0.2 - 0.1 + (0.5 \times 0.4 + 0.1 \times (-0.2)) = 3.6 + 0.18 = 3.78$. Error: $e = 4 - 3.78 = 0.22$.

Update with learning rate $\eta = 0.1$ and $\lambda = 0$: $b_u \leftarrow 0.2 + 0.1 \times 0.22 = 0.222$; $\mathbf{p}_u \leftarrow \mathbf{p}_u + \eta e\,\mathbf{q}_i = (0.5 + 0.0088,\ 0.1 - 0.0044) = (0.5088, 0.0956)$. The user's vector moves slightly towards the film's, so their predicted rating rises.

Matrix factorisation cuts the RMSE to 0.715, far better than every method above, because the 3 learned factors match the hidden structure of the data. On real data the number of factors is a hyperparameter (often 20–200), tuned with the validation methods of Lesson 23. Libraries use alternating least squares (ALS: fix the items and solve for users exactly, then swap), which parallelises well; for implicit feedback, weighted ALS treats every unclicked item as a weak negative.

7.Evaluating recommendations: rankings, not ratings

Users see a short list, not predicted stars. What matters is whether the top few items are good, so ranking metrics are used:

  • Precision@k: the share of the top $k$ recommendations that are relevant.
  • Recall@k and hit rate@k: the share of relevant items (or of users with at least one) that appear in the top $k$.
  • NDCG and MAP: also reward putting relevant items higher in the list.

Because our data is simulated, we know every user's true rating for every film, so we can check the top 10 unseen films we'd recommend each user:

# Ranking quality: of the 10 unseen films we recommend, how many would the user really like (true rating 4 or 5)?
# (We can check this only because the data is simulated and we know every true rating.)
liked = R >= 4
def precision_at_10(score_fn):
    hits = []
    for u in range(n_users):
        scores = score_fn(u).astype(float).copy()
        scores[mask[u]] = -np.inf                                   # don't recommend films they've rated
        top = np.argsort(scores)[::-1][:10]
        hits.append(liked[u, top].mean())
    return np.mean(hits)

pop = train.groupby("item").rating.mean().reindex(range(n_items), fill_value=mu).to_numpy()
rand = np.random.default_rng(1)
print("precision@10, random films:          ", round(precision_at_10(lambda u: rand.random(n_items)), 3))
print("precision@10, highest-rated films:   ", round(precision_at_10(lambda u: pop), 3))
print("precision@10, matrix factorisation:  ", round(precision_at_10(lambda u: bi + Q @ P[u]), 3))

Output:

precision@10, random films:           0.447
precision@10, highest-rated films:    0.671
precision@10, matrix factorisation:   0.912

Random films are liked 44.7% of the time (many films are decent). Recommending the highest-rated films to everyone, a popularity baseline, raises that to 67.1%. Matrix factorisation's personalised top 10 is liked 91.2% of the time. On real data you can't see true ratings for unseen items, so offline evaluation hides recent interactions (split by time, Lesson 5), and the final test is an online A/B test (Lesson 4's "Going deeper") on clicks, watch time or purchases.

8.Cold start, content and feedback loops

  • Cold start. A new user or a new item has no interactions, so collaborative methods can't place it. Fall back on popularity, ask new users a few questions, or use content-based features: an item's genre, text description (TF-IDF or embeddings, Lessons 12 and 19), price; a user's stated preferences. Hybrid systems combine both.
  • Two-stage systems. At scale, a fast retrieval stage picks a few hundred candidates (nearest neighbours of a user embedding, Lesson 11's "Going deeper"), then a ranking model (often gradient boosting or a neural network with many features) orders them.
  • Feedback loops and popularity bias. Users can only click what they're shown, so the system's own choices shape its future training data. Popular items get more exposure and look even more popular. Mix in some exploration (Lesson 28's Thompson sampling) and measure diversity and novelty, not just accuracy.
  • What to optimise. Clicks reward clickbait. Long-term satisfaction, return visits and explicit "not interested" signals are better guides.

9.In Python: content-based recommendations

When there are no interactions yet, item descriptions alone can drive recommendations. Here, Chennai Homes listings are recommended by the similarity of their descriptions (TF-IDF and cosine similarity), plus a small bonus for the same area:

import numpy as np
import pandas as pd
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

df = pd.read_csv("houses.csv")   # download it from Lesson 1
T = TfidfVectorizer().fit_transform(df["description"])
sim = cosine_similarity(T) + 0.2 * (df["area"].to_numpy()[:, None] == df["area"].to_numpy()[None, :])
np.fill_diagonal(sim, -1)                         # never recommend the house itself
viewed = 5                                         # a buyer looked at house id 5
row = df.index[df.id == viewed][0]
top = np.argsort(sim[row])[::-1][:3]
print("viewed:", df.description[row])
print(df.loc[top, ["id", "area", "description"]].to_string(index=False))

Output:

viewed: new spacious villa with garden
 id      area                    description
 12    Suburb new spacious villa near school
  8 Outskirts    new large villa with garden
  6    Suburb     old villa needs renovation

A buyer who viewed house 5 ("new spacious villa with garden") is shown other new, spacious villas and houses with gardens first. This needs no ratings at all, so it works from the very first day, and it's easy to explain ("because you viewed…"). It can't discover surprising tastes, which is what collaborative methods add once interactions build up.

10.Running example: Chennai Homes

A buyer looks at a house; which others should the site show? Standardise size, bedrooms, distance, age and price, and recommend the homes with the highest cosine similarity. For the Central flat with id 2, the top matches are ids 11 and 1 (similarity 0.69 and 0.68), both nearby flats; for id 11 they are 1, 4 and 2. This is content-based recommendation: it works with no interaction history at all, which is how the cold-start problem is usually handled.

Same 12 houses as Lesson 1. With so little data, treat the numbers as an illustration of the method, not as reliable estimates.

import pandas as pd
import numpy as np
df = pd.read_csv("houses.csv")   # download it from Lesson 1
from sklearn.preprocessing import StandardScaler
from sklearn.metrics.pairwise import cosine_similarity
cols = ["size_m2", "bedrooms", "dist_km", "age_yrs", "price_lakh"]
Z = StandardScaler().fit_transform(df[cols])
sim = cosine_similarity(Z)
np.fill_diagonal(sim, -1)
for viewed in [2, 11]:
    row = df.index[df.id == viewed][0]
    top = np.argsort(sim[row])[::-1][:3]
    print("viewed", viewed, "→ similar:", df.id.iloc[top].tolist(), " similarity", np.round(sim[row, top], 2).tolist())

Output:

viewed 2 → similar: [11, 1, 3]  similarity [0.69, 0.68, 0.33]
viewed 11 → similar: [1, 4, 2]  similarity [0.86, 0.74, 0.69]
Where this is used
  • Products, films, music and news recommendations
  • Job, property and course matching
  • Ranking search results and choosing which content to show next

Choose it when: Whenever many users interact with many items and you need to choose a few items for each user.

Think twice when: there are few items or no interaction history: then simple rules, popularity or content similarity are enough.

Misconceptions to unlearn

MythLower rating error means better recommendations.

RealityUsers see a ranked top few; a model can have good RMSE but rank poorly. Evaluate rankings.

MythMissing ratings mean the user dislikes the item.

RealityMostly they haven't seen it. Treating every missing value as a zero biases the model.

MythMore recommendations of what someone liked is always better.

RealityNarrow feedback loops reduce diversity and discovery; good systems mix in exploration.

Responsible AI · Feedback loops and filter bubbles

A recommender learns from what it showed, so popular items get more popular and niche ones disappear, and users can be pushed towards ever more extreme content if that maximises clicks. Measure diversity, coverage and exposure for item creators, not just clicks; add exploration; and give users controls to see why something was shown and to change it.

11.Questions beginners often ask

What if I only have clicks or purchases, not ratings?

That's implicit feedback: treat interactions as positive signals and unobserved pairs as weak negatives, use methods built for it (weighted matrix factorisation, ranking losses) and evaluate with ranking metrics.

How many latent factors should I use?

Tune it on validation data: typically 10 to 200. More factors fit more detail but overfit sparse data, so tune regularisation at the same time.

How are recommenders built at very large scale?

Usually in two stages: a fast candidate generator (approximate nearest neighbours on embeddings) picks hundreds of items, then a ranking model with many features orders them.

How do I recommend to a brand-new user?

Use popularity, simple questions at sign-up, context (location, device) or content features, then switch to collaborative filtering as interactions arrive.

Common mistakes to avoid
  • Evaluating on a random split that lets the model see a user's future interactions.
  • Treating unobserved user–item pairs as negative ratings.
  • Reporting RMSE only, when users experience a ranked list.
  • Forgetting to exclude items the user already has from their recommendations.
  • Comparing only with random recommendations instead of a popularity baseline.

What's the difference between collaborative filtering and content-based recommendation?

The trap: Calling them the same thing.

Collaborative filtering uses only interaction patterns (users who liked this also liked that), so it needs history. Content-based uses item features (text, category, price) to find similar items, so it works for new items. Production systems usually combine both.

Why is RMSE on ratings a poor way to evaluate a recommender?

The trap: Saying RMSE is fine because it's standard.

Users see a short ranked list, so what matters is whether the top few items are relevant: precision@k, recall@k, NDCG or hit rate on held-out interactions, split by time. RMSE weighs all items equally, including ones never shown, and ratings are missing not at random.

Explain matrix factorisation for recommendations.

The trap: Describing it as PCA on a filled-in matrix.

Each user and item gets a vector of k latent factors; the predicted rating is the global mean plus user and item biases plus the dot product of the vectors. It's fitted only on observed entries, with L2 regularisation, by SGD or alternating least squares. The factors capture tastes such as genre without being told.

How would you handle cold start for a new item?

The trap: "Wait until it has ratings."

Use its content features (text, category, price) to place it near similar items or to predict its latent factors, show it to a small exploration share of users, and update quickly as interactions arrive. For new users, use popularity, context and a few onboarding questions.

12.Key takeaways

  • Recommenders fill in a huge, sparse user × item matrix; most data is implicit feedback with no true negatives.
  • Start with popularity and bias baselines, which are strong and simple.
  • Collaborative filtering uses similar users or items, on centred ratings; it needs no item information.
  • Matrix factorisation learns low-dimensional user and item vectors with regularization; trained by SGD or ALS.
  • Evaluate with ranking metrics (precision@k, recall@k, NDCG), time-based splits and, finally, online A/B tests.
  • Handle cold start with content features, and watch for feedback loops and popularity bias.

13.Check your understanding

1. A user never clicked an item. In implicit feedback, that means…

Missing interactions mix "not interested" with "not shown", which is the central difficulty of implicit data.

2. Why are ratings centred (minus each user's average) before computing similarity?

Centring removes each user's personal rating scale.

3. In matrix factorisation, a predicted rating is…

$\hat{r}_{ui} = \mu + b_u + b_i + \mathbf{p}_u\cdot\mathbf{q}_i$.

4. A brand-new film has no ratings. Which method can still recommend it?

Collaborative methods need interactions; content features solve cold start.

5. Of the 10 films recommended to a user, 7 are relevant. What is precision@10?

Precision@k is relevant items in the top k divided by k. (Recall@k would depend on the total number relevant.)

14.Going deeper: alternating least squares and popularity bias

In plain wordsHow alternating least squares trains matrix factorisation by solving one small ridge regression per user and per item in turn, and how catalogue coverage and average popularity reveal a recommender that only pushes what's already popular.

Intermediate · skip on a first read

Two topics behind production recommenders: alternating least squares, the other standard way to train matrix factorisation, and how to measure whether a recommender only pushes what's already popular.

You'll need: this lesson, ridge regression from Lesson 10, and matrix products from Lesson 17.

Alternating least squares

Matrix factorisation's loss is hard to minimise for $P$ and $Q$ together, but if you fix the item factors $Q$, finding each user's vector is just a small ridge regression with a closed-form answer, $\mathbf{p}_u = (Q_u^\top Q_u + \lambda I)^{-1} Q_u^\top \mathbf{r}_u$, using only the items user $u$ rated. Then fix $P$ and solve for every item the same way. Alternating least squares (ALS) repeats these two steps:

import numpy as np
rng = np.random.default_rng(0)
n_users, n_items, k = 200, 40, 3
P_true, Q_true = rng.normal(0, 1, (n_users, k)), rng.normal(0, 1, (n_items, k))
R = P_true @ Q_true.T + rng.normal(0, 0.3, (n_users, n_items))
mask = rng.random((n_users, n_items)) < 0.2            # only 20% of ratings observed
test = (rng.random((n_users, n_items)) < 0.25) & mask
train = mask & ~test
P, Q, lam = rng.normal(0, 0.1, (n_users, k)), rng.normal(0, 0.1, (n_items, k)), 1.0
for sweep in range(1, 9):
    for u in range(n_users):                           # fix Q, solve a small ridge problem per user
        Qi = Q[train[u]]
        P[u] = np.linalg.solve(Qi.T @ Qi + lam * np.eye(k), Qi.T @ R[u, train[u]])
    for i in range(n_items):                           # fix P, solve per item
        Pu = P[train[:, i]]
        Q[i] = np.linalg.solve(Pu.T @ Pu + lam * np.eye(k), Pu.T @ R[train[:, i], i])
    if sweep in (1, 2, 4, 8):
        rmse = np.sqrt(np.mean((R - P @ Q.T)[test] ** 2))
        print("sweep", sweep, " test RMSE", round(rmse, 3))

Output:

sweep 1  test RMSE 1.635
sweep 2  test RMSE 1.456
sweep 4  test RMSE 0.964
sweep 8  test RMSE 0.762

With 3 true factors and 20% of the ratings observed, the test RMSE falls from 1.635 after one sweep to 0.762 after eight. Every user's (and every item's) update is independent, so ALS parallelises very well, which is why Spark's recommender uses it. It also adapts neatly to implicit feedback, where every unobserved pair counts as a weak zero: the weighted version of Hu, Koren and Volinsky.

Measuring popularity bias

Accuracy metrics reward recommending popular items, because popular items are most likely to appear in anyone's held-out set. Two simple health checks: catalogue coverage (the share of items ever recommended to anyone) and the average popularity of recommended items:

popularity = train.sum(axis=0)                         # how many users interacted with each item
scores_pop = np.tile(popularity, (n_users, 1)).astype(float)
scores_mf = P @ Q.T
for name, S in [("popular", scores_pop), ("matrix factorisation", scores_mf)]:
    S = np.where(train, -np.inf, S)                    # don't recommend items already seen
    top = np.argsort(-S, axis=1)[:, :5]
    coverage = len(np.unique(top)) / n_items
    avg_pop = popularity[top].mean()
    print(f"{name:21s} catalogue coverage {coverage:.2f}   average popularity of recommended items {avg_pop:.1f}")
print("average popularity across all items:", round(popularity.mean(), 1))

Output:

popular               catalogue coverage 0.30   average popularity of recommended items 38.7
matrix factorisation  catalogue coverage 0.85   average popularity of recommended items 30.4
average popularity across all items: 29.2

Recommending the most popular items reaches only 30% of the catalogue, and their average popularity (38.7 users) is well above the catalogue's 29.2. Matrix factorisation recommends 85% of the items, with popularity (30.4) close to average. Track these alongside precision@k: a change that raises precision slightly but halves coverage can make the product worse for users and for the people who supply the items.

SGD or ALS for matrix factorisation: how do you choose?

The trap: Saying one is always better.

SGD is simple, handles explicit ratings and extra terms (biases, side features) easily and is cheap per step, but needs a tuned learning rate. ALS has closed-form steps, needs no learning rate, parallelises across users and items, and handles implicit feedback with all unobserved pairs efficiently, which is why it's common on Spark. Both need regularisation tuned on validation data.
