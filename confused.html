Interview practice

Commonly confused terms

75 pairs of terms that people mix up — even experienced practitioners. Each has the difference in plain words and a one-line way to remember it.

Part 1: Foundations

Python list vs NumPy array

A list holds any objects and [1, 2] * 2 repeats it ([1, 2, 1, 2]). An array holds numbers of one type and np.array([1, 2]) * 2 doubles each element ([2, 4]). Arrays are much faster for maths.

Remember: Lists are containers; arrays are vectors.

Lesson 0 →

View vs copy

Slicing a NumPy array gives a view: changing the slice changes the original. Slicing a Python list gives a copy. Use .copy() when you need an independent array.

Remember: NumPy slices share memory; lists don't.

Lesson 0 →

* vs @ in NumPy

a * b multiplies element by element (shapes must match or broadcast). a @ b is matrix multiplication (dot products of rows with columns).

Remember: Star = side by side; at-sign = rows times columns.

Lesson 0 →

.loc vs .iloc

.loc selects by label (index values and column names, end of slice included). .iloc selects by integer position (end of slice excluded, like Python).

Remember: i for integer position.

Lesson 0 →

Algorithm vs model

The algorithm is the learning procedure (e.g. gradient descent for linear regression). The model is what it produces: a function with specific learned parameter values that you save and use.

Remember: Algorithm = recipe; model = the cake.

Lesson 1 →

Parameter vs hyperparameter

Parameters are learned from the data during training (weights, biases, split thresholds). Hyperparameters are chosen by you before training (learning rate, $k$ in kNN, tree depth, $\lambda$) and tuned on validation data.

Remember: If training changes it, it's a parameter. If you set it, it's a hyperparameter.

Lesson 1 →

Loss vs metric

The loss is what the training algorithm minimises; it must usually be differentiable (log loss, MSE). The metric is how you judge the model for the task (F1, accuracy, revenue). They are often different.

Remember: Loss is for the optimiser; the metric is for the business.

Lesson 1 →

Training vs inference

Training fits the parameters to data (slow, done once or periodically). Inference uses the fixed model to make predictions on new inputs (fast, done constantly). In statistics, "inference" instead means drawing conclusions about parameters, such as confidence intervals.

Remember: Learn once, predict many times.

Lesson 1 →

AI vs machine learning vs deep learning

AI is the broad goal of machines doing intelligent tasks (including hand-written rules). Machine learning is AI that learns from data. Deep learning is machine learning with many-layered neural networks.

Remember: Nested circles: DL ⊂ ML ⊂ AI.

Lesson 1 →

Regression (the task) vs linear regression (a model)

Regression means predicting a number; many models do it (trees, kNN, neural networks). Linear regression is one model for it. And logistic regression is a classification model despite its name.

Remember: Task names and model names are different things.

Lesson 1 →

Dot product vs element-wise product

The dot product multiplies matching entries and adds them up — one number. The element-wise (Hadamard) product multiplies matching entries and keeps them — a vector.

Remember: Dot product ends in a sum.

Lesson 2 →

Distance vs similarity

A distance is small for similar items (0 for identical). A similarity is large for similar items (cosine similarity is 1 for the same direction). Cosine similarity ignores length; Euclidean distance doesn't.

Remember: Distance: smaller is closer. Similarity: bigger is closer.

Lesson 2 →

L1 norm vs L2 norm

L1 adds absolute values ("city-block" or Manhattan distance); L2 is the straight-line length. They can disagree about which point is nearest: from (0, 0), the point (3, 0) is nearer in L1 (3 vs 4) but (2, 2) is nearer in L2 (2.83 vs 3).

Remember: L1 walks the streets; L2 flies.

Lesson 2 →

Derivative vs gradient

A derivative is the slope of a function of one variable. The gradient is the vector of all partial derivatives of a function of many variables; it points uphill, in the direction of steepest increase.

Remember: Gradient = all the slopes at once, as a vector.

Lesson 3 →

Gradient vs gradient descent

The gradient is a quantity (a vector of slopes). Gradient descent is an algorithm that repeatedly steps against the gradient to reduce a loss.

Remember: One is a measurement, the other is a method.

Lesson 3 →

Local minimum vs global minimum vs saddle point

A global minimum is the lowest point anywhere; a local minimum is lowest only nearby. A saddle point has zero gradient but goes down in some directions and up in others. All three have zero gradient.

Remember: Zero slope doesn't mean the bottom.

Lesson 3 →

Probability vs likelihood

Probability: parameters fixed, how probable are different data? $P(\text{data} \mid \theta)$ as a function of the data — sums to 1. Likelihood: data fixed, how well do different parameters explain it? The same formula as a function of $\theta$ — it need not sum to 1.

Remember: Probability predicts data; likelihood judges parameters.

Lesson 4 →

Independent vs mutually exclusive

Independent: knowing one happened doesn't change the chance of the other. Mutually exclusive: they can't both happen. Mutually exclusive events (with non-zero probability) are therefore strongly dependent: if one happens, the other's chance drops to 0.

Remember: Exclusive events tell you a lot about each other.

Lesson 4 →

Correlation vs causation

Correlation means two variables move together. Causation means changing one changes the other. Ice-cream sales and drownings are correlated because of a third variable, hot weather.

Remember: Look for the hidden third variable.

Lesson 4 →

Uncorrelated vs independent

Uncorrelated means no linear relationship. Independent means no relationship at all. For $x = -2, \dots, 2$ and $y = x^2$, the correlation is exactly 0, yet $y$ is completely determined by $x$.

Remember: Correlation only sees straight lines.

Lesson 4 →

Standard deviation vs standard error

Standard deviation describes how spread out individual values are. Standard error describes how uncertain an average is: $\sigma/\sqrt{n}$. With $\sigma = 10$ and 100 samples, individuals vary by about 10 but the mean is uncertain by only about 1.

Remember: SD is about the people; SE is about the estimate.

Lesson 4 →

Part 2: Learning from labelled data

Validation set vs test set

The validation set is used repeatedly to choose models and hyperparameters, so its score becomes optimistic. The test set is used once, at the very end, for an honest estimate. Using the test set to tune turns it into a second validation set.

Remember: Validate many times; test once.

Lesson 5 →

Overfitting vs data leakage

Overfitting: the model memorises noise, so training scores are high and validation scores are low. Leakage: information about the answer sneaks into the features or the evaluation, so validation scores are high too — and the model fails in production.

Remember: Overfitting shows up in validation; leakage hides from it.

Lesson 5 →

Cross-validation vs a train/test split

A single split gives one score that depends on which rows landed where. Cross-validation rotates the validation fold and averages, giving a more reliable score and its spread. You still keep a final test set aside.

Remember: One opinion vs five.

Lesson 5 →

Training error vs generalisation error

Training error is measured on the data the model learned from. Generalisation (test) error is the error on new data from the same source — what you actually care about.

Remember: Grading yourself vs being graded.

Lesson 5 →

Linear in features vs linear in parameters

"Linear regression" means linear in the weights. $\hat{y} = w_1x + w_2x^2$ draws a curve but is still linear regression, solved by the same formula.

Remember: Linear refers to the weights, not the shape.

Lesson 6 →

$R^2$ vs correlation

Correlation $r$ measures the strength and direction of a linear relationship between two variables (−1 to 1). $R^2$ measures the share of variance a model explains. For simple linear regression on training data, $R^2 = r^2$; in general they differ, and test-set $R^2$ can be negative.

Remember: $r$ has a sign; $R^2$ is a score.

Lesson 6 →

Residual vs error

A residual is observed minus fitted value — something you can compute. The error (noise) is the difference from the unknown true relationship — something you can't observe.

Remember: Residuals are the error's visible shadow.

Lesson 6 →

Epoch vs batch vs iteration

A batch is a group of examples used for one update. An iteration is one update. An epoch is one full pass through the training data. With 1,000 examples and batch size 100, one epoch is 10 iterations.

Remember: Epoch = whole dataset; iteration = one batch.

Lesson 7 →

Batch vs mini-batch vs stochastic gradient descent

Batch GD uses all examples per update; stochastic GD uses one; mini-batch uses a small group (e.g. 32). In deep learning, "SGD" almost always means mini-batch.

Remember: How many examples per step.

Lesson 7 →

Learning rate vs momentum

The learning rate scales each step. Momentum keeps a running average of past gradients, so steps keep moving in consistent directions and damp oscillations.

Remember: Step size vs inertia.

Lesson 7 →

Probability vs odds vs log-odds (logit)

Probability $p$ is between 0 and 1. Odds $= p/(1-p)$ are between 0 and infinity (0.8 → 4). Log-odds $= \ln$ odds can be any number; logistic regression models the log-odds as a linear function.

Remember: 0.5 probability = odds 1 = log-odds 0.

Lesson 8 →

Sigmoid vs softmax

Sigmoid turns one score into a probability for a yes/no question. Softmax turns several scores into probabilities that sum to 1 across classes. Softmax with two classes is exactly a sigmoid of the score difference.

Remember: Sigmoid for two classes, softmax for many.

Lesson 8 →

Log loss vs cross-entropy

Same thing for classification: the average of $-\ln(\text{probability given to the true class})$. "Binary cross-entropy" is the two-class version.

Remember: Two names, one formula.

Lesson 8 →

Multi-class vs multi-label

Multi-class: each example has exactly one of several classes (softmax). Multi-label: each example can have several labels at once (one sigmoid per label).

Remember: Pick one vs tick all that apply.

Lesson 8 →

Precision vs recall

Precision: of the items you flagged, how many were right? Recall: of the items you should have flagged, how many did you find? A spam filter needs high precision; a cancer screen needs high recall.

Remember: Precision = purity of the flags; recall = coverage of the positives.

Lesson 9 →

Sensitivity vs specificity

Sensitivity (= recall, TPR) is the share of positives correctly found. Specificity (TNR) is the share of negatives correctly cleared. FPR = 1 − specificity.

Remember: Sensitive tests catch the sick; specific tests clear the healthy.

Lesson 9 →

Type I vs Type II error

Type I = false positive (raising a false alarm). Type II = false negative (missing a real case).

Remember: Type I: the boy who cried wolf. Type II: the wolf nobody noticed.

Lesson 9 →

ROC curve vs precision–recall curve

ROC plots TPR against FPR; PR plots precision against recall. With rare positives, ROC can look excellent while precision is poor, because FPR is divided by the huge number of negatives. Prefer PR curves for imbalanced problems.

Remember: Rare positives? Read the PR curve.

Lesson 9 →

Micro vs macro averaging

Macro: compute the metric per class, then average — every class counts equally. Micro: pool all counts, then compute — big classes dominate. Weighted: average per class, weighted by class size.

Remember: Macro is fair to small classes.

Lesson 9 →

L1 (lasso) vs L2 (ridge) regularisation

L1 penalises $\sum|w|$ and drives some weights to exactly zero (feature selection). L2 penalises $\sum w^2$ and shrinks all weights smoothly but rarely to zero. Elastic net mixes both.

Remember: Lasso lassoes features out; ridge flattens them.

Lesson 10 →

Bias (statistics) vs bias term vs bias (fairness)

Statistical bias: systematic error from overly simple assumptions. The bias term: the intercept $b$ in $wx + b$. Fairness bias: unfair differences between groups. Same word, three ideas.

Remember: Ask which bias someone means.

Lesson 10 →

Regularisation vs normalisation

Regularisation penalises model complexity during training (L1, L2, dropout). Normalisation rescales data or activations (standardising features, batch normalisation).

Remember: One limits the model, the other rescales the numbers.

Lesson 10 →

Part 3: Classic algorithms

kNN vs k-means

kNN (k-nearest neighbours) is supervised: it predicts a label from the $k$ closest labelled examples. k-means is unsupervised: it groups unlabelled data into $k$ clusters. The two $k$s mean different things.

Remember: kNN looks at neighbours; k-means moves centres.

Lesson 11 →

Lazy vs eager learning

Lazy learners (kNN) store the data and do the work at prediction time. Eager learners (linear models, trees, networks) do the work during training and predict quickly.

Remember: Pay now or pay later.

Lesson 11 →

Generative vs discriminative models

Generative models learn how each class produces its features, $P(\mathbf{x} \mid y)$, then apply Bayes (Naive Bayes, Gaussian mixtures). Discriminative models learn the boundary or $P(y \mid \mathbf{x})$ directly (logistic regression, SVMs, most networks).

Remember: Describe each class vs draw the line between them.

Lesson 12 →

Prior vs likelihood vs posterior

Prior: belief before seeing the evidence, $P(\text{spam})$. Likelihood: how probable the evidence is under each hypothesis, $P(\text{words} \mid \text{spam})$. Posterior: updated belief after the evidence, $P(\text{spam} \mid \text{words})$.

Remember: Before, evidence, after.

Lesson 12 →

Gini impurity vs entropy

Two ways to score how mixed a node is. Gini: chance two random picks have different labels (max 0.5 for two classes). Entropy: average bits of uncertainty (max 1 bit). They nearly always pick the same splits.

Remember: Two rulers for the same mess.

Lesson 13 →

Pre-pruning vs post-pruning

Pre-pruning stops growth early (maximum depth, minimum samples per leaf). Post-pruning grows a full tree, then cuts back branches that don't help on validation data (cost-complexity pruning, ccp_alpha).

Remember: Stop early vs trim afterwards.

Lesson 13 →

Impurity importance vs permutation importance

Impurity importance adds up how much each feature reduced impurity during training — fast but biased towards features with many split points. Permutation importance shuffles one feature on held-out data and measures the drop in score — slower but more honest.

Remember: Credit claimed in training vs damage done when removed.

Lesson 13 →

Bagging vs boosting

Bagging trains models independently on bootstrap samples and averages them — reduces variance (random forests). Boosting trains models in sequence, each fixing the last one's errors — reduces bias (AdaBoost, gradient boosting).

Remember: Committee in parallel vs relay team in sequence.

Lesson 14 →

AdaBoost vs gradient boosting

AdaBoost re-weights the training examples so later models focus on the ones misclassified. Gradient boosting fits each new model to the residuals (the gradient of the loss) of the current ensemble. Gradient boosting works with any differentiable loss.

Remember: Re-weight the examples vs fit the leftovers.

Lesson 14 →

Out-of-bag score vs validation score

The OOB score uses each tree's unused bootstrap examples, so it needs no separate split (bagging only). A validation score uses a held-out set and works for any model.

Remember: Free built-in check vs a dedicated exam.

Lesson 14 →

Hard margin vs soft margin

A hard margin allows no points inside the road and only works if the data are perfectly separable. A soft margin allows violations, paid for by the hinge loss and controlled by C.

Remember: No exceptions vs a fine for each exception.

Lesson 15 →

C vs gamma in an RBF SVM

C: how heavily margin violations are penalised (bigger C = fit training data more closely). Gamma: how far each point's influence reaches (bigger gamma = more local, wigglier boundary). Both large → overfitting.

Remember: C is strictness; gamma is reach.

Lesson 15 →

Part 4: Finding structure without labels

Clustering vs classification

Classification learns from labelled examples and predicts known classes. Clustering has no labels and discovers groups that a person must interpret and name.

Remember: Known answer vs discovered groups.

Lesson 16 →

Inertia vs silhouette score

Inertia: total squared distance to cluster centres — lower is tighter, but it always falls as $k$ grows. Silhouette: how much closer each point is to its own cluster than to the next (−1 to 1) — can be compared across different $k$.

Remember: Inertia can't choose k; silhouette can help.

Lesson 16 →

k-means vs DBSCAN

k-means needs $k$, assigns every point, and finds round clusters. DBSCAN needs a radius and a density threshold, finds any number of clusters of any shape, and labels sparse points as noise.

Remember: Centres vs crowds.

Lesson 16 →

PCA vs t-SNE

PCA is a linear projection that keeps the directions of greatest variance; it's fast, can transform new data, and keeps global structure. t-SNE is a non-linear method for 2-D visualisation that keeps local neighbourhoods but distorts global distances, and can't be applied to new points directly.

Remember: PCA to compress; t-SNE to look.

Lesson 17 →

Feature selection vs feature extraction

Selection keeps some of the original features. Extraction (PCA, autoencoders) builds new features from combinations of them.

Remember: Choose columns vs make new ones.

Lesson 17 →

Eigenvector vs eigenvalue

In PCA, an eigenvector is a direction (a principal component); its eigenvalue is the variance of the data along that direction.

Remember: Direction vs amount.

Lesson 17 →

Part 5: Neural networks & real projects

Activation function vs loss function

An activation transforms a neuron's output inside the network (ReLU, sigmoid). The loss compares the network's final output with the truth (cross-entropy, MSE).

Remember: Inside the network vs at the end.

Lesson 18 →

Forward pass vs backward pass

The forward pass computes predictions and the loss from the inputs. The backward pass (backpropagation) computes the gradient of the loss with respect to every weight, using the chain rule from the output back to the input.

Remember: Predict, then assign blame.

Lesson 18 →

Dropout vs batch normalisation

Dropout randomly switches off neurons during training to reduce overfitting. Batch normalisation rescales each layer's activations using batch statistics to stabilise and speed up training. Both behave differently at inference time.

Remember: Random silence vs steady scaling.

Lesson 18 →

CNN vs RNN vs Transformer

CNNs slide shared kernels over grids (images). RNNs process sequences one step at a time with a memory. Transformers let every position attend to every other in parallel and now dominate language and much of vision.

Remember: Grids, chains, all-to-all.

Lesson 19 →

Fine-tuning vs feature extraction

Feature extraction freezes a pretrained network and trains only a new output layer on its features. Fine-tuning also updates some or all of the pretrained weights, usually with a small learning rate.

Remember: Use it as-is vs adjust it.

Lesson 19 →

Padding vs stride

Padding adds a border (usually zeros) so the kernel can cover the edges and the output stays larger. Stride is how many pixels the kernel jumps each step; stride 2 roughly halves the output size.

Remember: Padding adds space; stride skips.

Lesson 19 →

Normalisation vs standardisation

Often mixed up. Min–max normalisation rescales to [0, 1]. Standardisation subtracts the mean and divides by the standard deviation (mean 0, SD 1). "Normalisation" is also used loosely for both, and for scaling vectors to length 1.

Remember: Squeeze into a range vs centre and scale.

Lesson 20 →

One-hot vs label vs ordinal encoding

One-hot: one 0/1 column per category (no order implied). Label encoding: arbitrary integers (fine for trees, misleading for linear models). Ordinal encoding: integers in a meaningful order (small < medium < large).

Remember: Switches, ID numbers, or ranks.

Lesson 20 →

Data drift vs concept drift

Data drift: the inputs change (new kinds of customers). Concept drift: what the inputs mean for the target changes (the same behaviour now predicts a different outcome).

Remember: New questions vs new answers to old questions.

Lesson 20 →

Demographic parity vs equal opportunity vs equalised odds

Demographic parity: equal selection rates. Equal opportunity: equal true-positive rates (qualified people treated alike). Equalised odds: equal TPR and equal FPR. When base rates differ they generally can't all hold.

Remember: Equal approvals, equal chances for the qualified, or equal errors of both kinds.

Lesson 21 →

Disparate treatment vs disparate impact

Disparate treatment: explicitly treating people differently because of a protected attribute. Disparate impact: a neutral-looking rule that disproportionately harms a group. A model can cause disparate impact without ever seeing the attribute.

Remember: Intent in the rule vs effect in the outcome.

Lesson 21 →

General & production

Offline vs online evaluation

Offline: metrics on historical, held-out data before deployment. Online: measuring real outcomes with live users, usually via A/B tests. Offline gains don't always appear online.

Remember: Rehearsal vs the real show.

Batch vs real-time inference

Batch: predictions computed in bulk on a schedule and stored. Real-time: a prediction computed when requested, within milliseconds.

Remember: Pre-cooked vs made to order.

Accuracy vs calibration

Accuracy: how often the predicted class is right. Calibration: whether predicted probabilities match how often things really happen.

Remember: Right answers vs honest confidence.
