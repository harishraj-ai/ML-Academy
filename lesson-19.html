1.What makes learning "deep"?

Deep learning means neural networks with many layers. Each layer builds on the previous one: in an image network, early layers detect edges, middle layers combine edges into textures and shapes, and later layers recognise eyes, wheels or letters. The network learns this hierarchy of features by itself, from data.

Lesson 18's fully connected network treats every input independently. For images, sound and text that wastes structure we know is there — nearby pixels belong together; word order matters. Deep learning's big successes come from architectures built around that structure: convolutional networks for images, recurrent networks for sequences, and Transformers, which now power language models. This lesson explains how each works, plus the techniques that make deep networks trainable.

2.Making deep networks trainable

In plain wordsDeep networks are hard to train because the learning signal can fade as it travels back through many layers. ReLU activations, careful starting weights, normalisation layers, shortcut connections and smart optimisers like Adam fix this; dropout reduces overfitting.

Vanishing gradients

Backpropagation multiplies derivatives layer by layer (Lesson 18). The sigmoid's derivative is at most $0.25$. Through 10 sigmoid layers, a gradient can shrink by a factor of up to $0.25^{10} \approx 0.000001$ — the early layers barely learn. This vanishing gradient problem held deep learning back for years. Fixes:

  • ReLU activations: derivative exactly 1 for positive inputs, so gradients pass through undiminished.
  • Careful initialisation: scale random initial weights to the layer size (e.g. "He" or "Glorot" initialisation) so signals neither explode nor vanish.
  • Normalisation layers (batch norm, layer norm): rescale each layer's activations to a stable range during training.
  • Residual (skip) connections: compute $\mathbf{h} + f(\mathbf{h})$ instead of $f(\mathbf{h})$, giving gradients a shortcut path. These made networks with 100+ layers possible.

Better optimisers

Momentum keeps a running average of past gradients, so steps build speed in consistent directions and damp oscillations — like a ball rolling downhill. Adam (Kingma & Ba, ICLR 2015) combines momentum with a per-parameter step size, adapted from running averages of the gradient $g$ and the squared gradient:

$$m \leftarrow \beta_1 m + (1-\beta_1)g, \qquad s \leftarrow \beta_2 s + (1-\beta_2)g^2, \qquad w \leftarrow w - \eta\,\frac{\hat{m}}{\sqrt{\hat{s}} + \epsilon}$$

($\hat{m}, \hat{s}$ are bias-corrected versions of $m, s$; typical values are $\beta_1 = 0.9$, $\beta_2 = 0.999$.) Parameters with consistently large gradients take smaller steps, and rarely-updated ones take larger steps. Adam is the default optimiser in most deep learning work.

Fighting overfitting

  • Dropout: during training, randomly switch off a fraction of neurons (e.g. 20–50%) at each step. No neuron can rely on any specific other neuron, which acts like training an ensemble of many thinner networks (Lesson 14).
  • Data augmentation: create extra training examples by flipping, cropping or slightly rotating images — the label stays the same.
  • Early stopping and weight decay (L2), as before.

3.Convolutional neural networks (CNNs)

A 224×224 colour image has $224\times224\times3 = 150{,}528$ inputs. A fully connected layer of just 1,000 neurons would need 150 million weights — and it would have to learn "cat ear" separately for every position in the image. CNNs fix this with two ideas:

  • Local connections: each neuron looks only at a small patch (e.g. 3×3 pixels).
  • Weight sharing: the same small set of weights — a filter or kernel — is slid across the whole image. A feature detector learned in one place works everywhere.

The convolution operation

Slide the kernel over the image. At each position, multiply the overlapping numbers element by element and add them up; that sum is one pixel of the output, called a feature map.

$$\text{out}[i, j] = \sum_{u}\sum_{v}\text{image}[i + u,\ j + v]\cdot\text{kernel}[u, v]$$
Worked example — detecting a vertical edge

A 4×6 image: dark (0) on the left, bright (9) on the right. A 3×3 vertical-edge kernel:

$$\text{image} = \begin{bmatrix}0&0&0&9&9&9\\0&0&0&9&9&9\\0&0&0&9&9&9\\0&0&0&9&9&9\end{bmatrix} \qquad \text{kernel} = \begin{bmatrix}-1&0&1\\-1&0&1\\-1&0&1\end{bmatrix}$$

The kernel computes (right column − left column) of each 3×3 window.

  • Window over columns 1–3 (all 0s): $0$.
  • Window over columns 2–4: left column 0s, right column 9s: $3\times9 - 0 = 27$.
  • Window over columns 3–5: left 0s, right 9s again: $27$.
  • Window over columns 4–6 (all 9s): $3\times9 - 3\times9 = 0$.
$$\text{feature map} = \begin{bmatrix}0 & 27 & 27 & 0\\ 0 & 27 & 27 & 0\end{bmatrix}$$

The output "lights up" exactly where the edge is and is 0 in flat regions. A CNN learns its kernel values by backpropagation, discovering whatever detectors are useful.

Make sense of it

The situation: A phone camera app needs to find the edge of a document in a photo. A 3×3 kernel slides across the image looking for a jump from dark to bright.

What the result tells you: The feature map is 27 where the window straddles the edge and 0 in flat areas. Big value = "edge here".

What if…?

  • Bright on the left, dark on the right: the map becomes −27. The sign tells you the direction of the edge.
  • A faint edge (0 to 1 instead of 0 to 9): the response is only 3. The size tells you the strength.
  • A horizontal edge (dark top, bright bottom): this vertical-edge kernel gives 0 everywhere. You need a different kernel — so CNNs learn many.

Why it matters in ML: The same small kernel is reused at every position, so a CNN needs few weights and finds a pattern wherever it appears. Early layers learn edges like this; later layers combine them into shapes and objects.

Output size, stride and padding

For input width $W$, kernel size $F$, padding $P$ (zeros added around the border) and stride $S$ (step size):

$$W_{\text{out}} = \frac{W - F + 2P}{S} + 1$$

Example above: $(6 - 3 + 0)/1 + 1 = 4$ ✓. With a 28×28 image, $F = 3$, $P = 1$, $S = 1$: $(28 - 3 + 2)/1 + 1 = 28$ — "same" padding keeps the size.

Channels and parameter counts

A colour image has 3 channels (red, green, blue), so a 3×3 kernel actually has $3\times3\times3 = 27$ weights plus a bias. A layer usually has many kernels, each producing its own feature map. 16 kernels: $(27 + 1)\times16 = 448$ parameters. Compare a fully connected layer from a 32×32×3 image to just 16 neurons: $3072\times16 + 16 = 49{,}168$. Weight sharing makes CNNs over 100 times leaner here.

Pooling

Max pooling shrinks a feature map by keeping only the largest value in each small window, usually 2×2 with stride 2. It keeps "was the feature present around here?" while discarding the exact position, and cuts the size by 4×, which discards 75% of the activations.

Worked example — 2×2 max pooling
$$\begin{bmatrix}1&3&2&0\\4&6&1&1\\0&2&5&7\\1&1&3&2\end{bmatrix} \xrightarrow{\ \text{max pool}\ } \begin{bmatrix}6 & 2\\ 2 & 7\end{bmatrix}$$

Top-left window $\{1, 3, 4, 6\}$ → 6; top-right $\{2, 0, 1, 1\}$ → 2; bottom-left $\{0, 2, 1, 1\}$ → 2; bottom-right $\{5, 7, 3, 2\}$ → 7.

Make sense of it

The situation: After finding edges, the network only needs to know roughly where each one is, not to the exact pixel.

What the result tells you: Each 2×2 window keeps only its strongest response, so the map shrinks to a quarter of its size while keeping the important signals.

What if…?

  • Move the 6 one pixel within its window: the output is still 6. Small shifts don't change the result.
  • Average pooling instead: 3.5, 1, 1, 4.25 — smoother, but weak signals dilute strong ones.

Why it matters in ML: Pooling makes CNNs cheaper and more tolerant of small shifts in position. Many modern networks use strided convolutions instead, but the idea is the same.

A typical CNN

[conv → ReLU → pool] repeated several times (feature maps get smaller but more numerous), then flatten, then one or two fully connected layers, then softmax over the classes.

Step-by-step derivationWhere the output-size formula comes from
  1. $$W + 2P$$

    Padding adds $P$ zeros on each side, so the padded width is $W + 2P$.

  2. $$0,\ S,\ 2S,\ \dots,\ (W + 2P - F)$$

    The kernel's left edge can start at these positions: it must still fit, so the last start is $W + 2P - F$.

  3. $$\frac{W + 2P - F}{S} + 1$$

    Count the positions: the number of steps of size $S$, plus 1 for the starting position.

5.Recurrent neural networks (RNNs)

Text, speech, sensor readings and prices are sequences: order matters, and lengths vary. An RNN reads a sequence one step at a time, carrying a hidden state $\mathbf{h}_t$ — a memory of what it has seen so far:

$$\mathbf{h}_t = \tanh\big(W_h\mathbf{h}_{t-1} + W_x\mathbf{x}_t + \mathbf{b}\big)$$

The same weights are used at every step (weight sharing again, this time across time). The final state, or the state at each step, feeds an output layer — e.g. to classify a review as positive or negative, or to predict the next word.

The problem: training backpropagates through every time step, multiplying by $W_h$ again and again, so gradients vanish (or explode) over long sequences. Plain RNNs struggle to remember things from more than about 10–20 steps back.

LSTMs

The long short-term memory network (Hochreiter & Schmidhuber, 1997) adds a separate cell state — a kind of conveyor belt that information can travel along unchanged — controlled by three gates. Each gate is a sigmoid layer outputting numbers between 0 and 1, multiplied element-wise with the information it controls:

  • the forget gate decides what to erase from the cell state;
  • the input gate decides what new information to write;
  • the output gate decides what part of the cell state to output as $\mathbf{h}_t$.

Because the cell state is updated by addition rather than repeated multiplication, gradients survive over much longer sequences. LSTMs (and the simpler GRUs) dominated sequence tasks until Transformers arrived.

6.Transformers and attention

Picture itAt a busy party you hear your name across the room and instantly tune in to that conversation. Attention lets each word in a sentence tune in to the other words that matter for it, and mostly ignore the rest.

In plain wordsTransformers let every word look at every other word and decide which ones matter for its meaning ("attention"). This works very well and runs fast on GPUs, which is why it powers modern language models.

RNNs process words one at a time, which is slow and makes long-range connections hard. The Transformer (Vaswani et al., 2017, "Attention Is All You Need") is "based solely on attention mechanisms, dispensing with recurrence and convolutions entirely". Every position looks at every other position directly, in one step.

Self-attention

Each word (token) is represented by a vector. From it, the model computes three vectors with learned weight matrices:

  • a query $\mathbf{q}$ — "what am I looking for?",
  • a key $\mathbf{k}$ — "what do I contain?",
  • a value $\mathbf{v}$ — "what do I pass on if selected?".

Each token compares its query with every token's key (dot products — Lesson 2 — measure similarity), turns the scores into weights with softmax (Lesson 8), and takes the weighted average of the values:

$$\text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

Dividing by $\sqrt{d_k}$ (the key length) keeps the scores from growing too large as vectors get longer.

Worked example — attention over three tokens

Three tokens with 2-dimensional vectors. For simplicity, queries = keys: $\mathbf{q}_1 = \mathbf{k}_1 = (1, 0)$, $\mathbf{q}_2 = \mathbf{k}_2 = (0, 1)$, $\mathbf{q}_3 = \mathbf{k}_3 = (1, 1)$. Values: $\mathbf{v}_1 = (1, 0)$, $\mathbf{v}_2 = (0, 1)$, $\mathbf{v}_3 = (0.5, 0.5)$. Here $d_k = 2$, so we divide by $\sqrt2 \approx 1.414$.

Token 1's scores against keys 1, 2, 3: $\frac{(1,0)\cdot(1,0)}{\sqrt2} = 0.707$, $\ \frac{(1,0)\cdot(0,1)}{\sqrt2} = 0$, $\ \frac{(1,0)\cdot(1,1)}{\sqrt2} = 0.707$.

Softmax: $e^{0.707} \approx 2.03$, $e^0 = 1$, $e^{0.707} \approx 2.03$; total $5.06$. Weights $\approx (0.401,\ 0.198,\ 0.401)$.

Output: $0.401\,(1, 0) + 0.198\,(0, 1) + 0.401\,(0.5, 0.5) \approx (0.602,\ 0.398)$.

Token 1 "attended" most to itself and to token 3, whose keys resemble its query, and its new representation mixes in their values. In a sentence like "The animal didn't cross the street because it was tired", attention lets "it" pull information from "animal".

Make sense of it

The situation: In "The animal didn't cross the street because it was tired", the word "it" must find which earlier word it refers to. Attention lets each word ask the others "are you relevant to me?"

What the result tells you: Token 1's query matches keys 1 and 3 equally, so it takes 40% from each and 20% from token 2. Its new vector (0.60, 0.40) is a blend weighted by relevance.

What if…?

  • Without dividing by $\sqrt{d_k}$: weights (0.42, 0.16, 0.42) — sharper. With 512-dimensional vectors, unscaled scores get huge and softmax becomes almost all-or-nothing, which makes training unstable; that's why the scaling is there.
  • A stronger query (10, 0): weights (0.5, 0.0, 0.5) — it ignores token 2 completely.
  • Token 3's query (1, 1) matches itself most: weights (0.25, 0.25, 0.50).

Why it matters in ML: Attention is dot products (similarity), softmax (turn scores into weights) and a weighted average. That's the core of every Transformer, including large language models.

A Transformer stacks many such layers, each with several attention "heads" running in parallel, plus small feed-forward networks, residual connections and layer normalisation. Since attention itself ignores order, a positional encoding is added to each token's vector. Because all positions are processed at once, Transformers train efficiently on GPUs — which is what made today's large language models possible.

Large language models, reasoning models, agents and diffusion image generators are all built from the ideas in this lesson. For a dated overview of recent developments — and how each connects back to this course — see Recent developments in LLMs and generative AI.

Advanced · optionalWhy attention divides by √dₖ

Suppose the entries of a query $\mathbf{q}$ and key $\mathbf{k}$ are independent with mean 0 and variance 1. Then $\mathbf{q}\cdot\mathbf{k} = \sum_{i=1}^{d_k} q_ik_i$ is a sum of $d_k$ terms each with mean 0 and variance 1, so

$$\operatorname{Var}(\mathbf{q}\cdot\mathbf{k}) = d_k, \qquad \operatorname{Var}\!\left(\frac{\mathbf{q}\cdot\mathbf{k}}{\sqrt{d_k}}\right) = 1.$$

Without the scaling, with $d_k = 64$ the scores would have standard deviation 8; softmax of such spread-out numbers puts almost all the weight on one token, and its gradients become tiny (the softmax saturates). Dividing by $\sqrt{d_k}$ keeps the scores in a range where attention can spread out and still learn — the reason given in the original Transformer paper (Vaswani et al., 2017).

Read the formulaScaled dot-product attention
$$\text{Attention} = \htmlClass{fd-1}{\text{softmax}}\Big(\frac{\htmlClass{fd-2}{QK^\top}}{\htmlClass{fd-3}{\sqrt{d_k}}}\Big)\htmlClass{fd-4}{V}$$
  • softmax — turns scores into weights that sum to 1
  • QKᵀ — similarity of every query with every key (dot products)
  • √dₖ — keeps scores from growing too large
  • V — the values that get averaged using those weights

7.Transfer learning: standing on giants' shoulders

Training a large network from scratch needs huge datasets and computing power. Instead, you can take a pretrained model — trained on millions of images or billions of words — and fine-tune it on your smaller dataset. Its early layers already detect general features (edges, word meanings), so you only need to adapt the later layers. This is how most practical deep learning is done today.

8.Tools

scikit-learn's MLPClassifier is fine for small fully connected networks (Lesson 18), but it has no convolutions, recurrence, attention or GPU support. For deep learning, practitioners use PyTorch or TensorFlow/Keras, which compute gradients automatically ("autograd") and run on GPUs.

9.In Python

Convolution, pooling and attention from scratch with NumPy — the same calculations as the worked examples:

import numpy as np

def conv2d(image, kernel):
    kh, kw = kernel.shape
    out = np.zeros((image.shape[0] - kh + 1, image.shape[1] - kw + 1))
    for i in range(out.shape[0]):
        for j in range(out.shape[1]):
            out[i, j] = np.sum(image[i:i+kh, j:j+kw] * kernel)
    return out

image = np.array([[0, 0, 0, 9, 9, 9]] * 4, dtype=float)
edge = np.array([[-1, 0, 1]] * 3, dtype=float)
print(conv2d(image, edge))

fmap = np.array([[1, 3, 2, 0], [4, 6, 1, 1], [0, 2, 5, 7], [1, 1, 3, 2]], dtype=float)
print(fmap.reshape(2, 2, 2, 2).max(axis=(1, 3)))      # 2x2 max pooling

def attention(Q, K, V):
    scores = Q @ K.T / np.sqrt(K.shape[1])
    weights = np.exp(scores) / np.exp(scores).sum(axis=1, keepdims=True)   # softmax per row
    return weights, weights @ V

Q = K = np.array([[1, 0], [0, 1], [1, 1]], dtype=float)
V = np.array([[1, 0], [0, 1], [0.5, 0.5]])
weights, out = attention(Q, K, V)
print(weights.round(3))
print(out.round(3))

import torch.nn as nn

model = nn.Sequential(
    nn.Conv2d(1, 16, kernel_size=3, padding=1),   # 28x28x1  -> 28x28x16
    nn.ReLU(),

    nn.Flatten(),                                 # -> 1568 numbers
    nn.Dropout(0.25),
    nn.Linear(32 * 7 * 7, 10),                    # one score per digit
)

11.Questions beginners often ask

Do I need a GPU?

For training large networks on images or text, yes in practice. For small experiments and for fine-tuning small pretrained models, a CPU can be enough.

What's the difference between a CNN and a Transformer?

CNNs look at local patches with shared filters — ideal for images. Transformers let every position attend to every other — ideal for sequences like text, and now also used for images.

Should I train from scratch?

Rarely. Fine-tuning a pretrained model needs far less data and computing power.

Common mistakes to avoid
  • Training a large network from scratch when a pretrained model could be fine-tuned.
  • Forgetting to switch dropout off when evaluating (in PyTorch: model.eval()).
  • Using sigmoid in every layer of a deep network (vanishing gradients) — prefer ReLU in hidden layers.
Interview corner

Don't confuse

  • CNN vs RNN vs Transformer — Grids, chains, all-to-all.
  • Fine-tuning vs feature extraction — Use it as-is vs adjust it.
  • Padding vs stride — Padding adds space; stride skips.

Hidden questions — answer in your head first, then open.

Why do CNNs need far fewer parameters than dense networks on images?

The trap: "Convolutions are just efficient."

Weight sharing: one small kernel is reused at every position. A 3×3 convolution from 3 to 64 channels has 1,792 parameters whatever the image size; a dense layer from a 224×224×3 image to just 64 units needs 9,633,856.

Why does attention divide by $\sqrt{d_k}$?

The trap: "For normalisation", with no explanation.

Dot products of random $d_k$-dimensional vectors have a spread that grows like $\sqrt{d_k}$. Without scaling, large scores push softmax towards all-or-nothing, where its gradients vanish. Dividing keeps scores in a range where softmax is still sensitive.

Why do Transformers need positional encodings?

The trap: Assuming attention knows word order.

Attention treats its inputs as a set: shuffle the tokens and each output is just shuffled too. "Dog bites man" and "man bites dog" would look the same. Positional encodings (fixed or learned) add order information.

Why did LSTMs replace simple RNNs, and why did Transformers largely replace LSTMs?

The trap: Naming them without the reasons.

Simple RNNs suffer vanishing gradients over long sequences; LSTMs' gates and cell state carry information further. Transformers then removed the step-by-step recurrence: attention connects any two positions directly and trains in parallel on GPUs.

12.Key takeaways

  • Deep networks learn a hierarchy of features. ReLU, good initialisation, normalisation and residual connections fight vanishing gradients; Adam and dropout help training and generalization.
  • CNNs slide small shared kernels over images: output size $(W - F + 2P)/S + 1$; pooling downsamples.
  • RNNs carry a hidden state through a sequence; LSTMs use gates and a cell state to remember longer.
  • Transformers use self-attention, $\text{softmax}(QK^\top/\sqrt{d_k})V$, so every token can look at every other token at once.
  • In practice, start from a pretrained model and fine-tune it.

14.Going deeper: attention and residual connections, from scratch

In plain wordsThe two ideas behind modern architectures, built from scratch: attention (each token takes a weighted average of the others, with weights from matching queries and keys) and residual connections (a shortcut that lets gradients reach the early layers). Also: why attention divides by the square root of the dimension, positional encodings, and ways to adapt pretrained models (fine-tuning, LoRA).

Intermediate · skip on a first read

Two ideas power nearly every modern architecture, from image models to large language models: attention, which lets each part of the input decide which other parts matter, and residual connections, which make networks with hundreds of layers trainable. This section builds both in a few lines of NumPy, measures why attention divides by $\sqrt{d}$, and explains how pretrained models are adapted to new tasks.

You'll need: this lesson, the softmax from Lesson 8, and vanishing gradients from Lesson 18's "Going deeper".

Attention, step by step

Each token (a word piece, or an image patch) is a vector. Three learned matrices turn it into a query ("what am I looking for?"), a key ("what do I contain?") and a value ("what will I pass on?"). Each token's output is a weighted average of all the values, where the weights come from how well its query matches each key:

$$\operatorname{Attention}(Q, K, V) = \operatorname{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

import numpy as np

# Scaled dot-product attention from scratch, for a "sentence" of 4 tokens with 8-number vectors
rng = np.random.default_rng(0)
X = rng.normal(size=(4, 8))                                    # one row per token
Wq, Wk, Wv = (rng.normal(0, 1 / np.sqrt(8), size=(8, 8)) for _ in range(3))
Q, K, V = X @ Wq, X @ Wk, X @ Wv

def softmax(s):
    e = np.exp(s - s.max(axis=-1, keepdims=True))
    return e / e.sum(axis=-1, keepdims=True)

A = softmax(Q @ K.T / np.sqrt(8))                              # attention weights, one row per token
out = A @ V                                                    # each output mixes the value vectors
print("attention weights (row i: how much token i looks at each token):")
print(A.round(2))
print("each row sums to:", A.sum(axis=1).round(3), "  output shape:", out.shape)

Output:

attention weights (row i: how much token i looks at each token):
[[0.34 0.13 0.33 0.2 ]
 [0.78 0.   0.05 0.17]
 [0.25 0.28 0.29 0.18]
 [0.22 0.28 0.21 0.29]]
each row sums to: [1. 1. 1. 1.]   output shape: (4, 8)

Row $i$ of the weight matrix shows how much token $i$ attends to each token, and each row adds up to 1. Token 2 (the second row) puts 78% of its attention on token 1, while token 3 spreads its attention almost evenly. Every token's output is computed in parallel by matrix products, which is why transformers train so efficiently on GPUs compared with RNNs, which must process one step at a time. Multi-head attention runs several of these in parallel with different matrices, so different heads can track different relationships (grammar, meaning, position), and concatenates their outputs.

Why divide by $\sqrt{d_k}$, measured

If query and key entries have variance 1, their dot product over $d$ dimensions has variance $d$, so its spread grows like $\sqrt{d}$. Large scores push the softmax towards a one-hot choice, where its gradients are almost zero, and learning stalls. Dividing by $\sqrt{d}$ brings the spread back to about 1. Here each query is compared with 10 random keys:

# Why divide by sqrt(d)? Dot products of random vectors grow with d, making softmax nearly one-hot
for d in [8, 64, 512]:
    q, k = rng.normal(size=(1000, d)), rng.normal(size=(1000, 10, d))
    raw = np.einsum("nd,nkd->nk", q, k)
    top_raw = softmax(raw).max(axis=1).mean()
    top_scaled = softmax(raw / np.sqrt(d)).max(axis=1).mean()
    print(f"d {d:3d}: spread of dot products {raw.std():6.1f}   average top weight, unscaled {top_raw:.2f}, scaled {top_scaled:.2f}")

Output:

d   8: spread of dot products    2.9   average top weight, unscaled 0.62, scaled 0.31
d  64: spread of dot products    8.0   average top weight, unscaled 0.85, scaled 0.31
d 512: spread of dot products   22.5   average top weight, unscaled 0.95, scaled 0.32

Unscaled, the average largest weight climbs from 0.62 at $d = 8$ to 0.95 at $d = 512$: almost every query locks onto a single key. Scaled, it stays about 0.31 at every size, so attention stays soft and trainable. (This lesson's "Advanced" box derives the variance argument.)

Residual connections

A residual block computes $\mathbf{h} + f(\mathbf{h})$ instead of $f(\mathbf{h})$: the layer learns a correction to its input rather than a whole new representation. In backpropagation the derivative of $\mathbf{h} + f(\mathbf{h})$ is $I + J_f$, so there is always an identity path for the gradient, however small $J_f$ becomes (Lesson 3's "Going deeper" described the chain rule as multiplying Jacobians). Here is a 50-layer tanh network with small weights, with and without shortcuts:

# Residual connections: gradient reaching the first of 50 layers, with and without a shortcut h + f(h)
def first_layer_grad(residual, depth=50, width=64):
    W = [rng.normal(0, 0.5 / np.sqrt(width), size=(width, width)) for _ in range(depth)]   # small weights
    h = rng.normal(size=(32, width)); zs = []
    for Wl in W:
        z = h @ Wl; zs.append(z)
        h = h + np.tanh(z) if residual else np.tanh(z)
    g = np.ones_like(h)
    for Wl, z in zip(reversed(W), reversed(zs)):
        local = (g * (1 - np.tanh(z) ** 2)) @ Wl.T              # gradient through the layer itself
        g = g + local if residual else local                    # the shortcut adds an identity path
    return np.linalg.norm(g)

print("plain 50-layer network, gradient at layer 1:   ", f"{first_layer_grad(False):.2e}")
print("residual 50-layer network, gradient at layer 1:", f"{first_layer_grad(True):.2e}")

Output:

plain 50-layer network, gradient at layer 1:    2.04e-14
residual 50-layer network, gradient at layer 1: 4.02e+02

Without shortcuts, the gradient reaching the first layer is $2\times 10^{-14}$: effectively zero, so the early layers never learn. With shortcuts it's about 400. ResNets (2015) used this to train image networks with over 100 layers, and every transformer block wraps both its attention and its feed-forward part in a residual connection, usually with layer normalisation (Lesson 18's "Going deeper").

Positions, and putting a transformer block together

Attention on its own treats the input as an unordered set: shuffle the tokens and each output just moves with its token. Word order is reintroduced with positional encodings added to the token vectors: the original transformer used sine and cosine waves of different frequencies, $PE_{(p, 2i)} = \sin(p/10000^{2i/d})$, and many modern LLMs use rotary encodings (RoPE), which rotate queries and keys by an angle that depends on position. One transformer block is then:

  1. Multi-head self-attention, plus a residual connection, then layer norm.
  2. A small feed-forward network applied to each token separately (usually two layers with a GELU activation), plus a residual connection, then layer norm.

A language model stacks dozens of these blocks, uses a causal mask so each token can only attend to earlier tokens, and is trained to predict the next token.

Transfer learning and fine-tuning

Training a large model from scratch needs huge data and compute. Instead, start from a model pretrained on a broad task (images from ImageNet, or text from the web) and adapt it:

ApproachWhat's trainedWhen to use it
Feature extractionOnly a new output layer; the pretrained network is frozenVery little data; a task close to the pretraining task
Fine-tuningAll or the top layers, with a small learning rateA moderate amount of data; the best accuracy
Parameter-efficient fine-tuning (LoRA, adapters)Small added matrices; the original weights are frozenLarge language models: much less memory and storage per task
Prompting / in-context learningNothingLLMs, when instructions and a few examples are enough

LoRA uses an idea from Lesson 2's "Going deeper": it learns the change to a big weight matrix as a product of two thin matrices, $\Delta W = BA$ with rank $r$ of perhaps 8 or 16, so a $4096 \times 4096$ layer needs about $2 \times 4096 \times 8 = 65{,}536$ new numbers instead of 16.8 million.

Hidden questions — answer in your head first, then open.

Walk me through what a single self-attention head computes.

The trap: Describing attention as "focusing" without the computation.

Project each token's vector into a query, key and value with learned matrices. Compute scores $QK^\top$, scale by $1/\sqrt{d_k}$, apply a mask if needed (causal masking for language models), and softmax each row into weights. Each output is the weighted sum of the value vectors. Cost is quadratic in sequence length, which is why long contexts are expensive and why efficient-attention variants exist.

Why are residual connections so important in deep networks?

The trap: "They add information from earlier layers."

They make each block learn a correction $f(\mathbf{h})$ to an identity mapping. In backprop the Jacobian becomes $I + J_f$, so gradients always have a direct path to early layers, avoiding vanishing gradients through many layers. They also make very deep networks easy to optimise, since a block can default to doing almost nothing. Both ResNets and transformers depend on them.

What's LoRA, and why is it popular for fine-tuning LLMs?

The trap: Calling it a type of quantization.

Low-Rank Adaptation freezes the pretrained weights and learns, for chosen layers, a low-rank update $\Delta W = BA$ (rank 4–64). That trains and stores a tiny fraction of the parameters, needs much less GPU memory, and lets you keep many task-specific adapters for one base model. Quality is often close to full fine-tuning. QLoRA combines it with a quantized base model to save more memory.

Check your understanding: going deeper

1. In attention, what does each row of $\operatorname{softmax}(QK^\top/\sqrt{d})$ add up to?

Each row is a softmax: a set of weights for averaging the value vectors.

2. Without the $\sqrt{d}$ scaling, large $d$ makes the attention weights…

Dot-product spread grows like $\sqrt{d}$, pushing the softmax towards a single winner.

3. Why do residual connections help gradients flow?

Even if $f$'s Jacobian is tiny, the identity path carries the gradient back.

4. Without positional encodings, a transformer would treat a sentence as…

Self-attention is permutation-equivariant: it has no built-in notion of order.

5. LoRA fine-tunes a large model by…

$\Delta W = BA$ with a small rank, which is far fewer numbers to train and store.
