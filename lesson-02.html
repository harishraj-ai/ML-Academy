This lesson builds on:

  • Lesson 1: What Is Machine Learning? — A model maps features $x$ to a prediction $\hat{y}$. Training adjusts its parameters to make a loss (such as MSE) small, and the real goal is doing well on new data.

Where this fits: Every model in the course is written in the language of vectors and matrices. Learning it now makes the formulas in Lessons 6, 8, 15, 17 and 18 readable.

1.Why vectors and matrices?

In Lesson 1, each house was described by a list of numbers: size, bedrooms, distance. A whole dataset was a table of such lists. In maths, a list of numbers is called a vector, and a table of numbers is called a matrix. Almost every ML algorithm is written in this language, because it lets us describe operations on thousands of examples and features in one short line — and lets computers run them very fast.

You only need a handful of ideas, and we'll build each one by hand before using code.

2.Vectors: lists of numbers with meaning

A vector is an ordered list of numbers. We write it in bold or with an arrow, and usually as a column:

$$\mathbf{x} = \begin{bmatrix} 50 \\ 1 \\ 2 \end{bmatrix}$$

This could be a house with size 50, 1 bedroom, 2 km from the city. The number of entries is the vector's dimension; this vector lives in 3-dimensional space, written $\mathbf{x} \in \mathbb{R}^3$ ("x is a vector of 3 real numbers"). The entries are called components, and we refer to them as $x_1, x_2, x_3$.

Two ways to picture a vector

As a point: the vector $(3, 2)$ is the point 3 steps right and 2 steps up. As an arrow: an arrow from the origin $(0,0)$ to that point — it has a direction and a length. Both pictures are useful. In ML, each example is a point in "feature space", and similar examples are points close together.

3.Adding and scaling vectors

Addition works component by component (the vectors must have the same dimension):

$$\begin{bmatrix} 1 \\ 2 \end{bmatrix} + \begin{bmatrix} 3 \\ -1 \end{bmatrix} = \begin{bmatrix} 1+3 \\ 2+(-1) \end{bmatrix} = \begin{bmatrix} 4 \\ 1 \end{bmatrix}$$

Geometrically: walk along the first arrow, then the second; you end at the sum.

Scalar multiplication multiplies every component by a single number (a scalar):

$$3 \begin{bmatrix} 1 \\ 2 \end{bmatrix} = \begin{bmatrix} 3 \\ 6 \end{bmatrix}$$

This stretches the arrow 3 times longer in the same direction. Multiplying by $-1$ flips it around.

Where you'll see this

In gradient descent (Lesson 7), the update rule $\mathbf{w}_{\text{new}} = \mathbf{w} - \eta\,\nabla L$ is exactly "scale a vector, then subtract it from another vector".

4.Length (norm) and distance

The length of a vector — its norm — comes from Pythagoras' theorem. For $\mathbf{v} = (3, 4)$:

$$\|\mathbf{v}\| = \sqrt{3^2 + 4^2} = \sqrt{25} = 5$$

In general, for a vector with $d$ components:

$$\|\mathbf{v}\| = \sqrt{v_1^2 + v_2^2 + \dots + v_d^2} = \sqrt{\sum_{i=1}^{d} v_i^2}$$

This is the Euclidean (or L2) norm. The distance between two points is the length of their difference: $\text{dist}(\mathbf{a}, \mathbf{b}) = \|\mathbf{a} - \mathbf{b}\|$.

Worked example — distance between two houses

House A = (size 5, bedrooms 2), house B = (size 8, bedrooms 6). Difference $= (8-5,\ 6-2) = (3, 4)$. Distance $= \sqrt{9+16} = 5$.

The k-nearest-neighbours algorithm (Lesson 11) classifies a new example by finding the training examples with the smallest distance to it — exactly this calculation.

Make sense of it

The situation: A property app shows "homes like this one". It needs a number for how alike two homes are, and distance is that number.

What the result tells you: A distance of 5 combines a size difference of 3 and a bedroom difference of 4 into one number, using Pythagoras. Smaller means more similar.

What if…?

  • Same bedrooms: if both homes had 2 bedrooms, the distance is just the size gap, 3.
  • Change the units: measure size in m² instead (500 vs 800). The difference becomes $(300, 4)$ and the distance 300.03 — bedrooms now barely count. Nothing about the houses changed, only the units.
  • Shrink the size scale instead (5 → 0.5, 8 → 0.8): the distance is about 4.01, almost all from bedrooms.

Why it matters in ML: kNN, k-means and SVMs all rely on distances, so the feature with the biggest numbers wins by default. That's why we standardise features first (Lessons 11 and 20).

Another norm you'll meet is the L1 norm, the sum of absolute values: $\|\mathbf{v}\|_1 = |v_1| + |v_2| + \dots$. For $(3, 4)$ it is $7$ — the distance if you could only walk along a city grid. It appears in Lasso regularization (Lesson 10).

5.The dot product — the most important operation in ML

Picture itAt a shop you buy 2 notebooks at ₹40, 3 pens at ₹10 and 1 bag at ₹500. Your bill is $2\cdot40 + 3\cdot10 + 1\cdot500 = 610$: multiply matching entries and add. That's a dot product — and it's exactly how a linear model turns features and weights into a prediction.

The dot product takes two vectors of the same length and returns a single number: multiply matching components and add them up.

$$\mathbf{a} \cdot \mathbf{b} = a_1 b_1 + a_2 b_2 + \dots + a_d b_d = \sum_{i=1}^{d} a_i b_i$$
Worked example

$\mathbf{a} = (2, 3, 1)$, $\mathbf{b} = (4, -1, 5)$.

$\mathbf{a} \cdot \mathbf{b} = 2\cdot4 + 3\cdot(-1) + 1\cdot5 = 8 - 3 + 5 = 10$.

Make sense of it

The situation: Think of $\mathbf{a}$ as one applicant's three feature values and $\mathbf{b}$ as the weights a model gives those features. The dot product is the model's score.

What the result tells you: Each pair contributes separately: $8$ from the first feature, $-3$ from the second (its weight is negative, so it pulls the score down) and $5$ from the third. The total score is 10.

What if…?

  • Raise the second feature from 3 to 6: the score falls to 7, because that feature has a negative weight.
  • Flip every weight to $(-4, 1, -5)$: the score becomes −10 — the vectors now point in opposite directions.
  • Weights $(3, -2, 0)$: the score is 0 — the vectors are perpendicular, and this applicant is "neutral" to the model.

Why it matters in ML: Every linear model, every neuron and every attention score in a Transformer is a dot product of inputs with weights. Reading it as "sum of contributions" lets you see which feature pushed a prediction up or down.

Why it matters: a prediction is a dot product

Suppose a model predicts price as $\text{price} = 3\cdot\text{size} + 20\cdot\text{bedrooms} - 5\cdot\text{distance}$. Put the weights in one vector $\mathbf{w} = (3, 20, -5)$ and the features in another $\mathbf{x} = (50, 1, 2)$. Then:

$$\hat{y} = \mathbf{w}\cdot\mathbf{x} = 3\cdot50 + 20\cdot1 + (-5)\cdot2 = 150 + 20 - 10 = 160$$

So a linear model's prediction is a dot product (plus a bias $b$): $\hat{y} = \mathbf{w}\cdot\mathbf{x} + b$. Each weight says how much its feature matters, and its sign says in which direction.

The geometric meaning: how aligned are two vectors?

The dot product also equals:

$$\mathbf{a}\cdot\mathbf{b} = \|\mathbf{a}\|\,\|\mathbf{b}\|\cos\theta$$

where $\theta$ is the angle between the arrows. Since $\cos 0° = 1$, $\cos 90° = 0$, $\cos 180° = -1$:

  • Positive dot product → vectors point in a similar direction.
  • Zero → perpendicular (called orthogonal): unrelated directions.
  • Negative → pointing in opposite directions.

Dividing out the lengths gives cosine similarity, a score from $-1$ to $1$ widely used to compare documents, words and images:

$$\cos\theta = \frac{\mathbf{a}\cdot\mathbf{b}}{\|\mathbf{a}\|\,\|\mathbf{b}\|}$$
Advanced · optionalWhy a·b = ‖a‖‖b‖cos θ

Put $\mathbf{a}$ and $\mathbf{b}$ tail to tail; the third side of the triangle is $\mathbf{a}-\mathbf{b}$. Expanding with the dot product:

$$\|\mathbf{a}-\mathbf{b}\|^2 = (\mathbf{a}-\mathbf{b})\cdot(\mathbf{a}-\mathbf{b}) = \|\mathbf{a}\|^2 + \|\mathbf{b}\|^2 - 2\,\mathbf{a}\cdot\mathbf{b}.$$

The law of cosines says the same side satisfies $\|\mathbf{a}-\mathbf{b}\|^2 = \|\mathbf{a}\|^2 + \|\mathbf{b}\|^2 - 2\|\mathbf{a}\|\|\mathbf{b}\|\cos\theta$. Comparing the two gives $\mathbf{a}\cdot\mathbf{b} = \|\mathbf{a}\|\|\mathbf{b}\|\cos\theta$. Because $|\cos\theta|\le 1$, it also proves the Cauchy–Schwarz inequality $|\mathbf{a}\cdot\mathbf{b}| \le \|\mathbf{a}\|\|\mathbf{b}\|$, which we use in Lesson 3.

7.Matrices: tables of numbers

A matrix is a rectangular grid of numbers. A matrix with $m$ rows and $n$ columns has shape $m \times n$. Our house dataset (4 houses × 3 features) is a $4 \times 3$ matrix, conventionally called $X$:

$$X = \begin{bmatrix} 50 & 1 & 2 \\ 80 & 2 & 5 \\ 120 & 3 & 12 \\ 150 & 4 & 3 \end{bmatrix}$$

Each row is one example; each column is one feature. This convention is used throughout ML and in scikit-learn. The entry in row $i$, column $j$ is written $X_{ij}$; for example, $X_{32} = 3$ (house 3 has 3 bedrooms).

8.Matrix × vector: predicting for all examples at once

Multiplying a matrix by a vector means taking the dot product of each row with the vector:

$$X\mathbf{w} = \begin{bmatrix} \text{row}_1 \cdot \mathbf{w} \\ \text{row}_2 \cdot \mathbf{w} \\ \vdots \end{bmatrix}$$
Worked example — four predictions in one step

With $\mathbf{w} = (3, 20, -5)$:

Row 1: $3\cdot50 + 20\cdot1 - 5\cdot2 = 160$
Row 2: $3\cdot80 + 20\cdot2 - 5\cdot5 = 255$
Row 3: $3\cdot120 + 20\cdot3 - 5\cdot12 = 360$
Row 4: $3\cdot150 + 20\cdot4 - 5\cdot3 = 515$

$$X\mathbf{w} = \begin{bmatrix} 160 \\ 255 \\ 360 \\ 515 \end{bmatrix}$$

One expression, $\hat{\mathbf{y}} = X\mathbf{w}$, produced predictions for every house. That's why ML is written with matrices.

Make sense of it

The situation: Each row is one house: size (m²), bedrooms and age (years). The weights say each m² adds 3, each bedroom 20, and each year of age removes 5.

What the result tells you: 160, 255, 360 and 515 are the model's predicted prices for the four houses — computed in one matrix–vector product instead of four separate sums.

What if…?

  • House 1 gains a bedroom (1 → 2): its prediction rises by exactly the bedroom weight, 160 → 180.
  • House 1 is 10 years older (2 → 12): 10 × (−5) = −50, so the prediction drops to 110.
  • Change one weight (size 3 → 4): every prediction rises by that house's size — 210, 335, 480, 665. One weight affects every row.

Why it matters in ML: Training adjusts the weights so that $X\mathbf{w}$ matches the real prices. Because every weight touches every prediction, changing one weight is a global change — which is exactly what gradient descent does, a little at a time.

Shape rule: an $(m \times n)$ matrix times an $n$-vector gives an $m$-vector. The inner sizes ($n$) must match — each row needs exactly as many numbers as the vector has.

9.Matrix × matrix

In plain wordsMultiplying two matrices repeats the dot product for every row of the first and every column of the second. You'll rarely do it by hand — NumPy does it — but the shape rule matters: the inner sizes must match, like (3×4)(4×2) → 3×2.

To multiply $A$ ($m \times n$) by $B$ ($n \times p$), compute every row of $A$ dotted with every column of $B$. The result $C = AB$ has shape $m \times p$, with $C_{ij} = (\text{row } i \text{ of } A)\cdot(\text{column } j \text{ of } B)$.

Worked example
$$\begin{bmatrix} 1 & 2 \\ 3 & 4 \end{bmatrix}\begin{bmatrix} 5 & 6 \\ 7 & 8 \end{bmatrix} = \begin{bmatrix} 1\cdot5+2\cdot7 & 1\cdot6+2\cdot8 \\ 3\cdot5+4\cdot7 & 3\cdot6+4\cdot8 \end{bmatrix} = \begin{bmatrix} 19 & 22 \\ 43 & 50 \end{bmatrix}$$
Make sense of it

The situation: A neural network applies one transformation after another. Multiplying their matrices gives a single matrix that does both steps at once.

What the result tells you: Each entry of the result is a row of the first matrix dotted with a column of the second: $19 = 1\cdot5 + 2\cdot7$.

What if…?

  • Swap the order: $BA = \begin{bmatrix} 23 & 34 \\ 31 & 46 \end{bmatrix}$, not the same as $AB$. Doing step B then step A is a different overall transformation.

Why it matters in ML: Layers in a network are matrix multiplications applied in a fixed order. It's also why a stack of purely linear layers collapses into one matrix — and why networks need non-linear activations between them (Lesson 18).

Order matters

In general $AB \neq BA$. And the shapes must line up: $(m \times \mathbf{n})(\mathbf{n} \times p)$. If you ever see a "shapes not aligned" error in NumPy, this rule is why.

Neural networks (Lesson 18) are mostly matrix multiplications: each layer computes $W\mathbf{x} + \mathbf{b}$ for a weight matrix $W$.

10.Transpose and the identity matrix

In plain wordsThe transpose flips a table so rows become columns. It appears in many formulas simply to make the shapes line up.

The transpose $A^\top$ flips a matrix over its diagonal: rows become columns.

$$\begin{bmatrix} 1 & 2 & 3 \\ 4 & 5 & 6 \end{bmatrix}^\top = \begin{bmatrix} 1 & 4 \\ 2 & 5 \\ 3 & 6 \end{bmatrix}$$

A $2\times3$ matrix becomes $3\times2$. You'll see it constantly: the dot product can be written $\mathbf{a}^\top\mathbf{b}$, and the linear regression solution (Lesson 6) contains $X^\top X$.

The identity matrix $I$ has 1s on the diagonal and 0s elsewhere. It acts like the number 1: $I\mathbf{x} = \mathbf{x}$.

$$I_3 = \begin{bmatrix} 1 & 0 & 0 \\ 0 & 1 & 0 \\ 0 & 0 & 1 \end{bmatrix}$$

11.Doing it in Python with NumPy

NumPy is the Python library for vectors and matrices. Everything above, in a few lines:

import numpy as np

a = np.array([2, 3, 1])
b = np.array([4, -1, 5])
print(a + b)             # [6 2 6]      addition
print(3 * a)             # [6 9 3]      scalar multiplication
print(a @ b)             # 10           dot product
print(np.linalg.norm(np.array([3, 4])))   # 5.0   length

X = np.array([[50, 1, 2],
              [80, 2, 5],
              [120, 3, 12],
              [150, 4, 3]])
w = np.array([3, 20, -5])
print(X.shape)           # (4, 3)  4 examples, 3 features
print(X @ w)             # [160 255 360 515]   all predictions at once
print(X.T.shape)         # (3, 4)  transpose

The @ operator means matrix multiplication (or a dot product, for two vectors). Run this and compare with the hand calculations above — they match.

12.Running example: Chennai Homes

Each house becomes a vector of numbers, and the whole table becomes a matrix $X$ with 12 rows and 4 columns. Houses 1 and 2 are 26 units apart (mostly because their sizes differ by 25 m²). Multiplying $X$ by a weight vector gives a prediction for every house at once.

Same 12 houses as Lesson 1. With so little data, treat the numbers as an illustration of the method, not as reliable estimates.

import pandas as pd
import numpy as np
df = pd.read_csv("houses.csv")   # download it from Lesson 1
X = df[["size_m2", "bedrooms", "dist_km", "age_yrs"]].to_numpy()
print(X.shape)                                   # 12 houses x 4 features
a, b = X[0], X[1]                                # house 1 and house 2 as vectors
print(a, b, round(np.linalg.norm(a - b), 2))     # their Euclidean distance
w = np.array([0.6, 2.0, -1.2, -0.5])             # some made-up weights
print((X @ w)[:3].round(1))                      # predictions for the first 3 houses

Output:

(12, 4)
[65  1  2  5] [90  2  3 12] 26.0
[36.1 48.4 63.2]
Where this is used
  • Representing customers, images and words as vectors
  • Search engines and recommenders comparing items with cosine similarity
  • GPUs running matrix multiplications for neural networks

Choose it when: Always — this is the notation for nearly all ML.

Misconceptions to unlearn

MythThe dot product measures distance.

RealityIt measures alignment (and depends on lengths). Distance is $\|\mathbf{a} - \mathbf{b}\|$ — two very different things.

MythA matrix is just storage for numbers.

RealityA matrix also represents an operation: multiplying by it transforms vectors. That's what each neural-network layer does.

Responsible AI · Turning people into vectors

Representing a person as a list of numbers hides choices. A feature such as a postcode can act as a proxy for ethnicity or income even if those columns are removed, so a model can discriminate without ever "seeing" a protected attribute. Removing a sensitive column is not enough; check what the remaining features correlate with.

13.Questions beginners often ask

Why use matrices instead of loops?

They describe operations on all examples at once in one short expression, and libraries like NumPy run them in fast compiled code — often hundreds of times faster than a Python loop.

What's the difference between a vector and a list?

In code they look alike. Mathematically, a vector supports operations like addition, scaling and dot products, and has a length and a direction.

Do I have to multiply matrices by hand?

No — NumPy's @ does it. Doing a few small ones by hand builds the intuition you need to read formulas and fix shape errors.

Common mistakes to avoid
  • Multiplying matrices whose inner sizes don't match — check shapes first: $(m\times n)(n\times p)$.
  • Assuming $AB = BA$. Matrix multiplication order matters.
  • Mixing up NumPy's * (element-wise) with @ (matrix multiplication / dot product).
Interview corner

Don't confuse

  • Dot product vs element-wise product — Dot product ends in a sum.
  • Distance vs similarity — Distance: smaller is closer. Similarity: bigger is closer.
  • L1 norm vs L2 norm — L1 walks the streets; L2 flies.

Hidden questions — answer in your head first, then open.

Is cosine similarity a distance? What does it ignore?

The trap: Treating 1 − cosine as a proper distance.

It measures the angle between vectors and ignores their lengths, so (1, 1) and (100, 100) are identical to it. $1 - \cos$ is not a true metric: it can violate the triangle inequality. Use it when direction matters more than magnitude, as with text embeddings.

Can the nearest neighbour change if you switch from Euclidean (L2) to Manhattan (L1) distance?

The trap: Assuming distances always agree on order.

Yes. From (0, 0): the point (3, 0) is at L1 distance 3 and L2 distance 3; the point (2, 2) is at L1 4 but L2 2.83. L1 picks (3, 0); L2 picks (2, 2).

In NumPy, what's the difference between A * B and A @ B?

The trap: Using * for matrix multiplication.

* multiplies element by element (and broadcasts). @ is matrix multiplication. A forward pass needs @; using * can silently give a wrong answer instead of an error if the shapes happen to broadcast.

Why do we write predictions as $X\mathbf{w}$ with examples as rows?

The trap: Thinking the order is arbitrary.

With $X$ of shape $(n, d)$ (one row per example) and $\mathbf{w}$ of shape $(d,)$, $X\mathbf{w}$ gives one prediction per row. It's a convention, but it fixes every other shape — in a neural layer, inputs $(n, d)$ times weights $(d, h)$ give outputs $(n, h)$.

14.Key takeaways

  • A vector is a list of numbers — one example's features, or a model's weights.
  • A matrix is a table — a dataset $X$ has one row per example and one column per feature.
  • The norm measures length; $\|\mathbf{a}-\mathbf{b}\|$ measures distance between examples.
  • The dot product $\mathbf{w}\cdot\mathbf{x} = \sum w_i x_i$ is how linear models make predictions, and it measures how aligned two vectors are.
  • $X\mathbf{w}$ computes predictions for all examples at once. Inner dimensions must match.

15.Check your understanding

1. What is $(1, 2, 3)\cdot(4, 0, -1)$?

$1\cdot4 + 2\cdot0 + 3\cdot(-1) = 4 + 0 - 3 = 1$.

2. What is the length of $(6, 8)$?

$\sqrt{36 + 64} = \sqrt{100} = 10$. (14 is the L1 norm.)

3. A dataset has 500 examples and 20 features. What is the shape of $X$?

Rows = examples, columns = features: $500 \times 20$.

4. Two vectors have a dot product of 0. What does that tell you?

$\cos 90° = 0$, so non-zero vectors with dot product 0 are at a right angle (orthogonal).

5. $A$ is $3\times4$ and $B$ is $4\times2$. What is the shape of $AB$?

$(3\times\mathbf{4})(\mathbf{4}\times2)$: inner sizes match, result is outer sizes $3\times2$.

16.Going deeper: the linear algebra behind ML algorithms

In plain wordsThe linear algebra that explains how algorithms behave: different ways to measure size (norms), when a set of features carries duplicate information (rank), the special directions a matrix only stretches (eigenvectors, the heart of PCA), the SVD that finds hidden structure in a data table, and why nearly duplicate features make weights unstable (the condition number).

Intermediate · skip on a first read

The lesson above gives you what you need to use vectors and matrices in ML code. This section covers the ideas that explain why algorithms behave as they do: why lasso and ridge give different weights, why some regressions can't be solved, how PCA and recommender systems find hidden structure, and why nearly duplicate features make a model unstable. Each idea is used again in a later lesson, which is named as you go.

You'll need: everything in this lesson, especially the dot product, matrix × matrix and the transpose.

Other ways to measure size: norms

Section 4 measured a vector's length with the familiar straight-line distance. That's one norm, a rule that gives every vector a size. ML uses several, and the choice changes how models behave:

  • L2 norm $\lVert\mathbf{v}\rVert_2 = \sqrt{v_1^2 + \dots + v_n^2}$: the straight-line length. Big entries count a lot, because they're squared.
  • L1 norm $\lVert\mathbf{v}\rVert_1 = |v_1| + \dots + |v_n|$: the "city-block" distance, as if you could only walk along streets. Every entry counts in proportion to its size.
  • L∞ norm $\lVert\mathbf{v}\rVert_\infty = \max_i |v_i|$: only the biggest entry counts.
  • Frobenius norm of a matrix, $\lVert A\rVert_F = \sqrt{\sum_{i,j} a_{ij}^2}$: the L2 norm of all its entries treated as one long list. It measures how far apart two matrices are, as in the SVD example below.
import numpy as np

v = np.array([3.0, -4.0, 1.0])
print("L1 norm (sum of sizes):    ", np.linalg.norm(v, 1))
print("L2 norm (straight line):   ", round(np.linalg.norm(v), 3))
print("L-infinity (biggest entry):", np.linalg.norm(v, np.inf))

M = np.array([[1.0, 2.0], [3.0, 4.0]])
print("Frobenius norm of M:       ", round(np.linalg.norm(M), 3))

Output:

L1 norm (sum of sizes):     8.0
L2 norm (straight line):    5.099
L-infinity (biggest entry): 4.0
Frobenius norm of M:        5.477

For $\mathbf{v} = (3, -4, 1)$: L1 is $3 + 4 + 1 = 8$, L2 is $\sqrt{9 + 16 + 1} = \sqrt{26} \approx 5.099$, and L∞ is $4$. Why it matters: ridge regression (Lesson 10) penalises the L2 norm of the weights and shrinks them all a little; lasso penalises the L1 norm and pushes some exactly to zero. The difference comes from the shapes of the "unit balls" $\lVert\mathbf{v}\rVert = 1$: a circle for L2, but a diamond with sharp corners on the axes for L1. kNN (Lesson 11) can use L1 or L2 distance too.

Independence, rank and the determinant

Columns of a matrix are linearly independent if none of them can be built from the others by adding and scaling. The rank is the number of independent columns. It matters because least squares needs $X^\top X$ to be invertible, and that happens only when the columns of $X$ are independent (full rank).

The determinant of a square matrix is the factor by which it scales areas (in 2D) or volumes (in 3D). If $\det A = 0$, the matrix squashes space flat, information is lost, and $A$ has no inverse.

# Three features, but the third is the sum of the first two
X = np.array([[1, 2, 3],
              [2, 0, 2],
              [0, 1, 1],
              [3, 1, 4]], dtype=float)
print("columns:", X.shape[1], " rank:", np.linalg.matrix_rank(X))
print("det(XᵀX):", round(np.linalg.det(X.T @ X), 6))

A = np.array([[2.0, 1.0], [1.0, 3.0]])
print("det(A):", round(np.linalg.det(A), 3), "-> A scales areas by this factor")

Output:

columns: 3  rank: 2
det(XᵀX): 0.0
det(A): 5.0 -> A scales areas by this factor

The third feature is exactly feature 1 + feature 2, so only 2 of the 3 columns carry new information: rank 2, and $\det(X^\top X) = 0$. This is the same problem as the dummy-variable trap in Lesson 6. For the 2×2 matrix $A$, $\det A = 2\cdot 3 - 1\cdot 1 = 5$: it stretches every shape to 5 times its area.

Eigenvalues and eigenvectors

Most vectors change direction when you multiply them by a matrix. An eigenvector is a special direction that the matrix only stretches or shrinks:

$$A\mathbf{v} = \lambda\mathbf{v}$$

The number $\lambda$ is its eigenvalue: how much that direction is stretched. To find the eigenvalues by hand, solve $\det(A - \lambda I) = 0$. For $A = \begin{pmatrix}2 & 1\\ 1 & 3\end{pmatrix}$:

$$\det\begin{pmatrix}2-\lambda & 1\\ 1 & 3-\lambda\end{pmatrix} = (2-\lambda)(3-\lambda) - 1 = \lambda^2 - 5\lambda + 5 = 0 \;\Rightarrow\; \lambda = \frac{5 \pm \sqrt{5}}{2} \approx 1.382,\ 3.618$$

For $\lambda = 3.618$, the first row of $(A - \lambda I)\mathbf{v} = 0$ gives $v_2 = 1.618\,v_1$; scaled to length 1, that's $\mathbf{v} \approx (0.526, 0.851)$.

vals, vecs = np.linalg.eigh(A)            # eigh: for symmetric matrices
print("eigenvalues:", vals.round(3))
print("eigenvectors (columns):")
print(vecs.round(3))
v1 = vecs[:, 1]
print("A @ v:     ", (A @ v1).round(3))
print("lambda * v:", (vals[1] * v1).round(3))
print("dot product of the two eigenvectors:", abs(round(vecs[:, 0] @ vecs[:, 1], 10)))

Output:

eigenvalues: [1.382 3.618]
eigenvectors (columns):
[[-0.851  0.526]
 [ 0.526  0.851]]
A @ v:      [1.902 3.078]
lambda * v: [1.902 3.078]
dot product of the two eigenvectors: 0.0

The check $A\mathbf{v} = \lambda\mathbf{v}$ works, and the two eigenvectors have dot product 0: they're at right angles. That's not luck. The spectral theorem says every symmetric matrix ($A = A^\top$) has real eigenvalues and a full set of perpendicular eigenvectors, so it can be written as $A = Q\Lambda Q^\top$ (rotate, stretch along the axes, rotate back). Covariance matrices are symmetric, which is exactly why PCA (Lesson 17) works: its components are the covariance matrix's eigenvectors, and each eigenvalue is the variance along that direction. Use np.linalg.eigh for symmetric matrices; it's faster and more accurate than the general eig.

Positive definite matrices

A symmetric matrix is positive definite if $\mathbf{x}^\top A\mathbf{x} > 0$ for every non-zero $\mathbf{x}$, which is the same as all its eigenvalues being positive. It's positive semi-definite (PSD) if $\ge 0$ is allowed. The matrix $A$ above is positive definite: both eigenvalues are positive.

The matrix that appears all over ML, $X^\top X$, is always PSD, and the proof is one line:

$$\mathbf{w}^\top (X^\top X)\,\mathbf{w} = (X\mathbf{w})^\top(X\mathbf{w}) = \lVert X\mathbf{w}\rVert^2 \ge 0$$

It's positive definite exactly when the columns of $X$ are independent. Lesson 3's "Going deeper" uses this to show that the squared-error loss is convex: shaped like a bowl, with one lowest point.

The singular value decomposition (SVD)

Eigenvectors need a square matrix. The SVD works for any matrix, including a data table with $n$ rows and $d$ columns:

$$A = U\,\Sigma\,V^\top$$

$U$ and $V$ have perpendicular columns (directions in row space and column space), and $\Sigma$ is diagonal with the singular values $\sigma_1 \ge \sigma_2 \ge \dots \ge 0$, which say how important each direction is. The key result (the Eckart–Young theorem) is that keeping only the $k$ largest singular values gives the best possible rank-$k$ approximation of $A$.

Here's why that's useful. Below is a table of 50 users' ratings of 40 films. It was secretly built from just 3 hidden "tastes" (say, action, comedy and drama) plus noise:

# A ratings table: 50 users × 40 films, built from 3 hidden "tastes" plus noise
rng = np.random.default_rng(0)
R = rng.normal(size=(50, 3)) @ rng.normal(size=(3, 40)) + rng.normal(0, 0.3, size=(50, 40))
U, s, Vt = np.linalg.svd(R, full_matrices=False)
print("largest singular values:", s[:6].round(1))
for k in [1, 2, 3, 5, 10]:
    approx = U[:, :k] @ np.diag(s[:k]) @ Vt[:k]          # keep only the k largest
    err = np.linalg.norm(R - approx) / np.linalg.norm(R)
    print(f"rank {k:2d}: stores {k * (50 + 40 + 1):4d} of 2000 numbers, relative error {err:.3f}")

Output:

largest singular values: [54.9 40.6 38.5  3.9  3.6  3.4]
rank  1: stores   91 of 2000 numbers, relative error 0.722
rank  2: stores  182 of 2000 numbers, relative error 0.510
rank  3: stores  273 of 2000 numbers, relative error 0.157
rank  5: stores  455 of 2000 numbers, relative error 0.142
rank 10: stores  910 of 2000 numbers, relative error 0.110

The singular values drop sharply after the third (38.5, then 3.9): the SVD has discovered that 3 hidden factors explain the table. A rank-3 approximation stores 273 numbers instead of 2,000, with a relative error of 0.157, and most of that error is the random noise. Keeping more singular values hardly helps (0.142 at rank 5), because they only describe noise. This is the idea behind recommender systems (predicting missing ratings), PCA (Lesson 17, which is the SVD of the centred data), image compression and the pseudo-inverse $A^{+} = V\Sigma^{+}U^\top$ that np.linalg.lstsq uses to solve least squares safely.

Condition number: when tiny changes cause big swings

The condition number of a matrix is the ratio of its largest to its smallest singular value (for a symmetric PSD matrix like $X^\top X$, its largest to smallest eigenvalue). It measures how much small errors in the input can be amplified in the answer. A value near 1 is perfect; values in the thousands or millions mean trouble. In this example, two features measure almost the same thing: a home's size, recorded twice with slightly different tape measures.

rng = np.random.default_rng(2)
n = 100
size = rng.uniform(50, 150, n)
size2 = size + rng.normal(0, 0.5, n)                 # a second, almost identical measurement
Xc = np.column_stack([size, size2]); Xc = Xc - Xc.mean(axis=0)
y = 0.6 * Xc[:, 0] + rng.normal(0, 5, n)
y_nudged = y + rng.normal(0, 1, n)                   # a small change in the targets

G = Xc.T @ Xc
print("condition number of XᵀX:", round(np.linalg.cond(G)))
print("weights:            ", np.linalg.solve(G, Xc.T @ y).round(2))
print("after a tiny change:", np.linalg.solve(G, Xc.T @ y_nudged).round(2))
Gr = G + 100 * np.eye(2)                             # ridge: add λI with λ = 100
print("condition number with ridge:", round(np.linalg.cond(Gr)))
print("ridge weights:      ", np.linalg.solve(Gr, Xc.T @ y).round(2))
print("after a tiny change:", np.linalg.solve(Gr, Xc.T @ y_nudged).round(2))

Output:

condition number of XᵀX: 14469
weights:             [ 0.96 -0.36]
after a tiny change: [ 1.2  -0.61]
condition number with ridge: 1462
ridge weights:       [0.37 0.23]
after a tiny change: [0.39 0.21]

With a condition number of about 14,000, a tiny change in $y$ swings the weights from $(0.96, -0.36)$ to $(1.2, -0.61)$. Their sum stays near 0.6, so the predictions barely change, but the individual weights mean nothing. This is the linear-algebra view of multicollinearity (Lesson 6's "Going deeper"). Adding $\lambda I$, which is exactly what ridge regression does, raises every eigenvalue by $\lambda$. That cuts the condition number about tenfold, to 1,462, and the weights become stable ($0.37, 0.23$ and then $0.39, 0.21$).

Matrix calculus: the four rules you'll actually use

Many ML derivations need the gradient of an expression with vectors and matrices in it. These rules cover almost all of them ($\mathbf{a}$ is a constant vector and $A$ a constant matrix):

Function of $\mathbf{w}$Gradient $\nabla_{\mathbf{w}}$Like the 1-D rule
$\mathbf{a}^\top\mathbf{w}$$\mathbf{a}$$\frac{d}{dw}(aw) = a$
$\mathbf{w}^\top\mathbf{w} = \lVert\mathbf{w}\rVert^2$$2\mathbf{w}$$\frac{d}{dw}w^2 = 2w$
$\mathbf{w}^\top A\,\mathbf{w}$$(A + A^\top)\,\mathbf{w}$, which is $2A\mathbf{w}$ if $A$ is symmetric$\frac{d}{dw}aw^2 = 2aw$
$\lVert X\mathbf{w} - \mathbf{y}\rVert^2$$2X^\top(X\mathbf{w} - \mathbf{y})$chain rule

The last rule gives the normal equation from Lesson 6 in one line: set $2X^\top(X\mathbf{w} - \mathbf{y}) = \mathbf{0}$, so $X^\top X\,\mathbf{w} = X^\top\mathbf{y}$. Always check a hand-derived gradient numerically, by nudging each weight a tiny amount (Lesson 3 shows how):

# Check the matrix-calculus rule  ∇_w ||Xw − y||² = 2 Xᵀ(Xw − y)  with finite differences
rng = np.random.default_rng(3)
Xg = rng.normal(size=(5, 3)); yg = rng.normal(size=5); w = rng.normal(size=3)
f = lambda w: np.sum((Xg @ w - yg) ** 2)
formula = 2 * Xg.T @ (Xg @ w - yg)
h = 1e-6
numeric = np.array([(f(w + h * e) - f(w - h * e)) / (2 * h) for e in np.eye(3)])
print("formula:", formula.round(4))
print("numeric:", numeric.round(4))

Output:

formula: [-13.3106  19.8282   2.4238]
numeric: [-13.3106  19.8282   2.4238]

The formula and the numerical estimate agree to 4 decimal places, so the rule is right. Deep-learning libraries compute such gradients automatically, but knowing these rules lets you read papers and debug models.

Interview corner · intermediate

Hidden questions — answer in your head first, then open.

Why does L1 regularization produce exactly-zero weights, while L2 only shrinks them?

The trap: "Because L1 is stronger."

It's about shape, not strength. The L1 ball $|w_1| + |w_2| \le t$ is a diamond with corners on the axes. When the loss's contours first touch it, they usually touch at a corner, where some weights are exactly 0. The L2 ball is round, so the touching point is almost never on an axis. Equivalently, the L1 penalty's slope stays the same size right up to zero, so it keeps pushing until a weight reaches 0. The L2 penalty's slope $2\lambda w$ fades as $w$ shrinks.

What is an eigenvector, and where do eigenvectors appear in ML?

The trap: Giving only the equation, with no meaning.

A direction that a matrix only stretches, $A\mathbf{v} = \lambda\mathbf{v}$. In ML: PCA's components are the eigenvectors of the covariance matrix, with eigenvalues equal to the variance in each direction. The eigenvalues of the Hessian describe a loss surface's curvature (and so how fast gradient descent converges). Spectral clustering and Google's PageRank are also eigenvector methods.

What's the relationship between PCA and the SVD?

The trap: Treating them as unrelated algorithms.

Centre the data matrix $X$ and take its SVD, $X = U\Sigma V^\top$. The columns of $V$ are the principal components (the eigenvectors of $X^\top X$), and $\sigma_i^2/(n-1)$ is the variance along each one. Libraries compute PCA through the SVD because it's more accurate than forming $X^\top X$, which squares the condition number.

Your linear regression's weights change wildly when you add a few rows of data. What's going on, and how do you fix it?

The trap: Blaming the optimiser or the random seed.

Probably ill-conditioning: some features are nearly linear combinations of others, so $X^\top X$ has a tiny eigenvalue and a huge condition number. Small data changes then cause big swings along that weak direction. Check the VIFs or the condition number. Fix it by removing or combining redundant features, using PCA, or adding ridge regularization, which adds $\lambda$ to every eigenvalue.

Why is $X^\top X$ never negative definite, and when is it invertible?

The trap: "It's always invertible because it's square."

$\mathbf{w}^\top X^\top X\mathbf{w} = \lVert X\mathbf{w}\rVert^2 \ge 0$, so it is always positive semi-definite. It is invertible (positive definite) exactly when the columns of $X$ are linearly independent, which requires at least as many rows as columns. With more features than examples ($d > n$) it is always singular.

Check your understanding: going deeper

1. What is the L1 norm of $(2, -3, 1)$?

L1 adds the sizes of the entries: $2 + 3 + 1 = 6$. ($\sqrt{14}$ is the L2 norm and 3 is the L∞ norm.)

2. A data matrix has 5 columns but rank 4. What does that tell you?

Rank counts independent columns. With one redundant column, ordinary least squares has no unique answer.

3. $A\mathbf{v} = 3\mathbf{v}$. What does the matrix $A$ do to the direction of $\mathbf{v}$?

That's the definition of an eigenvector with eigenvalue 3: same direction, three times as long.

4. The singular values of a data table are 90, 60, 2, 1 and 0.5. A good low-rank summary keeps about…

The values drop sharply after the second. The remaining ones are tiny and mostly describe noise.

5. Ridge regression adds $\lambda I$ to $X^\top X$. What does that do to its eigenvalues?

$(X^\top X + \lambda I)\mathbf{v} = (\mu + \lambda)\mathbf{v}$ for each eigenvector. The smallest eigenvalue rises, so the condition number falls.
