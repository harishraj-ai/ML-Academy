Understanding

Which model should I use?

A few questions about your data and goal lead to the algorithms worth trying first.

How to use this

Answer a few questions about your problem and you'll get a short list of algorithms to try, in order, with the lessons that explain them. It is a starting point, not a rule: in practice you try two or three candidates and let cross-validation decide.

Every recommendation at a glance

The same advice as the questions above, as one list you can scan or print.

Collect more data first

When: Predict a number → A row in a table → Fewer than 50 or Predict a category → A row in a table → Fewer than 50

  • A simple baseline (mean / most common class) — With under 50 examples, no algorithm can learn reliably — and you can't even measure it reliably. (Lesson 5)
  • Then the simplest model: linear or logistic regression — Few parameters means less overfitting. (Lesson 6)

Watch out: Use leave-one-out cross-validation to evaluate; treat any result as a rough estimate.

Logistic regression or a small decision tree

When: Predict a category → A row in a table → 50 to 100,000 → Yes, it must be explainable

  • Logistic regression — Each weight shows how a feature pushes the odds up or down. (Lesson 8)
  • Decision tree (limited depth) — Gives readable if-then rules. (Lesson 13)
  • Then: random forest + feature importances — If you need more accuracy, check whether it's worth losing some explainability. (Lesson 14)

Watch out: Check precision and recall, not just accuracy — especially if one class is rare.

Start simple, then try tree ensembles

When: Predict a category → A row in a table → 50 to 100,000 → No, accuracy matters most

  • Baseline: logistic regression — Fast, and tells you how much a fancier model really adds. (Lesson 8)
  • Random forest — Strong with almost no tuning. (Lesson 14)
  • Gradient boosting — Usually the most accurate on tables, with tuning. (Lesson 14)
  • Also worth a try: SVM (RBF kernel) or kNN — Good on small-to-medium data once features are scaled (kNN: Lesson 11). (Lesson 15)

Watch out: Compare all candidates with the same cross-validation folds and metric (Lessons 5 and 9).

Models that scale to big data

When: Predict a category → A row in a table → More than 100,000

  • Logistic regression with SGD — Learns from mini-batches, so data size isn't a problem. (Lesson 7)
  • Gradient boosting (LightGBM / XGBoost) — Fast, scalable libraries; often the top choice for big tables. (Lesson 14)
  • Neural network — Worth it when there are many complex feature interactions. (Lesson 18)

Watch out: With lots of data, a simple hold-out validation set is usually enough.

Naive Bayes or logistic regression on word counts

When: Predict a category → Text → Up to a few thousand documents

  • Naive Bayes — Classic fast baseline for text; works with little data. (Lesson 12)
  • Logistic regression on TF-IDF features (word counts, down-weighted for very common words) — Usually a bit more accurate once you have more examples. (Lesson 8)

Watch out: Fit the vocabulary (CountVectorizer) inside a pipeline so test text never leaks into training (Lesson 20).

Fine-tune a pretrained Transformer

When: Predict a category → Text → Lots, or the meaning is subtle

  • Pretrained language model (Transformer) — Already understands language; you only adapt it to your labels. (Lesson 19)
  • Keep a word-count + logistic regression baseline — Shows how much the big model actually adds. (Lesson 8)

Watch out: Training a Transformer from scratch needs enormous data — fine-tune instead.

Deep learning — usually starting from a pretrained network

When: Predict a number → Images, audio or text or Predict a category → Images, audio or video

  • Images: convolutional network (CNN) — Learns edges, textures and shapes from pixels. (Lesson 19)
  • Text or sequences: Transformer — Handles word order and long-range context. (Lesson 19)
  • Fine-tuning a pretrained model — Needs far less data and compute than training from scratch. (Lesson 19)

Watch out: Deep learning needs a GPU and plenty of data; check whether a pretrained model already solves your task.

Lasso (or elastic net)

When: Predict a number → A row in a table → 50 to 100,000 → Yes, only a few

  • Lasso regression — Sets the weights of unhelpful features to exactly zero. (Lesson 10)
  • Elastic net — Mixes lasso and ridge; more stable when features are correlated. (Lesson 10)

Watch out: Standardise features first, and choose the penalty strength by cross-validation.

Ridge regression, then tree ensembles

When: Predict a number → A row in a table → 50 to 100,000 → No, or not sure

  • Baseline: linear / ridge regression — Fast, explainable, and hard to beat when relationships are roughly linear. (Lesson 10)
  • Random forest regressor — Captures non-linear effects and interactions automatically. (Lesson 14)
  • Gradient boosting regressor — Often the most accurate on tables. (Lesson 14)
  • Also worth a try: SVR (RBF kernel) or kNN regression — Good on small data once features are scaled (kNN: Lesson 11). (Lesson 15)

Watch out: Report MAE or RMSE in the target's own units so the error is easy to interpret.

Models that scale to big data

When: Predict a number → A row in a table → More than 100,000

  • Linear regression with SGD — Learns in mini-batches. (Lesson 7)
  • Gradient boosting (LightGBM / XGBoost) — Scales well and handles non-linear patterns. (Lesson 14)
  • Neural network — For very large, complex problems. (Lesson 18)

Watch out: Scale numeric features for SGD and neural networks (Lesson 20).

k-means

When: Find groups in data without labels → Yes → Yes, or I can't tell

  • k-means (with k-means++ starts) — Fast and simple; finds round clusters around centres. (Lesson 16)
  • MiniBatchKMeans for millions of points — scikit-learn's version that updates the centroids from small random batches — much faster, nearly as good. (Lesson 16)

Watch out: Scale features first, try several values of k, and check them with the elbow method or silhouette score.

k-means over a range of k

When: Find groups in data without labels → No → No / not sure — and the dataset is large

  • k-means for k = 2 … 10 — Pick k with the elbow method or the silhouette score. (Lesson 16)
  • Then inspect the clusters — Do they make sense to someone who knows the data? (Lesson 16)

Watch out: There's no 'correct' answer in clustering — judge clusters by whether they're useful.

DBSCAN

When: Find groups in data without labels → Yes → No — odd shapes, or very different sizes or Find groups in data without labels → No → Yes

  • DBSCAN — Follows dense regions of any shape and labels sparse points as noise. (Lesson 16)
  • Tune eps by trying a few values — Too small and most points become noise; too large and clusters merge. scikit-learn's default min_samples = 5 is a fair start. (Lesson 16)

Watch out: DBSCAN struggles when clusters have very different densities.

Hierarchical clustering

When: Find groups in data without labels → No → No / not sure — and the dataset is small (< 10,000)

  • Agglomerative clustering + dendrogram — Shows every level of grouping; cut the tree where the gaps are largest. (Lesson 16)
  • Compare with k-means at the k you pick — A second opinion on the same data. (Lesson 16)

Watch out: Memory grows with the square of the number of points — fine for thousands, not millions.

PCA

When: Simplify or visualise many features → To feed a model: fewer, uncorrelated features

  • PCA (keep ~95% of the variance) — Fast, linear, and the same transform works on new data. (Lesson 17)
  • Or: lasso / feature selection — If you'd rather keep original, explainable features. (Lesson 10)

Watch out: Standardise first, and fit PCA only on the training data (inside a pipeline).

PCA first, then t-SNE or UMAP

When: Simplify or visualise many features → To draw a 2D picture and look for structure

  • PCA to ~50 dimensions — Removes noise and speeds up the next step. (Lesson 17)
  • t-SNE (or UMAP) to 2D — Places similar points close together, so clusters become visible. (Lesson 17)

Watch out: Distances between t-SNE clusters and their sizes mean little; use it for looking, not as model input.
