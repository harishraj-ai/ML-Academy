1.Why think in probabilities about the model itself?

Most models you've built give one answer: one set of weights, one predicted price. But with 10 data points the weights are very uncertain, and with 10 million they're not, and a single number hides that difference. Bayesian machine learning treats everything unknown, including the model's parameters, as uncertain, describes that uncertainty with probability distributions, and updates them as data arrives.

That gives you things ordinary models don't: honest error bars on predictions, sensible behaviour with little data, a principled way to include prior knowledge, and decisions that weigh risks ("the chance that B is worse, and how much we'd lose"). This lesson builds the core tools from scratch: conjugate updating for A/B tests, Bayesian linear regression, Gaussian processes, MCMC sampling, and Thompson sampling for learning while deciding.

The core idea

Start with a prior (what's plausible before the data), multiply by the likelihood (how well each possibility explains the data), and you get the posterior: an updated belief about every possibility. Predictions and decisions then average over the whole posterior instead of trusting a single best guess.

2.Bayes' theorem for parameters

Lesson 4 used Bayes' theorem for events. For a model's parameters $\theta$ and data $D$ it reads:

$$p(\theta \mid D) = \frac{p(D \mid \theta)\,p(\theta)}{p(D)} \;\propto\; \text{likelihood} \times \text{prior}$$

Lesson 4's "Going deeper" showed three useful facts: maximising the likelihood alone gives the MLE; maximising the posterior gives the MAP estimate, which equals ridge or lasso for normal or Laplace priors; and with a conjugate prior, such as a Beta prior for a probability, the posterior has a simple closed form. This lesson uses the whole posterior, not just its peak.

3.A Bayesian A/B test

Lesson 4's "Going deeper" ran a classical test on a checkout page: A converted 120 of 2,400 visitors and B 156 of 2,400, with $p = 0.026$. The Bayesian version gives each page's conversion rate a Beta(1, 1) prior (every rate equally plausible) and updates it with the data. Then it simply asks the questions a manager cares about, by drawing many samples from the two posteriors:

import numpy as np
from scipy import stats

# A/B test the Bayesian way: Beta(1, 1) priors, then the observed conversions
a_conv, a_n, b_conv, b_n = 120, 2400, 156, 2400
post_a = stats.beta(1 + a_conv, 1 + a_n - a_conv)
post_b = stats.beta(1 + b_conv, 1 + b_n - b_conv)
rng = np.random.default_rng(0)
da, db = post_a.rvs(200000, random_state=rng), post_b.rvs(200000, random_state=rng)
print("95% credible interval, A:", np.round(post_a.ppf([0.025, 0.975]), 4))
print("95% credible interval, B:", np.round(post_b.ppf([0.025, 0.975]), 4))
print("probability that B converts better than A:", round(np.mean(db > da), 4))
print("expected lift if we switch to B:", round(np.mean(db - da), 4), "  risk (expected loss if B is actually worse):", round(np.mean(np.maximum(da - db, 0)), 5))

Output:

95% credible interval, A: [0.042  0.0595]
95% credible interval, B: [0.0558 0.0756]
probability that B converts better than A: 0.9869
expected lift if we switch to B: 0.015   risk (expected loss if B is actually worse): 3e-05
Worked example — the posterior by hand

A Beta($a$, $b$) prior plus $s$ successes and $f$ failures gives a Beta($a + s$, $b + f$) posterior. For page B: Beta($1 + 156$, $1 + 2{,}244$) = Beta(157, 2,245).

Its mean is $\frac{157}{157 + 2245} = \frac{157}{2402} \approx 0.0654$: very close to the observed $156/2400 = 0.065$, because 2,400 visitors overwhelm a weak prior.

Its standard deviation is $\sqrt{\frac{ab}{(a+b)^2(a+b+1)}} = \sqrt{\frac{157 \times 2245}{2402^2 \times 2403}} \approx 0.0050$, so the rate is about $6.5\% \pm 1.0\%$ (two standard deviations), matching the credible interval above.

There's a 98.7% probability that B really converts better, the expected gain from switching is 1.5 percentage points, and the expected loss if B is actually worse is tiny (0.003 percentage points). These are direct answers about the thing you care about, unlike a p-value (Lesson 4's "Going deeper"). The price is that you must choose a prior; with plenty of data, reasonable priors give almost the same answer.

5.Bayesian linear regression

Give the weights of a linear regression a normal prior, $\mathbf{w} \sim \mathcal{N}(0, \tau^2 I)$, and assume normal noise with variance $\sigma^2$. The posterior is again normal, with

$$\Sigma_{\text{post}} = \Big(\tfrac{1}{\sigma^2}X^\top X + \tfrac{1}{\tau^2}I\Big)^{-1}, \qquad \mathbf{m}_{\text{post}} = \tfrac{1}{\sigma^2}\,\Sigma_{\text{post}}X^\top\mathbf{y}$$

The posterior mean is exactly ridge regression with $\lambda = \sigma^2/\tau^2$ (Lesson 10). What's new is the covariance $\Sigma_{\text{post}}$: it says how uncertain each weight is, and it gives each prediction its own error bar, $\boldsymbol\phi^\top\Sigma_{\text{post}}\boldsymbol\phi + \sigma^2$, combining uncertainty about the line with the noise.

# Bayesian linear regression: a normal prior on the weights gives a full posterior, not just one line
x = np.array([0.5, 1.0, 1.5, 3.0, 3.5])
y = np.array([1.1, 1.9, 3.2, 5.8, 7.1])
X = np.column_stack([np.ones_like(x), x])
sigma2, tau2 = 0.25, 10.0                                   # noise variance and prior variance of each weight
S_post = np.linalg.inv(X.T @ X / sigma2 + np.eye(2) / tau2)  # posterior covariance
m_post = S_post @ X.T @ y / sigma2                          # posterior mean (= ridge with lambda = sigma2/tau2)
print("posterior mean (intercept, slope):", m_post.round(3))
print("posterior std  (intercept, slope):", np.sqrt(np.diag(S_post)).round(3))
for x_new in [2.0, 6.0]:
    phi = np.array([1, x_new])
    mean, var = phi @ m_post, phi @ S_post @ phi + sigma2
    print(f"x {x_new}: predicted y {mean:.2f}, 95% prediction interval [{mean - 1.96 * np.sqrt(var):.2f}, {mean + 1.96 * np.sqrt(var):.2f}]")

Output:

posterior mean (intercept, slope): [0.086 1.965]
posterior std  (intercept, slope): [0.425 0.192]
x 2.0: predicted y 4.02, 95% prediction interval [2.94, 5.09]
x 6.0: predicted y 11.88, 95% prediction interval [10.00, 13.75]

With five points, the slope is about $1.97 \pm 0.19$. The prediction interval at $x = 2$, inside the data, is about 2.1 units wide; at $x = 6$, beyond the data, it's about 3.8 units wide. The model knows it is extrapolating, which ordinary least squares can't tell you.

6.Gaussian processes

A Gaussian process (GP) goes further: instead of a distribution over a few weights, it puts a prior directly over functions, controlled by a kernel that says how similar nearby outputs are (the RBF kernel from Lesson 15). After seeing data, it predicts a mean and a standard deviation at every point. Lesson 23's "Going deeper" used one to drive Bayesian optimisation.

from sklearn.gaussian_process import GaussianProcessRegressor
from sklearn.gaussian_process.kernels import RBF, WhiteKernel

# A Gaussian process: uncertainty grows away from the data
xs = np.array([1, 2, 3, 6, 7, 8.0])[:, None]
ys = np.sin(xs[:, 0]) + np.random.default_rng(2).normal(0, 0.1, 6)
gp = GaussianProcessRegressor(RBF(1.0) + WhiteKernel(0.01), random_state=0).fit(xs, ys)
for q in [2.0, 4.5, 11.0]:
    m, s = gp.predict([[q]], return_std=True)
    print(f"x {q:4}: mean {m[0]:+.2f}, std {s[0]:.2f}")

Output:

x  2.0: mean +0.86, std 0.00
x  4.5: mean -1.19, std 0.45
x 11.0: mean -0.01, std 0.99

At $x = 2$, where there's data, the GP is confident (standard deviation about 0). At $x = 4.5$, in the gap between the two groups of points, its uncertainty rises to 0.45. At $x = 11$, far beyond all data, it falls back towards the prior: mean near 0 and standard deviation about 1. GPs are excellent for small, smooth problems (calibration curves, sensor data, experiment design) and give honest uncertainty, but exact GPs cost $O(n^3)$, so they're limited to a few thousand points without approximations.

7.When there's no formula: MCMC

Most posteriors have no neat closed form. Markov chain Monte Carlo (MCMC) draws samples from them anyway. The simplest version, the Metropolis algorithm: propose a small random move; if the posterior is higher there, accept it; if lower, accept it with probability equal to the ratio. The chain then visits each region in proportion to its posterior probability, and only ratios are needed, so the awkward normalising constant $p(D)$ cancels.

Here we estimate the centre of seven measurements, one of which (8.5) looks like a mistake. A Cauchy likelihood, which has heavy tails, makes the model robust to it:

# MCMC from scratch: sample a posterior that has no neat formula with the Metropolis algorithm
data = np.array([2.1, 2.9, 3.4, 2.2, 8.5, 3.0, 2.7])        # one suspicious value (8.5)
def log_post(mu):                                          # Cauchy likelihood (robust to outliers) and normal prior
    return np.sum(stats.cauchy.logpdf(data, loc=mu, scale=0.5)) + stats.norm.logpdf(mu, 0, 10)
rng = np.random.default_rng(3)
mu, chain, accepted = 0.0, [], 0
for step in range(20000):
    prop = mu + rng.normal(0, 0.5)                         # propose a small random move
    if np.log(rng.random()) < log_post(prop) - log_post(mu):
        mu, accepted = prop, accepted + 1                  # accept with probability min(1, ratio)
    chain.append(mu)
chain = np.array(chain[2000:])                             # drop the warm-up
print("acceptance rate:", round(accepted / 20000, 2))
print("posterior mean of the centre:", round(chain.mean(), 2), "  95% interval:", np.round(np.percentile(chain, [2.5, 97.5]), 2))
print("ordinary mean of the data, for comparison:", round(data.mean(), 2))

Output:

acceptance rate: 0.52
posterior mean of the centre: 2.76   95% interval: [2.2  3.28]
ordinary mean of the data, for comparison: 3.54

About half of the proposals were accepted, a healthy rate. The posterior mean of the centre is 2.76 with a 95% interval of 2.2 to 3.28, while the ordinary mean (3.54) is dragged up by the outlier. Modern tools (Stan, PyMC, NumPyro) use far more efficient samplers such as Hamiltonian Monte Carlo and NUTS, but the idea is the same: write down the prior and likelihood, and let the sampler produce the posterior.

8.Deciding under uncertainty: Thompson sampling

A classical A/B test splits traffic evenly until it ends, so half the visitors keep seeing the worse page. A multi-armed bandit learns and earns at the same time. Thompson sampling is the Bayesian way: for each visitor, draw one plausible conversion rate for each design from its current posterior, show the design whose draw is highest, and update that design's posterior with the result. Uncertain designs sometimes win the draw (exploration); clearly good ones win most of the time (exploitation).

# Thompson sampling: a bandit that learns which of 3 page designs converts best while it runs
true_rates = np.array([0.04, 0.05, 0.065])
wins, losses = np.ones(3), np.ones(3)                      # Beta(1, 1) prior for each design
rng = np.random.default_rng(4)
shown = np.zeros(3, int)
for visitor in range(10000):
    choice = np.argmax(rng.beta(wins, losses))             # sample a plausible rate for each, show the best
    shown[choice] += 1
    if rng.random() < true_rates[choice]: wins[choice] += 1
    else: losses[choice] += 1
print("visitors shown each design:", shown.tolist())
print("conversions:", int(wins.sum() - 3), "  versus a fixed even split (expected):", round(10000 * true_rates.mean()))

Output:

visitors shown each design: [354, 458, 9188]
conversions: 652   versus a fixed even split (expected): 517

With true rates of 4%, 5% and 6.5%, Thompson sampling quickly shifted traffic: 9,188 of the 10,000 visitors saw the best design. It earned 652 conversions, against about 517 for an even three-way split. Bandits are used for headlines, recommendations (Lesson 27's feedback loops) and ad selection. The trade-off is that the weaker designs get too little traffic for a precise comparison, so use a classical or Bayesian A/B test when you need an exact measurement, and a bandit when you need results now.

9.In Python: Bayesian ridge with uncertainty

Scikit-learn's BayesianRidge learns the noise and prior variances from the data and returns a standard deviation with every prediction:

import numpy as np
import pandas as pd
from sklearn.linear_model import BayesianRidge

df = pd.read_csv("houses.csv")   # download it from Lesson 1
X, y = df[["size_m2", "dist_km", "age_yrs"]], df["price_lakh"]
model = BayesianRidge().fit(X, y)
new = pd.DataFrame({"size_m2": [100, 200], "dist_km": [8, 30], "age_yrs": [5, 1]})
mean, std = model.predict(new, return_std=True)
for (_, h), m, s in zip(new.iterrows(), mean, std):
    print(f"{h.size_m2:.0f} m², {h.dist_km:.0f} km, {h.age_yrs:.0f} yrs: {m:.0f} lakh ± {1.96 * s:.0f} (95%)")

Output:

100 m², 8 km, 5 yrs: 79 lakh ± 12 (95%)
200 m², 30 km, 1 yrs: 111 lakh ± 20 (95%)

For a typical home (100 m², 8 km, 5 years), the model gives a prediction with a modest interval; for an unusual one (200 m², 30 km away), outside the range of the 12 training homes, the interval is much wider. Communicating that kind of uncertainty is often worth more than a slightly more accurate point prediction.

10.Running example: Chennai Homes

How sure can we be about which areas sell fast, with only 12 homes? Give each area's "sold fast" rate a Beta(1, 1) prior and update it with the area's homes. Central sold 3 of 4 fast (posterior mean 0.67) and the Suburb 3 of 5 (0.57), but their 90% credible intervals, about 0.34 to 0.92 and 0.27 to 0.85, overlap heavily. The Outskirts sold none of 3, yet the posterior still allows rates up to about 0.53. With this little data, the intervals are the honest answer.

Same 12 houses as Lesson 1. With so little data, treat the numbers as an illustration of the method, not as reliable estimates.

import pandas as pd
import numpy as np
df = pd.read_csv("houses.csv")   # download it from Lesson 1
from scipy import stats
for area, g in df.groupby("area"):
    a, b = 1 + g.sold_fast.sum(), 1 + (1 - g.sold_fast).sum()     # Beta(1, 1) prior
    lo, hi = stats.beta(a, b).ppf([0.05, 0.95])
    print(f"{area:9s} sold fast {g.sold_fast.sum()} of {len(g)}  posterior mean {a / (a + b):.2f}  90% interval [{lo:.2f}, {hi:.2f}]")

Output:

Central   sold fast 3 of 4  posterior mean 0.67  90% interval [0.34, 0.92]
Outskirts sold fast 0 of 3  posterior mean 0.20  90% interval [0.01, 0.53]
Suburb    sold fast 3 of 5  posterior mean 0.57  90% interval [0.27, 0.85]
Where this is used
  • A/B tests that report the probability one version is better
  • Small-data science and engineering models that need honest error bars
  • Bandits for headlines and offers, and Bayesian optimisation of expensive experiments

Choose it when: Whenever uncertainty matters to the decision, data is limited, or you have real prior knowledge to include.

Think twice when: you have huge data and only need point predictions: then the posterior is narrow and ordinary models are simpler and faster.

Misconceptions to unlearn

MythBayesian methods need lots of computation.

RealityConjugate models such as the Beta A/B test are one line of arithmetic; MCMC is only needed when there's no formula.

MythThe prior lets you get any answer you want.

RealityWith enough data, reasonable priors converge; a prior that changes the conclusion is a sign the data is weak, which is worth knowing.

MythA credible interval and a confidence interval are the same thing.

RealityOnly a credible interval is a direct probability statement about the parameter.

Responsible AI · Priors and uncertainty in high-stakes decisions

A prior encodes assumptions, and in decisions about people (credit, health, policing) a prior built from biased history carries that bias into every new case. State priors openly and test how much they move conclusions. Equally, uncertainty is a responsibility: when an interval is wide, say so, and route the decision to a person rather than presenting a guess as a fact.

11.Questions beginners often ask

Isn't choosing a prior subjective?

Somewhat, but it's explicit and can be checked: try a few reasonable priors and see whether the conclusion changes. With plenty of data the likelihood dominates and they agree.

What's the difference between a credible interval and a confidence interval?

A 95% credible interval contains the parameter with 95% probability given the data and prior. A 95% confidence interval comes from a procedure that covers the true value in 95% of repeated samples; it isn't a probability statement about this interval.

Which tools do people use for Bayesian modelling?

PyMC, Stan and NumPyro for general models with MCMC or variational inference; scikit-learn's BayesianRidge and GaussianProcessRegressor for the common simple cases.

Can neural networks be Bayesian?

Approximately: ensembles of networks, Monte Carlo dropout and variational methods give useful uncertainty estimates, though exact Bayesian deep learning is too expensive.

Common mistakes to avoid
  • Using a strong prior without checking how much it changes the result.
  • Reporting only the posterior mean and throwing away the uncertainty.
  • Running MCMC without checking the acceptance rate or whether the chain has settled.
  • Using a bandit when you need an unbiased, precise comparison of every option.
  • Using an exact Gaussian process on hundreds of thousands of points.

Hidden questions — answer in your head first, then open.

What's the difference between a credible interval and a confidence interval?

The trap: Saying they're the same.

A 95% credible interval contains the parameter with 95% probability given the data and the prior. A 95% confidence interval comes from a procedure that covers the true value in 95% of repeated samples; this particular interval either contains it or doesn't.

How would you run a Bayesian A/B test on conversion rates?

The trap: Only computing a p-value.

Give each version's rate a Beta prior, update it to Beta(a + conversions, b + non-conversions), and draw samples from both posteriors to estimate P(B > A), the expected lift and the expected loss of choosing B. Decide when the expected loss falls below a threshold, and check that reasonable priors give the same decision.

Why is ridge regression a Bayesian method in disguise?

The trap: Saying it isn't related.

With Gaussian noise of variance σ² and a Gaussian prior N(0, τ²) on the weights, the posterior mean (and MAP) of the weights is the ridge solution with λ = σ²/τ². A Laplace prior gives lasso at the MAP. The full Bayesian treatment also gives the posterior covariance, and so uncertainty for each prediction.

What's Thompson sampling, and when would you use it instead of an A/B test?

The trap: Calling it random allocation.

For each decision, sample a plausible value of each option's reward from its posterior and choose the best sample; update the chosen option's posterior with the result. It shifts traffic to better options while still exploring uncertain ones. Use it when you want to earn while learning (headlines, offers); use an A/B test when you need an unbiased, precise estimate of each option.

12.Key takeaways

  • Bayesian ML treats unknown parameters as uncertain: posterior ∝ likelihood × prior.
  • With conjugate priors (Beta for rates) the posterior is a simple update; a Bayesian A/B test reports $P(B > A)$ and expected loss directly.
  • Bayesian linear regression's mean is ridge; its covariance gives error bars that widen away from the data.
  • Gaussian processes put priors on functions and give uncertainty everywhere, at $O(n^3)$ cost.
  • MCMC (Metropolis, HMC) samples posteriors that have no formula, using only ratios.
  • Thompson sampling uses posteriors to balance exploring and exploiting while deciding.

13.Check your understanding

1. A Beta(2, 8) prior is updated with 3 successes and 7 failures. The posterior is…

Add successes to $a$ and failures to $b$: Beta($2 + 3$, $8 + 7$).

2. The posterior mean of Bayesian linear regression with a normal prior equals…

With $\lambda = \sigma^2/\tau^2$. A Laplace prior would give lasso at the MAP.

3. Far from all training data, a Gaussian process's predictive standard deviation…

With no nearby data, the GP has only its prior to go on.

4. Why does the Metropolis algorithm not need the normalising constant $p(D)$?

Accepting with probability min(1, posterior ratio) needs the posterior only up to a constant.

5. In Thompson sampling, how is the design for each visitor chosen?

Random draws let uncertain designs be tried sometimes, while clearly good ones are chosen most of the time.

14.Going deeper: prior sensitivity and checking MCMC

In plain wordsHow three different priors give very different answers with 50 visitors but almost the same with 5,000, and how running several MCMC chains and comparing them with R-hat shows whether the sampler really reached the posterior.

Intermediate · skip on a first read

Two habits of careful Bayesian work: checking how much the prior changes the answer, and checking that an MCMC sampler has really explored the posterior before trusting its samples.

You'll need: this lesson and variance from Lesson 2.

How much does the prior matter?

Here three analysts give a conversion rate different priors: flat Beta(1, 1); sceptical Beta(10, 190), centred on 5%; and optimistic Beta(30, 170), centred on 15%. All see the same 6% conversion rate, with growing numbers of visitors:

from scipy import stats
for visitors, conv in [(50, 3), (500, 30), (5000, 300)]:
    row = []
    for name, a, b in [("flat", 1, 1), ("sceptical", 10, 190), ("optimistic", 30, 170)]:
        post = stats.beta(a + conv, b + visitors - conv)
        row.append(f"{name} {post.mean():.3f}")
    print(f"{visitors:5d} visitors (6% converted):", "   ".join(row))

Output:

   50 visitors (6% converted): flat 0.077   sceptical 0.052   optimistic 0.132
  500 visitors (6% converted): flat 0.062   sceptical 0.057   optimistic 0.086
 5000 visitors (6% converted): flat 0.060   sceptical 0.060   optimistic 0.063

With 50 visitors, the posterior means range from 5.2% to 13.2%: the priors dominate. With 500 they range from 5.7% to 8.6%, and with 5,000 they all agree within a third of a percentage point. A Beta($a$, $b$) prior acts like $a + b$ earlier visitors, so the optimistic prior is worth 200 of them. A sensitivity analysis like this belongs in any Bayesian report: if reasonable priors disagree, the data can't settle the question yet.

Has the sampler converged?

An MCMC chain starts somewhere arbitrary and needs time to reach the posterior; if its steps are too small it may never get there. The standard check is to run several chains from very different starting points and compare them with the $\hat{R}$ ("R-hat") statistic, which compares the spread between chains with the spread within them. Values near 1 mean the chains agree; above about 1.01 means keep sampling or fix the sampler. This version of the lesson's model uses a Cauchy likelihood with scale 1 and a wide normal prior:

import numpy as np
data = np.array([2.9, 3.1, 2.4, 3.3, 2.7, 8.5, 2.8])
def log_post(m):
    return -np.sum(np.log1p((data - m) ** 2)) - m ** 2 / 200       # Cauchy likelihood, wide normal prior
def chain(start, step, n=4000, seed=0):
    rng, m, out = np.random.default_rng(seed), start, []
    for _ in range(n):
        prop = m + rng.normal(0, step)
        if np.log(rng.random()) < log_post(prop) - log_post(m):
            m = prop
        out.append(m)
    return np.array(out[n // 2:])                                    # drop the first half as warm-up
def r_hat(chains):
    c = np.array(chains); n = c.shape[1]
    W, B = c.var(axis=1, ddof=1).mean(), n * c.mean(axis=1).var(ddof=1)
    return np.sqrt(((n - 1) / n * W + B / n) / W)
for step in [0.5, 0.005]:
    chains = [chain(s, step, seed=i) for i, s in enumerate([-10, 0, 10, 20])]
    print("step", step, " chain means", [round(float(c.mean()), 2) for c in chains], " R-hat", round(float(r_hat(chains)), 2))

Output:

step 0.5  chain means [2.91, 2.91, 2.95, 2.9]  R-hat 1.0
step 0.005  chain means [-9.8, -0.06, 9.84, 20.19]  R-hat 122.7

With a step size of 0.5, four chains starting at −10, 0, 10 and 20 all settle at about 2.9, and $\hat{R}$ is 1.0. With a step size of 0.005 each chain barely moves from where it started, and $\hat{R}$ is enormous. Each chain alone would look perfectly smooth, which is why one chain is never enough. Stan and PyMC report $\hat{R}$ and the effective sample size automatically; check both before using the samples.

How do you check that an MCMC run is trustworthy?

The trap: "Look at the trace and it looks fine."

Run several chains from dispersed starting points; check that $\hat{R}$ is close to 1 (below about 1.01) and that the effective sample size is large enough for the quantities you report; inspect trace plots and, for HMC, divergent transitions. Then do posterior predictive checks: simulate data from the fitted model and compare with the real data.

4. Why is one smooth-looking chain not enough?

Multiple starting points reveal it.

5. $\hat{R}$ is 1.3. What do you do?

Values above about 1.01 mean the chains haven't converged.
