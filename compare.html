Side-by-side comparisons

Eight pairs of ideas that are easy to mix up, compared point by point.

Beginners often mix up pairs of ideas that look alike. Each section below puts two of them side by side: the one-sentence difference, a picture computed with real models, a comparison table and when to choose each.

Linear regression vs logistic regressionRidge (L2) vs lasso (L1) regularisationBagging vs boostingk-means vs hierarchical clustering vs DBSCANPCA vs t-SNEPrecision vs recallNaive Bayes vs logistic regressionClassical machine learning vs deep learning

Linear regression vs logistic regression

Same recipe — a weighted sum of the features — but linear regression outputs that number directly, while logistic regression squashes it into a probability between 0 and 1.

Linear regressionLogistic regression
TaskRegression: predict a numberClassification: predict a class (via a probability)
Model$\hat{y} = \mathbf{w}\cdot\mathbf{x} + b$$p = \sigma(\mathbf{w}\cdot\mathbf{x} + b)$
Output rangeAny real numberBetween 0 and 1
Loss it minimisesMean squared errorLog loss (cross-entropy)
How it's solvedExact formula (normal equation) or gradient descentGradient descent only — no closed-form answer
Reading a weightChange in $y$ per unit of the featureChange in log-odds; $e^{w}$ multiplies the odds
Typical metricsMAE, RMSE, $R^2$Accuracy, precision, recall, ROC AUC, log loss
Chennai HomesPrice from size, distance and ageWill it sell within 30 days?
Choose Linear regression when…the answer is a quantity: a price, a temperature, a number of sales.
Choose Logistic regression when…the answer is a category, or you need a probability to set your own threshold.

Ridge (L2) vs lasso (L1) regularisation

Both add a penalty on large weights to fight overfitting. Ridge penalises squared weights and shrinks them all; lasso penalises absolute weights and sets some exactly to zero.

Ridge (L2)Lasso (L1)
Penalty added to the loss$\lambda\sum_j w_j^2$$\lambda\sum_j |w_j|$
Effect on weightsAll shrink towards 0, none become exactly 0Many become exactly 0
Feature selectionNo — keeps every featureYes — automatically drops weak features
Correlated featuresShares the weight between themTends to keep one and drop the others
SolutionClosed form existsIterative (coordinate descent)
GeometryCircle-shaped constraintDiamond-shaped constraint — corners lie on the axes
Choose Ridge when…you believe most features help a little, or features are strongly correlated.
Choose Lasso when…you suspect only a few features really matter and want a simpler, more explainable model. (Elastic net mixes both.)

Bagging vs boosting

Both combine many trees. Bagging trains them independently on random samples and averages them, which reduces variance. Boosting trains them one after another, each fixing the previous errors, which reduces bias.

Bagging / random forestBoosting / gradient boosting
How trees are builtIndependently, in parallelOne after another
Data each tree seesA bootstrap sample (random rows, plus random features in a forest)All the data, focused on what's still wrong (residuals or reweighted points)
Individual treesDeep, low bias, high varianceShallow, high bias, low variance
Mainly reducesVariance (overfitting)Bias (underfitting)
CombiningMajority vote or averageWeighted sum, scaled by a learning rate
Overfitting risk with more treesLow — more trees don't hurtGrows if you add too many — use early stopping
Tuning effortLittle: works well with defaultsMore: learning rate, number of trees, depth
Famous versionsRandom forest, extra treesAdaBoost, gradient boosting, XGBoost, LightGBM, CatBoost
Choose Bagging / random forest when…you want a strong model quickly with little tuning, or you can train in parallel.
Choose Boosting / gradient boosting when…you want the highest accuracy on tabular data and can spend time tuning.

k-means vs hierarchical clustering vs DBSCAN

Three ways to find groups. k-means looks for k round blobs around centres; hierarchical clustering builds a tree of merges you can cut at any level; DBSCAN grows clusters through dense regions and leaves sparse points as noise.

k-meansDBSCAN
You must choose$k$, the number of clusterseps (neighbourhood radius) and min_samples
Cluster shapesRound, similar-sized blobsAny shape, as long as it's dense
OutliersForced into some clusterLabelled as noise
Speed on large dataVery fast (MiniBatch for millions of points)Fast with a spatial index; struggles when densities vary
Result isSame $k$ every time; may vary with the startDeterministic for core points
Hierarchical clustering (third option)Builds a dendrogram of nested merges; choose the number of clusters afterwards by cutting itGood for small datasets and when the hierarchy itself is interesting
Choose k-means when…groups are roughly round and similar in size, and you know (or can test) how many there are.
Choose DBSCAN when…clusters have odd shapes, the data contains noise or outliers, or you don't know how many clusters to expect.

PCA vs t-SNE

PCA finds the straight directions of greatest variance and projects onto them. t-SNE moves points around in 2D so that neighbours stay neighbours — good for pictures, not for features.

PCAt-SNE (and UMAP)
TypeLinear projectionNon-linear embedding
PreservesGlobal structure and large distances (variance)Local neighbourhoods; distances between clusters mean little
Deterministic?YesNo — depends on the random seed and perplexity
New dataTransform it with the same projectionNo direct transform in t-SNE (UMAP can)
SpeedVery fastSlower; usually run on a PCA-reduced version
Interpretable axesYes — each component is a weighted mix of featuresNo — the axes have no meaning
Main useCompressing features before modelling, removing correlationVisualising high-dimensional data in 2D
Choose PCA when…you need fewer features for a model, want to understand which features vary together, or need a fast, repeatable transform.
Choose t-SNE when…you only want to see whether your data has clusters. Never feed t-SNE output to a model.

Precision vs recall

Precision asks: of everything I flagged, how much was right? Recall asks: of everything I should have flagged, how much did I catch? Raising the threshold usually trades recall for precision.

PrecisionRecall
Formula$\dfrac{TP}{TP + FP}$$\dfrac{TP}{TP + FN}$
Question it answersWhen the model says yes, how often is it right?Of all the real yeses, how many did it find?
Hurt byFalse alarms (false positives)Misses (false negatives)
Higher thresholdUsually goes upGoes down
Chennai Homes (Lesson 9)0.86 — one false alarm out of 7 flagged1.0 — all 6 fast sellers were caught
Combined intoF1 score = harmonic mean of the twoF1 score = harmonic mean of the two
Choose Precision when…false alarms are costly: a spam filter hiding real email, recommending a bad investment.
Choose Recall when…misses are costly: screening for a disease, detecting fraud.

Naive Bayes vs logistic regression

Two classic classifiers for text and simple tables. Naive Bayes models how each class generates the features (generative); logistic regression learns the boundary between classes directly (discriminative).

Naive BayesLogistic regression
ApproachGenerative: learns $P(\mathbf{x}\mid y)$ and $P(y)$, then uses Bayes' ruleDiscriminative: learns $P(y\mid\mathbf{x})$ directly
Key assumptionFeatures are independent within each classLog-odds are a linear function of the features
TrainingCounting — one pass over the data, instantGradient descent — iterative
Small datasetsOften better — needs little dataCan overfit without regularisation
Large datasetsUsually overtakenUsually more accurate
ProbabilitiesOften over-confident (too close to 0 or 1)Usually well calibrated
Choose Naive Bayes when…you need a fast baseline, especially for text, or you have very little data.
Choose Logistic regression when…you have more data and want better accuracy and trustworthy probabilities.

Classical machine learning vs deep learning

Classical models learn from features you design; deep networks learn the features themselves from raw data, at the price of much more data and computing power.

Classical ML (trees, linear models, SVMs…)Deep learning (neural networks)
Best data typeTables of numbers and categoriesImages, audio, text, video
FeaturesDesigned by you (feature engineering)Learned automatically from raw input
Data neededHundreds to millions of rowsUsually many thousands to billions of examples — or a pretrained model
HardwareA laptop CPUOften GPUs
Training timeSeconds to minutesMinutes to weeks
InterpretabilityOften good (weights, tree rules, importances)Hard — needs special explanation tools
Tabular data championGradient-boosted trees usually winRarely beats boosting on ordinary tables
Choose Classical ML when…your data is a table, the dataset is modest, or you need to explain decisions.
Choose Deep learning when…the input is images, sound or language, you have lots of data or can fine-tune a pretrained model.
