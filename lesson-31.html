1.Learning by acting

Supervised learning is told the right answer for every example. In many problems nobody can say what the right move is, only whether things went well in the end: a robot reaching a charger, a game won, a warehouse running cheaply, a thermostat saving energy while keeping people comfortable. Reinforcement learning (RL) learns from such delayed rewards, by acting, seeing what happens and adjusting.

This lesson covers the foundations without neural networks: Markov decision processes, value functions and the Bellman equation, value iteration when the rules are known, and Q-learning when they aren't. Lesson 28's bandits were the simplest RL problem: one decision, no state. Deep RL, which uses neural networks to handle huge state spaces such as images, builds directly on these ideas.

The core idea

The value of a situation is the reward you get now plus the (discounted) value of the situation you'll be in next, if you act well. Write that down for every state and you get the Bellman equation; solving it, or learning it from experience, tells you the best action everywhere.

2.Markov decision processes

A Markov decision process (MDP) has:

  • States $s$: the situations the agent can be in.
  • Actions $a$: what it can do in each state.
  • Transitions $P(s' \mid s, a)$: where an action leads, possibly at random.
  • Rewards $R$: the number received after each step.
  • A discount factor $\gamma$ between 0 and 1: how much future rewards count compared with immediate ones.

"Markov" means the next state depends only on the current state and action, not on the history. A policy $\pi(s)$ says which action to take in each state; the goal is the policy that maximises the expected return, $R_1 + \gamma R_2 + \gamma^2 R_3 + \dots$. Our example is a classic grid world: start at S, reach the goal G (+1), avoid the pit X (−1), with a wall at #. Each step costs 0.04, and the floor is slippery: 10% of the time the agent slides sideways instead of moving where it intended:

import numpy as np
ROWS, COLS = 4, 5
GOAL, PIT, WALL, START = (0, 4), (1, 4), (1, 1), (3, 0)
ACTIONS = {"↑": (-1, 0), "↓": (1, 0), "←": (0, -1), "→": (0, 1)}
STEP_COST, SLIP = -0.04, 0.1
states = [(i, j) for i in range(ROWS) for j in range(COLS) if (i, j) != WALL]
def move(s, a):
    i, j = s[0] + ACTIONS[a][0], s[1] + ACTIONS[a][1]
    return s if not (0 <= i < ROWS and 0 <= j < COLS) or (i, j) == WALL else (i, j)
def outcomes(s, a):                     # (probability, next state) — slips go sideways
    side = ["←", "→"] if a in "↑↓" else ["↑", "↓"]
    return [(1 - SLIP, move(s, a)), (SLIP / 2, move(s, side[0])), (SLIP / 2, move(s, side[1]))]
def reward(s):
    return 1.0 if s == GOAL else -1.0 if s == PIT else STEP_COST
terminal = {GOAL, PIT}
for i in range(ROWS):
    print(" ".join("G" if (i, j) == GOAL else "X" if (i, j) == PIT else "#" if (i, j) == WALL else "S" if (i, j) == START else "." for j in range(COLS)))

Output:

. . . . G
. # . . X
. . . . .
S . . . .

3.Values and the Bellman equation

The value $V(s)$ of a state is the expected return from there when acting optimally. It satisfies the Bellman optimality equation:

$$V(s) = \max_a \sum_{s'} P(s' \mid s, a)\,\big[R(s') + \gamma V(s')\big]$$

In words: try each action, average over where it might lead, and take the best. Value iteration turns this into an algorithm: start with all values at 0, apply the equation to every state, and repeat until nothing changes:

def value_iteration(gamma=0.9, tol=1e-6):
    V = {s: 0.0 for s in states}
    for sweep in range(1, 1000):
        delta = 0
        for s in states:
            if s in terminal: continue
            best = max(sum(p * (reward(n) + (0 if n in terminal else gamma * V[n])) for p, n in outcomes(s, a)) for a in ACTIONS)
            delta, V[s] = max(delta, abs(best - V[s])), best
        if delta < tol:
            return V, sweep
V, sweeps = value_iteration()
print("converged after", sweeps, "sweeps")
for i in range(ROWS):
    print(" ".join(f"{V[(i, j)]:6.3f}" if (i, j) in V and (i, j) not in terminal else "   +1 " if (i, j) == GOAL else "   -1 " if (i, j) == PIT else "   ## " for j in range(COLS)))

Output:

converged after 13 sweeps
 0.558  0.682  0.815  0.973    +1 
 0.452    ##   0.684  0.731    -1 
 0.363  0.451  0.561  0.596  0.412
 0.283  0.363  0.453  0.480  0.385
Worked example — one Bellman update

Take the square just left of the goal, (0, 3), with $\gamma = 0.9$. Moving → reaches the goal with probability 0.9, giving reward +1 and no future. With probability 0.05 each, it slides ↑ (into the edge, staying put) or ↓ (to the square with value 0.731).

So $Q(\rightarrow) = 0.9 \times 1 + 0.05\,(-0.04 + 0.9 \times 0.973) + 0.05\,(-0.04 + 0.9 \times 0.731) = 0.9 + 0.0418 + 0.0309 \approx 0.973$, which matches the converged value. The other actions give less, so → is best.

Values are highest next to the goal and fall with distance, since each step costs 0.04 and future rewards are discounted. The square left of the pit (0.731) is worth less than the one above it (0.973), because a slip could drop the agent into the pit.

4.From values to a policy

Once the values are known, the best action in each state is the one that achieves the maximum in the Bellman equation:

def greedy(V, gamma=0.9):
    return {s: max(ACTIONS, key=lambda a: sum(p * (reward(n) + (0 if n in terminal else gamma * V[n])) for p, n in outcomes(s, a)))
            for s in states if s not in terminal}
policy = greedy(V)
for i in range(ROWS):
    print(" ".join(policy.get((i, j), "G" if (i, j) == GOAL else "X" if (i, j) == PIT else "#") for j in range(COLS)))

Output:

→ → → → G
↑ # ↑ ↑ X
↑ → ↑ ↑ ←
→ → ↑ ↑ ←

The policy goes up the left side and along the top, well away from the pit, rather than taking the shorter route past it: with a slippery floor, the safe path has a higher expected return. In the bottom-right corner the arrows point left, away from the pit. The policy is optimal for this MDP, but finding it needed the full transition probabilities, which real problems rarely give you.

5.Try it: value iteration

Run one sweep at a time to watch values spread outwards from the goal, or run to convergence. Lower the discount and the agent becomes short-sighted; raise the slip chance and the policy steers further from the pit.

6.Learning without a model: Q-learning

Without known transition probabilities, the agent must learn from experience. Q-learning learns the value of each action in each state, $Q(s, a)$, from single steps. After taking action $a$ in state $s$, receiving reward $r$ and landing in $s'$, it nudges its estimate towards a target:

$$Q(s, a) \leftarrow Q(s, a) + \alpha\big[r + \gamma \max_{a'} Q(s', a') - Q(s, a)\big]$$

Here $\alpha$ is a learning rate, and the bracket is the temporal-difference error: how surprised the agent was. To keep discovering, it uses an ε-greedy policy, the bandit idea from Lesson 28: usually take the best-looking action, but with probability ε pick one at random.

rng = np.random.default_rng(0)
def step(s, a):
    r, acc = rng.random(), 0
    for p, n in outcomes(s, a):
        acc += p
        if r < acc: return n, reward(n)
    return n, reward(n)
def q_learning(episodes=3000, alpha=0.1, gamma=0.9, eps=0.1):
    Q = {s: {a: 0.0 for a in ACTIONS} for s in states}
    for _ in range(episodes):
        s = START
        for t in range(100):
            a = rng.choice(list(ACTIONS)) if rng.random() < eps else max(Q[s], key=Q[s].get)
            n, r = step(s, a)
            target = r if n in terminal else r + gamma * max(Q[n].values())
            Q[s][a] += alpha * (target - Q[s][a])       # move the estimate towards the target
            s = n
            if s in terminal: break
    return Q
Q = q_learning()
learned = {s: max(Q[s], key=Q[s].get) for s in policy}
agree = np.mean([learned[s] == policy[s] for s in policy])
print("Q-learning's greedy policy matches value iteration in", f"{agree:.0%}", "of states")
print("estimated value of the start: Q-learning", round(max(Q[START].values()), 3), " value iteration", round(V[START], 3))

Output:

Q-learning's greedy policy matches value iteration in 94% of states
estimated value of the start: Q-learning 0.277  value iteration 0.283

After 3,000 episodes of trial and error, without ever seeing the transition probabilities, Q-learning's greedy policy matches the optimal one in 94% of states, and its estimate of the start's value (0.277) is close to the true 0.283. The states where it differs are rarely visited, so it has had little experience of them. This is the general shape of RL: data comes from the agent's own behaviour, so what it explores decides what it can learn.

7.Rewards shape behaviour

The agent optimises exactly the reward you give it, so choosing rewards is a design decision with consequences. Here the same grid is solved with three different step costs (each row of the grid separated by "|"):

for cost in [-0.01, -0.4, -2.0]:
    STEP_COST = cost                                        # reward() reads this global
    pol = greedy(value_iteration()[0])
    rows = [" ".join(pol.get((i, j), "G" if (i, j) == GOAL else "X" if (i, j) == PIT else "#") for j in range(COLS)) for i in range(ROWS)]
    print(f"step cost {cost}:   " + "   |   ".join(rows))
STEP_COST = -0.04

Output:

step cost -0.01:   → → → → G   |   ↑ # ↑ ↑ X   |   ↑ → ↑ ↑ ←   |   ↑ → ↑ ↑ ←
step cost -0.4:   → → → → G   |   ↑ # ↑ ↑ X   |   ↑ → ↑ ↑ ←   |   → → ↑ ↑ ↑
step cost -2.0:   → → → → G   |   ↑ # → → X   |   → → → ↑ ↑   |   → → → ↑ ↑

With a small step cost, the agent takes the long, safe route. With a huge one (−2 per step), living is so expensive that from the squares next to the pit the agent heads straight for it: ending the episode at −1 beats wandering towards the goal. That's correct for the reward given, and a small example of reward hacking: agents find whatever maximises the reward, intended or not. Real systems need careful reward design and testing, and often constraints.

8.RL in practice

IdeaWhat it means
Model-based vs model-freeValue iteration uses known transitions; Q-learning learns from experience alone
On-policy vs off-policySARSA learns the value of the policy it follows; Q-learning learns the optimal policy while exploring
Policy gradient methodsAdjust a parameterised policy directly in the direction that increases return (REINFORCE, PPO)
Function approximationReplace the Q table with a model (linear or a neural network: deep Q-networks) when there are too many states
Offline RLLearn from logged data without new experiments; hard, because of distribution shift

RL is powerful but data-hungry and hard to debug. In business settings, start with simpler tools: a bandit (Lesson 28) for choosing between options, a forecast plus optimisation for planning, or supervised learning when the right answer is known. Use full RL when decisions really affect future states and you can simulate or safely experiment.

9.In Python: Q-learning on a corridor

A compact, self-contained Q-learning agent on a 6-square corridor: start in the middle, +1 at the right end, −1 at the left:

import numpy as np

rng = np.random.default_rng(1)
N, START, gamma, alpha, eps = 6, 2, 0.9, 0.2, 0.2
Q = np.zeros((N, 2))                      # actions: 0 left, 1 right
for episode in range(500):
    s = START
    while 0 < s < N - 1:
        a = rng.integers(2) if rng.random() < eps else int(Q[s].argmax())
        s2 = s + (1 if a == 1 else -1)
        r = 1.0 if s2 == N - 1 else -1.0 if s2 == 0 else 0.0
        target = r if s2 in (0, N - 1) else r + gamma * Q[s2].max()
        Q[s, a] += alpha * (target - Q[s, a])
        s = s2
print("Q values for 'right' in squares 1 to 4:", np.round(Q[1:N - 1, 1], 3).tolist())
print("best action in squares 1 to 4:", ["right" if q[1] > q[0] else "left" for q in Q[1:N - 1]])

Output:

Q values for 'right' in squares 1 to 4: [0.729, 0.81, 0.9, 1.0]
best action in squares 1 to 4: ['right', 'right', 'right', 'right']

The Q values for "right" grow towards the goal: each one is about $\gamma$ times the next, because the +1 is one more step away. The learned policy goes right everywhere, even from square 1, next to the −1, because the goal's value has propagated back that far.

10.Running example: Chennai Homes

Should a seller cut the price of a listed home? Treat it as a small MDP: each week the home sells with some probability (about 1 in 8, from the share of homes that sold fast), cutting the price 5% doubles that chance but lowers the sale value, and each week on the market costs 0.5 lakh. Value iteration says holding is best in every state: with these numbers, waiting a few extra weeks costs less than the 5% cut. Raise the weekly cost or the effect of a cut and the policy switches, which is exactly the kind of trade-off RL formalises.

Same 12 houses as Lesson 1. With so little data, treat the numbers as an illustration of the method, not as reliable estimates.

import pandas as pd
import numpy as np
df = pd.read_csv("houses.csv")   # download it from Lesson 1
# Each week a listed home sells with probability p; cutting the price 5% raises p but lowers the sale value.
p_hold = df.sold_fast.mean() / 4                     # about half the homes sell within ~4 weeks
p_cut, price, gamma, weekly_cost = min(1, 2 * p_hold), df.price_lakh.median(), 0.98, 0.5
V = {k: 0.0 for k in range(4)}                       # state: number of price cuts so far (max 3)
for _ in range(500):
    V = {k: max(p_hold * price * 0.95 ** k + (1 - p_hold) * gamma * V[k] - weekly_cost,
                p_cut * price * 0.95 ** (k + 1) + (1 - p_cut) * gamma * V[min(k + 1, 3)] - weekly_cost if k < 3 else -1e9)
         for k in V}
for k in V:
    hold = p_hold * price * 0.95 ** k + (1 - p_hold) * gamma * V[k] - weekly_cost
    print(f"after {k} cuts: value {V[k]:.1f} lakh, best action:", "hold" if abs(V[k] - hold) < 1e-9 else "cut")

Output:

after 0 cuts: value 62.7 lakh, best action: hold
after 1 cuts: value 59.4 lakh, best action: hold
after 2 cuts: value 56.3 lakh, best action: hold
after 3 cuts: value 53.3 lakh, best action: hold

Where this is used
  • Robotics, games and simulated control
  • Inventory, pricing and resource allocation over time
  • Recommendation and ad systems that optimise long-term engagement

Choose it when: Whenever decisions affect future situations and you can simulate or safely experiment.

Think twice when: the right answer for each case is known (supervised learning), or a single decision has no lasting effect (a bandit).

Misconceptions to unlearn

MythRL is the best approach for any sequential decision.

RealityIt's data-hungry and hard to debug; simpler methods (forecast plus optimisation, bandits) are often better.

MythThe agent will do what we mean.

RealityIt does what maximises the reward we give, which may differ (reward hacking).

MythExploration can be switched off once training starts.

RealityWithout exploration the agent can't discover better actions; it must keep some throughout learning.

Responsible AI · Optimising the wrong thing at scale

RL systems pursue exactly the reward they're given, relentlessly. A recommender optimised for watch time can learn to promote outrage; a pricing agent can learn to exploit vulnerable customers. Choose rewards that reflect real long-term value, add constraints for things that must never happen, test policies in simulation and with small, monitored rollouts, and keep humans able to override.

11.Questions beginners often ask

How is RL different from supervised learning?

Supervised learning is told the right answer for each example. RL only gets rewards, often delayed, and its data depends on its own actions, so it must explore.

Why discount future rewards?

It keeps returns finite for long tasks, reflects uncertainty about the future, and expresses a preference for sooner rewards. A $\gamma$ near 1 means far-sighted behaviour.

What's the difference between Q-learning and SARSA?

Q-learning updates towards the best next action (off-policy); SARSA updates towards the action it actually takes next (on-policy), so SARSA learns safer behaviour while exploring.

Where does deep RL fit in?

When there are too many states for a table, a neural network approximates the Q function or the policy. The update rules are the same ideas as here.

Common mistakes to avoid
  • Designing a reward that can be maximised in an unintended way.
  • Using no exploration, so the agent never tries better actions.
  • Choosing a discount factor that makes the agent too short-sighted.
  • Evaluating a policy only on the states it visited during training.
  • Reaching for RL when a supervised model or a bandit would do.

Hidden questions — answer in your head first, then open.

How is reinforcement learning different from supervised learning?

The trap: Saying RL just has a different loss function.

Supervised learning gets the correct answer for every example. RL gets only rewards, often delayed, for actions it chooses, and its data depends on its own behaviour, so it must balance exploration and exploitation and assign credit to earlier actions for later rewards.

Explain the Bellman equation.

The trap: Writing the formula without explaining it.

It says the value of a state equals the best expected immediate reward plus the discounted value of the next state: V(s) = max_a Σ P(s′|s,a)[R + γV(s′)]. It breaks a long-horizon problem into one-step relations; value iteration applies it repeatedly, and Q-learning uses a sampled version as its update target.

What is reward hacking, and how do you guard against it?

The trap: "Use a bigger model."

An agent finds a way to maximise its reward that the designers didn't intend: ending an episode early, exploiting a simulator bug, optimising clicks with outrage. Guard against it with rewards that reflect the true goal, constraints and penalties for unsafe actions, testing in diverse simulations, monitoring behaviour not just reward, and human oversight.

Explain on-policy versus off-policy reinforcement learning with an example.

The trap: Saying they're the same algorithm.

On-policy methods (SARSA, PPO) learn the value of the policy they're actually following, including its exploration; off-policy methods (Q-learning, DQN) learn about a different target policy, usually the greedy one, from data generated by another behaviour policy. On the cliff-walking task, Q-learning finds the optimal edge route but falls off often while exploring, while SARSA learns a safer route. Off-policy methods can reuse old or logged data, which on-policy ones can't easily do.

12.Key takeaways

  • RL learns from rewards by acting; an MDP has states, actions, transitions, rewards and a discount $\gamma$.
  • The Bellman equation links a state's value to its neighbours'; value iteration solves it when the model is known.
  • A policy follows from the values: pick the action with the best expected return.
  • Q-learning learns action values from experience alone, with ε-greedy exploration.
  • Agents optimise exactly the reward they're given; design it carefully.

14.Going deeper: SARSA versus Q-learning on a cliff

In plain wordsQ-learning learns the shortest route along a cliff edge, while SARSA, which accounts for its own random exploration, learns a safer route and collects more reward while it's still learning.

Intermediate · skip on a first read

A classic experiment showing the difference between learning the best policy and learning the best policy given that you keep exploring, and why that matters for real systems.

You'll need: this lesson's Q-learning section.

Two learners, one cliff

On a 4×8 grid, the agent starts bottom left and must reach bottom right. The squares between them are a cliff: stepping on one costs −100 and sends it back to the start; every other step costs −1. SARSA differs from Q-learning in one word: it updates towards the value of the action it will actually take next (including random exploratory ones), not the best one:

$$Q(s, a) \leftarrow Q(s, a) + \alpha\big[r + \gamma\,Q(s', a') - Q(s, a)\big]$$

import numpy as np
# Cliff walking: a 4×8 grid; the bottom row between start and goal is a cliff (−100, back to start).
R, C = 4, 8
start, goal = (3, 0), (3, 7)
moves = [(-1, 0), (1, 0), (0, -1), (0, 1)]
def env(s, a):
    i, j = min(max(s[0] + moves[a][0], 0), R - 1), min(max(s[1] + moves[a][1], 0), C - 1)
    if i == 3 and 0 < j < 7: return start, -100
    return (i, j), -1
rng = np.random.default_rng(0)
def train(method, episodes=500, alpha=0.5, eps=0.1):
    Q = np.zeros((R, C, 4))
    pick = lambda s: rng.integers(4) if rng.random() < eps else int(Q[s].argmax())
    for _ in range(episodes):
        s = start; a = pick(s)
        for t in range(200):
            s2, r = env(s, a); a2 = pick(s2)
            nxt = 0 if s2 == goal else (Q[s2].max() if method == "Q" else Q[s2][a2])
            Q[s][a] += alpha * (r + nxt - Q[s][a]); s, a = s2, a2
            if s == goal: break
    return Q
def route(Q):
    s, path = start, [start]
    for _ in range(40):
        s, _ = env(s, int(Q[s].argmax())); path.append(s)
        if s == goal: break
    return path
for method in ["Q", "SARSA"]:
    p = route(train(method))
    edge = sum(1 for c in p if c[0] == 2)                  # steps right next to the cliff
    print(f"{method:5s}: greedy route length {len(p) - 1}, steps along the cliff edge {edge}")

Output:

Q    : greedy route length 9, steps along the cliff edge 8
SARSA: greedy route length 13, steps along the cliff edge 2

Q-learning learns the shortest route, 9 steps with 8 of them right along the cliff edge: optimal if you never make a mistake. SARSA learns a longer, 13-step route that keeps away from the edge, because it knows that its own ε-greedy exploration will sometimes take a random step, and next to the cliff that's a disaster.

Which is better depends on when you're judged

Measure the reward actually collected during learning, while both agents still explore 10% of the time:

def run_returns(method, episodes=500, eps=0.1):
    Q, total = np.zeros((R, C, 4)), []
    for _ in range(episodes):
        s, G = start, 0
        a = rng.integers(4) if rng.random() < eps else int(Q[s].argmax())
        for t in range(200):
            s2, r = env(s, a); G += r
            a2 = rng.integers(4) if rng.random() < eps else int(Q[s2].argmax())
            nxt = 0 if s2 == goal else (Q[s2].max() if method == "Q" else Q[s2][a2])
            Q[s][a] += 0.5 * (r + nxt - Q[s][a]); s, a = s2, a2
            if s == goal: break
        total.append(G)
    return np.mean(total[-200:])
q_ret = np.mean([run_returns("Q") for _ in range(5)]); s_ret = np.mean([run_returns("SARSA") for _ in range(5)])
print("average return while still exploring: Q-learning", round(q_ret, 1), "  SARSA", round(s_ret, 1))

Output:

average return while still exploring: Q-learning -31.2   SARSA -21.0

SARSA collects more reward while exploring (−21.0 against −31.2), because Q-learning's edge-hugging route often falls off when a random step happens. If exploration stops after training, Q-learning's policy is better; if the agent keeps exploring, or a real robot occasionally slips, SARSA's caution pays. In real systems where mistakes during learning are costly, that's a strong argument for on-policy or explicitly risk-aware methods, and for learning in simulation first.

Explain on-policy versus off-policy reinforcement learning with an example.

The trap: Saying they're the same algorithm.

On-policy methods (SARSA, PPO) learn the value of the policy they're actually following, including its exploration; off-policy methods (Q-learning, DQN) learn about a different target policy, usually the greedy one, from data generated by another behaviour policy. On the cliff-walking task, Q-learning finds the optimal edge route but falls off often while exploring, while SARSA learns a safer route. Off-policy methods can reuse old or logged data, which on-policy ones can't easily do.

Check your understanding: going deeper

1. What's the one difference between SARSA's and Q-learning's update?

SARSA is on-policy; Q-learning is off-policy.

2. Why does SARSA learn a route further from the cliff?

Next to the cliff, a random step is very costly.

3. If exploration stops after training, which policy is better on the cliff?

Without random steps, the edge route is optimal.

4. Which agent collected more reward while still exploring?

Its cautious route avoided most falls.

5. Why might a real robot prefer SARSA-style learning?

Safety during learning matters.
