The real goal: doing well on data you've never seen

In Lesson 1 we said learning means "find the parameters that make the loss small". That's true — but there's a catch. A model's job is not to describe the data it was trained on; we already know the answers for that data. Its job is to make good predictions on new data: next month's houses, tomorrow's emails, a patient who walks in next week.

This ability is called generalization, and it is the single most important idea in machine learning. This lesson explains how data is organised, why a model can fool you by memorising, and the techniques everyone uses to measure generalization honestly.

Analogy: the exam

A teacher gives students 50 practice questions. Student A memorises the 50 answers. Student B learns the methods behind them. On the practice questions both score 100%. On the real exam — new questions — Student A fails and Student B passes. A model that memorises its training data is Student A. We want Student B, and we need a fair exam to tell them apart.

What a dataset looks like

A typical supervised dataset is a table: one row per example, one column per feature, plus a label column. From Lesson 2, the features form a matrix $X$ of shape $n \times d$ ($n$ examples, $d$ features) and the labels form a vector $\mathbf{y}$ of length $n$.

Kinds of features

  • Numerical — measured quantities: size in m², age, temperature. Can be continuous (any value) or discrete (counts like number of bedrooms).
  • Categorical — one of a fixed set of categories: colour (red/green/blue), city, product type. Computers need these converted to numbers (Lesson 20 shows how).
  • Ordinal — categories with a natural order: small < medium < large; ratings 1–5 stars.
  • Binary — yes/no, true/false, encoded as 1/0.
  • Text, images, audio — unstructured data that must be turned into numbers first (e.g. word counts, pixel values).

Good data matters more than clever algorithms

A model can only learn patterns that are actually in the data. Common problems:

  • Missing values — blanks in the table.
  • Errors and outliers — a house listed at 5 m², a typo adding three zeros to a price.
  • Too few examples — the model can't tell real patterns from coincidences.
  • Unrepresentative data — training only on city flats, then predicting rural farmhouses.
  • Wrong labels — mislabelled examples teach the wrong lesson.
The i.i.d. assumption

Most ML assumes examples are independent and identically distributed (i.i.d.): each one is drawn from the same underlying source, without depending on the others. In plain words: the future data will look like the past data. When that stops being true — fashions change, a new competitor arrives — models quietly get worse. This is called distribution shift or drift.

Underfitting, good fit and overfitting

Imagine data that follows a gentle curve, plus some random noise. We can fit models of different complexity (flexibility):

  • Underfitting — the model is too simple to capture the pattern, e.g. a straight line through a curve. It's wrong on the training data and on new data. High error everywhere.
  • Good fit — the model captures the real pattern and ignores the noise. Low error on training data, and similarly low on new data.
  • Overfitting — the model is so flexible that it bends to pass through every training point, noise included. Training error is tiny, but on new data it makes wild mistakes.
Definitions

Training error: the loss measured on the data the model was trained on.
Test (generalization) error: the loss on new data the model has never seen.
Overfitting: training error ≪ test error. Underfitting: both are high.

Training error almost always keeps falling as complexity grows — a more flexible model can always fit the training points better. Test error, however, falls at first and then rises again once the model starts fitting noise. The sweet spot is the bottom of the test-error curve.

Try it: watch overfitting happen

The blue dots are training data and the orange dots are test data, both drawn from the same hidden curve plus noise. The green line is a polynomial of the chosen degree fitted to the training dots only. Increase the degree and watch: training error keeps shrinking, but past a point the curve starts wiggling to chase individual points, and the test error grows.

A polynomial of degree $k$ is $\hat{y} = w_0 + w_1x + w_2x^2 + \dots + w_kx^k$. With 12 training points, a degree-11 polynomial has 12 parameters and can pass through every point exactly — a perfect training score and a terrible model.

The train / validation / test split

The fix is simple and non-negotiable: evaluate on data the model did not train on. Before doing anything else, split your data:

SetUsed forTypical share
Training setFitting the model's parameters.~70%
Validation setComparing models and choosing settings (like the polynomial degree).~15%
Test setOne final, honest estimate of performance on new data.~15%

Google's Machine Learning Crash Course uses exactly this 70 / 15 / 15 illustration. The exact percentages vary; with very large datasets the validation and test sets can be a smaller share.

Why a separate validation set?

If you try 20 different models and pick whichever scores best on the test set, you have used the test set to make decisions — you've tuned to it. Its score is now optimistic. The test set must stay locked away until the very end. Choices are made on the validation set; the test set gives the final verdict. Validation and test sets also "wear out": the more you reuse them, the less trustworthy they become.

Rules for a good split:

  • Shuffle randomly before splitting (unless the data is a time series — then train on the past and test on the future).
  • Make sure the test set is representative — the same mix of cases as real-world data.
  • No duplicates between training and test sets, or you're testing on memorised examples.
  • For classification, use a stratified split so each set has the same proportion of each class.

k-fold cross-validation

With a small dataset, a single validation split is unreliable: the score depends heavily on which examples happened to land in it. k-fold cross-validation uses the data more efficiently:

  1. Split the training data into $k$ equal parts called folds (commonly $k = 5$ or $10$).
  2. Train on $k-1$ folds and evaluate on the remaining fold.
  3. Repeat $k$ times, so each fold is the validation fold exactly once.
  4. Report the mean (and standard deviation) of the $k$ scores.
$$\text{CV score} = \frac{1}{k}\sum_{j=1}^{k} \text{score}_j$$
Worked example — 5-fold CV

A model's accuracy on the 5 validation folds: $0.82,\ 0.85,\ 0.80,\ 0.84,\ 0.84$.

Mean: $(0.82 + 0.85 + 0.80 + 0.84 + 0.84)/5 = 4.15/5 = 0.83$.

Deviations from the mean: $-0.01,\ 0.02,\ -0.03,\ 0.01,\ 0.01$. Squared: $0.0001,\ 0.0004,\ 0.0009,\ 0.0001,\ 0.0001$. Variance $= 0.0016/5 = 0.00032$, standard deviation $= \sqrt{0.00032} \approx 0.018$.

We report 0.83 ± 0.02. The ± tells you how much the score depends on the particular split — if two models differ by less than this, the difference may just be luck.

Every example is used for validation exactly once and for training $k-1$ times. The cost: you train $k$ models instead of one. You still keep a separate test set for the very end.

Data leakage: the silent killer

Data leakage happens when information from outside the training data sneaks into training, making evaluation look better than reality. Classic examples:

  • Preprocessing before splitting. Computing the mean and standard deviation for standardisation (Lesson 4) on all data, including the test set. The model has indirectly "seen" the test data.
  • Features that contain the answer. Predicting whether a customer will cancel, using a column "cancellation fee charged".
  • Time travel. Using future information to predict the past, e.g. randomly splitting stock prices so the model trains on Wednesday to predict Tuesday.
  • Duplicates across train and test.
The golden rule

Split first. Then learn everything — scaling statistics, feature choices, model parameters — from the training data only, and merely apply it to validation and test data. scikit-learn's documentation states it directly: never call fit on the test data.

Putting it together

  1. Split off a test set and don't look at it.
  2. On the training set, use cross-validation (or a validation set) to compare models and settings.
  3. Pick the best, then retrain it on the full training set.
  4. Evaluate once on the test set and report that number.

In Python

This experiment reproduces the demo: fit polynomials of increasing degree and compare training and test error.

import numpy as np
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import PolynomialFeatures
from sklearn.linear_model import LinearRegression
from sklearn.pipeline import make_pipeline
from sklearn.metrics import mean_squared_error

rng = np.random.default_rng(0)
x = rng.uniform(-3, 3, 30)
y = np.sin(x) + rng.normal(0, 0.3, 30)          # hidden curve + noise
X = x.reshape(-1, 1)                             # sklearn wants a 2D matrix

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.5, random_state=1)

for degree in [1, 3, 9, 12]:
    model = make_pipeline(PolynomialFeatures(degree), LinearRegression())
    model.fit(X_train, y_train)
    train_mse = mean_squared_error(y_train, model.predict(X_train))
    test_mse = mean_squared_error(y_test, model.predict(X_test))
    print(f"degree {degree:2d}: train MSE {train_mse:.3f}   test MSE {test_mse:.3f}")

Output:

degree  1: train MSE 0.217   test MSE 0.188
degree  3: train MSE 0.041   test MSE 0.092
degree  9: train MSE 0.010   test MSE 0.250
degree 12: train MSE 0.006   test MSE 0.492

Degree 1 underfits: a straight line can't follow a sine wave, so both errors are high. Degree 3 fits well: both errors are low. As the degree rises to 9 and 12, training error keeps falling — but test error climbs to more than five times its best value. That's overfitting.

And 5-fold cross-validation in two lines:

from sklearn.model_selection import cross_val_score

model = make_pipeline(PolynomialFeatures(3), LinearRegression())
scores = cross_val_score(model, X_train, y_train, cv=5, scoring="neg_mean_squared_error")
print(-scores.mean(), scores.std())     # mean MSE across the 5 folds, and its spread

(scikit-learn reports errors as negative numbers so that "higher is better" for every score; we flip the sign back.)

Key takeaways

  • The goal is generalization: good performance on new, unseen data.
  • Underfitting = too simple (both errors high). Overfitting = memorising noise (training error low, test error high).
  • Always split: train to fit, validation to choose, test once at the end.
  • k-fold cross-validation gives a more reliable estimate: report mean ± standard deviation.
  • Avoid data leakage: split first, fit everything on training data only.

Check your understanding

1. Training error 0.01, test error 2.5. What's happening?

A huge gap between low training error and high test error means the model memorised the training data: overfitting.

2. Training error 3.1, test error 3.3, and a simple model. What's the likely problem?

Both errors are high and similar: the model is too simple to capture the pattern — underfitting. Try a more flexible model or better features.

3. Which set should you use to choose between 10 candidate models?

Choices are made on validation data. The test set is reserved for one final, unbiased evaluation; the training score is too optimistic.

4. In 5-fold cross-validation, how many models are trained?

One per fold: each of the 5 folds takes a turn as the validation set.

5. You standardise all your data using its overall mean, then split into train and test. What's wrong?

The mean was computed partly from test data. Split first, compute statistics on the training set only, then apply them to the test set.
