Why explain a model?

A bank's model refuses a loan. The applicant asks why. The regulator asks how the model decides. The data scientist wants to know whether it learned something real or a shortcut, such as a hospital's scanner model that "detects" pneumonia by reading the hospital's name printed on the X-ray. Accuracy answers none of these questions.

Interpretability methods answer two kinds of question:

  • Global: how does the model behave overall? Which features matter most, and how does the prediction change as a feature changes?
  • Local: why did the model make this prediction for this person?

This lesson covers the methods practitioners use most: reading linear weights properly, permutation importance, partial-dependence and ICE plots, SHAP values (built from scratch, so there's no mystery), and LIME-style local surrogates, along with the traps that make explanations misleading.

The core idea

An explanation is itself a simplified model of the model. Global methods summarise behaviour across all the data; local methods describe one prediction. Every method answers a specific, narrow question, and none of them says what causes the outcome in the real world: only what the model relies on.

Reading linear models properly

For linear and logistic regression the weights are the explanation, but only if the features are on comparable scales. A weight per millimetre and a weight per kilometre can't be compared. Standardise first (Lesson 10), and each weight becomes "the change in log-odds for a one-standard-deviation increase in the feature":

import numpy as np
import pandas as pd
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

data = load_breast_cancer()
X, y, names = data.data, data.target, data.feature_names      # target 1 = benign
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)
lin = make_pipeline(StandardScaler(), LogisticRegression(C=0.1, max_iter=5000)).fit(X_tr, y_tr)
coef = pd.Series(lin[-1].coef_[0], index=names)
print("largest standardised weights (positive pushes towards benign):")
print(coef.reindex(coef.abs().sort_values(ascending=False).index).head(5).round(3))

Output:

largest standardised weights (positive pushes towards benign):
worst texture          -0.543
worst radius           -0.529
worst perimeter        -0.496
worst concave points   -0.469
worst area             -0.463
dtype: float64

On the breast-cancer data (target 1 = benign), the five largest standardised weights are all negative: larger "worst" tumour measurements push the prediction away from benign. Three cautions from earlier lessons apply. Correlated features share and swap weight (Lesson 6's "Going deeper": radius, perimeter and area are almost the same measurement here). Regularization shrinks weights. And a weight describes association in this model, not cause.

Permutation importance

For any model, permutation importance asks: how much worse does the model get if this feature's information is destroyed? Shuffle one column of the test data, which breaks its link to the target but keeps its distribution, and measure the drop in score. Repeat with several shuffles and average. Lesson 13's "Going deeper" showed why this is more honest than a tree's built-in impurity importance.

from sklearn.ensemble import RandomForestClassifier
from sklearn.inspection import permutation_importance

rf = RandomForestClassifier(n_estimators=300, random_state=0).fit(X_tr, y_tr)
print("test accuracy:", round(rf.score(X_te, y_te), 3))
perm = permutation_importance(rf, X_te, y_te, n_repeats=30, random_state=0)
imp = pd.Series(perm.importances_mean, index=names).sort_values(ascending=False)
print("permutation importance on test data (drop in accuracy):")
print(imp.head(5).round(4))

Output:

test accuracy: 0.953
permutation importance on test data (drop in accuracy):
worst radius            0.0211
worst area              0.0177
worst concave points    0.0156
worst texture           0.0131
worst perimeter         0.0131
dtype: float64

The random forest's accuracy falls most when "worst radius" is shuffled (by 0.021, about 2 percentage points). The drops are small because the features are highly correlated: when one is shuffled, the forest can lean on a near-copy. That's the main weakness of permutation importance; the fix is to shuffle groups of correlated features together, or to read the results as "unique information this feature adds".

Partial dependence and ICE plots

Importance says how much a feature matters, not how. A partial-dependence plot (PDP) shows the average prediction as one feature is varied: set the feature to a value $v$ for every row, predict, average, and repeat for a grid of values:

$$\text{PD}(v) = \frac{1}{n}\sum_{i=1}^{n} f\big(v,\ \mathbf{x}_{i,\text{other}}\big)$$

An ICE plot (individual conditional expectation) draws one such curve per row instead of their average, revealing whether different people respond differently.

from sklearn.datasets import load_diabetes
from sklearn.ensemble import GradientBoostingRegressor
from sklearn.inspection import partial_dependence

d = load_diabetes()
Xd, yd = d.data, d.target
gbr = GradientBoostingRegressor(random_state=0).fit(Xd, yd)
bmi = list(d.feature_names).index("bmi")
pd_res = partial_dependence(gbr, Xd, [bmi], grid_resolution=6, kind="both")
print("bmi (scaled):        ", np.round(pd_res["grid_values"][0], 3))
print("average prediction:  ", np.round(pd_res["average"][0], 1))
ice = pd_res["individual"][0]
print("ICE spread at each bmi value (std across patients):", np.round(ice.std(axis=0), 1))

Output:

bmi (scaled):         [-0.067 -0.036 -0.005  0.025  0.056  0.087]
average prediction:   [130.9 129.1 141.7 176.4 177.  209.7]
ICE spread at each bmi value (std across patients): [45.2 40.6 49.  42.6 45.4 45.8]

For a gradient-boosting model of diabetes progression, the average prediction rises from about 131 to 210 as BMI goes from low to high: a clear, mostly increasing effect, with a jump in the middle of the range. The ICE curves are spread out by about 40–49 units at every BMI value, so patients' baseline predictions differ a lot even though the BMI effect is similar. One warning: a PDP sets BMI to every value for every patient, including combinations that don't occur in real data (say, very high BMI with very low weight-related blood measures). With strongly correlated features, prefer ALE plots (accumulated local effects), which only use realistic nearby values.

SHAP values: fair credit for each feature

For one prediction, we'd like to split "prediction minus the average prediction" into a contribution from each feature. The fair way to do it comes from cooperative game theory: the Shapley value. Treat features as players and the prediction as the payout. A feature's Shapley value is its average extra contribution when it joins, averaged over every possible order in which the features could join:

$$\phi_j = \sum_{S \subseteq F \setminus \{j\}} \frac{|S|!\,(p - |S| - 1)!}{p!}\Big[v(S \cup \{j\}) - v(S)\Big]$$

Here $v(S)$ is the model's expected prediction when only the features in $S$ are known; the unknown ones are filled in from a background sample. Shapley values are the only way of splitting the credit that is fair in a precise sense:

  • Efficiency: the contributions add up exactly to prediction minus baseline.
  • Symmetry: two features that always contribute equally get equal credit.
  • Dummy: a feature that never changes the prediction gets 0.
Worked example — Shapley values by hand

A tiny model: $f = 2x_1 + 3x_2 + 4x_1x_3$, explained at $\mathbf{x} = (1, 0.5, 1)$ against the baseline $(0, 0, 0)$, where $f = 0$. So the total to share is $f(\mathbf{x}) = 2 + 1.5 + 4 = 7.5$.

$x_2$ enters the model on its own, so it adds $3 \times 0.5 = 1.5$ whenever it joins: $\phi_2 = 1.5$.

$x_1$ always adds its own $2$. It also adds the interaction $4$, but only if $x_3$ has already joined, which happens in half of the orderings. So $\phi_1 = 2 + 4 \times \tfrac12 = 4$.

$x_3$ has no effect of its own; it adds the interaction $4$ only if $x_1$ is already in (half the orderings): $\phi_3 = 2$.

Check: $4 + 1.5 + 2 = 7.5$ ✓. The interaction's credit is split equally between the two features that create it.

The same formula, computed exactly for a gradient-boosting model on four diabetes features and one patient:

from itertools import combinations
from math import factorial

# Exact Shapley values for a model on 4 features, for one patient
feats = ["bmi", "bp", "s5", "age"]
idx = [list(d.feature_names).index(f) for f in feats]
X4 = Xd[:, idx]
model4 = GradientBoostingRegressor(random_state=0).fit(X4, yd)
background = X4[:100]                    # "absent" features are filled in from these patients
x = X4[200]

def value(subset):
    """Average prediction when the features in `subset` take x's values and the others vary as in the background."""
    Z = background.copy()
    Z[:, list(subset)] = x[list(subset)]
    return model4.predict(Z).mean()

p = len(feats); shap = np.zeros(p)
for j in range(p):
    others = [k for k in range(p) if k != j]
    for size in range(p):
        for S in combinations(others, size):
            weight = factorial(size) * factorial(p - size - 1) / factorial(p)
            shap[j] += weight * (value(S + (j,)) - value(S))

base, pred = value(()), model4.predict(x[None, :])[0]
for f, v in zip(feats, shap):
    print(f"{f:4}: {v:+7.2f}")
print(f"baseline {base:.2f}, plus the contributions ({shap.sum():.2f}), gives {base + shap.sum():.2f}")
print(f"the model's actual prediction: {pred:.2f}")

Output:

bmi :  -11.11
bp  :   +2.11
s5  :  -13.74
age :   +5.26
baseline 136.35, plus the contributions (-17.47), gives 118.87
the model's actual prediction: 118.87

The baseline (average prediction over the background patients) is 136.35. For this patient, low s5 (a blood-serum measure) lowers the prediction by 13.74 and low BMI by 11.11, while age adds 5.26 and blood pressure 2.11. The four contributions add to −17.47, giving 118.87, exactly the model's prediction: the efficiency property in action.

The exact formula needs $2^p$ subsets, so with 4 features it's 16 evaluations, but with 40 features it's about a trillion. The shap library makes it practical with clever approximations: KernelSHAP (a weighted regression over sampled subsets, for any model) and TreeSHAP (an exact, fast algorithm for tree ensembles). Plotting many patients' SHAP values together gives global views too: a "beeswarm" plot shows each feature's contributions across the whole dataset.

Try it: Shapley values for a tiny model

The model is $f = 2x_1 + 3x_2 + 4x_1x_3$, explained against the baseline $(0, 0, 0)$. Move the sliders and watch the contributions. Set $x_3 = 0$ and see $x_1$'s share of the interaction disappear; set $x_1 = 0$ and $x_3$ gets nothing at all.

Local surrogates (LIME)

LIME (local interpretable model-agnostic explanations) explains one prediction by fitting a simple model, usually linear, that imitates the black box near that point: create many perturbed copies of the example, ask the black box to predict them, weight each copy by how close it is, and fit a weighted linear regression. Its slopes are the explanation:

from sklearn.linear_model import Ridge

# A LIME-style local explanation: fit a weighted linear model to the black box near one patient
rng = np.random.default_rng(0)
scale = X4.std(axis=0)
Z = x + rng.normal(0, 0.5, size=(2000, 4)) * scale          # perturbed copies of the patient
w = np.exp(-np.sum(((Z - x) / scale) ** 2, axis=1) / 2)        # nearer copies count more
local = Ridge(alpha=1e-3).fit((Z - x) / scale, model4.predict(Z), sample_weight=w)
print("local slopes (prediction change per +1 standard deviation):")
for f, c in zip(feats, local.coef_):
    print(f"{f:4}: {c:+7.2f}")

Output:

local slopes (prediction change per +1 standard deviation):
bmi :   +9.25
bp  :   +7.68
s5  :  +21.64
age :   +8.76

Near this patient, the model's prediction rises by about 22 units per standard deviation of s5 and by 7.7–9.3 units for the others. Notice these are slopes ("what if s5 increased a little?"), while the SHAP values above were contributions ("how much did this patient's s5 move the prediction from average?"). Both are valid; they answer different questions. LIME's results depend on choices such as the neighbourhood width and the sampling, and can change from run to run, which is why SHAP, with its guarantees, is more widely used.

How explanations mislead

  • Importance is not causation. A model may lean on a feature because it's correlated with the true cause. Changing that feature in the real world won't change the outcome (Lesson 4: correlation vs causation).
  • Correlated features share, split or hide credit. Methods that perturb one feature at a time also create unrealistic inputs.
  • Explanations describe the model, including its mistakes. If the model learned a shortcut (a watermark, a hospital ID), a faithful explanation shows the shortcut. That's a feature, not a bug: it's how shortcuts are found.
  • Different methods answer different questions (weights, drops in score, average curves, contributions, local slopes). Say which one you're reporting.
  • Simple, interpretable models (a short tree, a sparse linear model, a scorecard) are sometimes nearly as accurate as a black box. When the stakes are high, consider them first rather than explaining a black box afterwards (Rudin, 2019).

In Python: an explanation workflow

A typical sequence for a tabular model: check global importance on test data, look at the effect shape of the top features, then explain individual predictions.

import numpy as np
from sklearn.datasets import load_diabetes
from sklearn.model_selection import train_test_split
from sklearn.ensemble import GradientBoostingRegressor
from sklearn.inspection import permutation_importance, partial_dependence

d = load_diabetes()
X_tr, X_te, y_tr, y_te = train_test_split(d.data, d.target, test_size=0.3, random_state=0)
model = GradientBoostingRegressor(random_state=0).fit(X_tr, y_tr)

# 1. Global: which features does the model rely on? (on test data)
perm = permutation_importance(model, X_te, y_te, n_repeats=20, random_state=0, scoring="r2")
top = np.argsort(perm.importances_mean)[::-1][:3]
print("top features:", [d.feature_names[i] for i in top], np.round(perm.importances_mean[top], 3))

# 2. Shape: how does the prediction change with the most important feature?
pdr = partial_dependence(model, X_tr, [top[0]], grid_resolution=5, method="brute")
print("partial dependence:", np.round(pdr["average"][0], 1))

Output:

top features: ['s5', 'bmi', 'bp'] [0.221 0.181 0.043]
partial dependence: [103.4 129.  155.  186.5 194.5]

Shuffling s5 lowers the test $R^2$ the most (by 0.221), followed by BMI (0.181) and blood pressure (0.043), and the predicted progression rises steadily with s5, from about 103 to 195. For step 3, local explanations, install the shap library: shap.TreeExplainer(model)(X_te) gives exact SHAP values for tree models in milliseconds, and shap.plots.waterfall draws one prediction's contributions like the bars in the demo.

Key takeaways

  • Global explanations describe overall behaviour; local ones explain one prediction.
  • Linear weights are explanations only after standardising, and correlated features share their weight.
  • Permutation importance: the drop in test score when one feature is shuffled. Model-agnostic, but correlated features hide each other.
  • PDP and ICE show how the prediction changes with a feature, on average and per row; use ALE when features are strongly correlated.
  • SHAP values split prediction minus baseline into fair contributions that add up exactly; TreeSHAP makes them fast for tree models.
  • Explanations describe the model, not the world: importance is not causation.

1. Permutation importance measures…

Shuffling destroys the feature's information; a big drop means the model relied on it.

2. A model's baseline prediction is 100 and it predicts 130 for Priya. Her SHAP values must add up to…

Efficiency: contributions sum to prediction minus baseline.

3. In $f = 4x_1x_3$, explained at $x_1 = x_3 = 1$ against a baseline of 0, the SHAP value of $x_1$ is…

The interaction's credit is shared equally between the two features that create it.

4. A PDP shows predictions rising with "number of support calls". Can we conclude that more support calls cause customers to leave?

Unhappy customers call support and also leave; the calls may be a symptom, not a cause.

5. ICE curves for a feature are parallel lines at different heights. What does that suggest?

Parallel curves mean the same shape of effect for each row; crossing or diverging curves reveal interactions.
