Gradient descent

1Why we need it

Linear regression had a formula for the best weights. That's a lucky special case: logistic regression, neural networks and most of modern ML have no formula, and even linear regression's gets slow with many features. Gradient descent only needs to know which way is downhill, and it trains almost every model from here on, including the biggest networks.

$\mathbf{w}\leftarrow\mathbf{w}-\eta\,\nabla L(\mathbf{w})$

new parameters ← current parameters − learning rate × gradient (the gradient points uphill, so we subtract).

2A hiker in the fog

You can't see the valley, but you can feel the slope under your feet: step the steepest way down, feel again, repeat. Position = the parameters, altitude = the loss, feeling the slope = computing the gradient.

3The algorithm

  1. Initialise the parameters (zeros or small random numbers).
  2. Predict and compute the loss.
  3. Compute the gradient for every parameter.
  4. Update: subtract learning rate × its partial derivative.
  5. Repeat 2–4 until the loss stops improving.

4The gradient for linear regression

$\dfrac{\partial L}{\partial w}=\dfrac2n\sum(\hat y_i-y_i)\,x_i\qquad\dfrac{\partial L}{\partial b}=\dfrac2n\sum(\hat y_i-y_i)$

Each example "votes" in proportion to its error. Predictions too high on average → the $b$ gradient is positive → $b$ goes down. Too high where $x$ is large → lower the slope.

5Three steps by hand

Example from the lesson
Same data as Lesson 6 (answer: $w=0.6$, $b=2.2$). Start $w=b=0$, $\eta=0.05$.
Step 1: errors −2, −4, −5, −4, −5, loss 17.2. Gradients −26.4 and −8 → $w=1.32$, $b=0.4$.
Step 2: loss 1.646. Gradients now +5.04 and +0.72 (we overshot a little) → $w=1.068$, $b=0.364$.
Step 3: loss 1.105, and it keeps creeping towards the answer.

6The landscape demo

A contour map of the loss over $(w,b)$, like height lines on a hiking map. Try: learning rate above about 0.085 → diverges; very small → crawls; tick "standardise x" → the long narrow valley turns round and descent is much faster.

7Choosing the learning rate

It's your stride length: tiny shuffles are safe but slow; giant leaps can jump over the valley onto the other slope, and if big enough each bounce goes higher (divergence).

Example: $L(w)=w^2$
Gradient $2w$, so each step multiplies $w$ by $(1-2\eta)$. From $w=1$:
$\eta=0.1$ → ×0.8: 0.8, 0.64, 0.51… steady ✓
$\eta=0.5$ → ×0: lands on 0 in one step.
$\eta=0.9$ → ×(−0.8): bounces side to side but shrinks.
$\eta=1.1$ → ×(−1.2): bounces outwards → explodes.
Loss rising → nan?
The learning rate is too big. Lower it, and check the feature scaling.

8Why feature scaling matters

One feature 0–1, another 0–100,000 → the loss becomes a long, narrow valley. A rate safe for the steep direction is far too small for the flat one, so descent zigzags. Standardising makes the bowl round.

Example
Even $x$ = 1–5 (not centred) stretches the valley: at $\eta=0.05$, standardising cuts the steps needed from 190 to 47.

9When to stop

  • Fixed budget: a set number of steps or epochs (full passes over the data).
  • Tolerance: the loss improves by less than a tiny amount.
  • Early stopping: stop when the validation loss starts rising (overfitting).

Linear regression's loss is one bowl (convex), so every path ends at the same minimum. Neural networks have many valleys (local minima); in large networks these are usually good enough, but the start point and learning rate matter.

10Batch, stochastic, mini-batch

  • Batch: all $n$ examples per step. Exact gradient, smooth path, slow per step on big data.
  • Stochastic (SGD): 1 random example. Very cheap, noisy zigzag; the noise can help escape bad spots.
  • Mini-batch: e.g. 32–256. Best of both and efficient on GPUs: the standard for neural networks.

Why noisy steps still work: a random sample's gradient points the right way on average, like asking a few random people for directions instead of polling the whole town.

★Going deeper: modern optimisers and learning-rate schedules

Why plain gradient descent is slow: narrow valleys

You're walking down a long, narrow canyon in fog. The side walls are very steep, the floor slopes gently towards the exit. If you take big steps, you bounce from wall to wall. So you take tiny steps, but then you crawl along the floor. That's plain gradient descent on a badly shaped loss.

How many steps?
Goal: shrink the error 1,000 times.
Valley with $\kappa=10$: each step keeps $1-1/10=0.9$ of the error. $0.9^{66}\approx 0.001$, so about 66 steps.
Valley with $\kappa=1000$: each step keeps $0.999$. You need $0.999^{n}\approx0.001$, so about 6,900 steps.
Same goal, 100× more work, only because the valley is thinner.

Momentum: a ball rolling downhill

Instead of a careful walker, roll a heavy ball. It remembers which way it was going. Pushes that keep flipping left-right cancel out; a push that keeps pointing forward builds up speed.

Adaptive learning rates: RMSProp and Adam

A sound engineer with many sliders. Loud channels get turned down, quiet ones turned up, so every channel ends up at a sensible level. Adam does this for every weight's step size.

Adam's first step
Weight A has gradient 100, weight B has gradient 0.01. Plain gradient descent with $\eta=0.1$ would move A by 10 and B by 0.001: 10,000× apart.
Adam, step 1, weight A: $m = 0.1\times100 = 10$, $s = 0.001\times100^2 = 10$.
Without correction: $m/\sqrt{s} = 10/3.16 = 3.16$, a step 3× too big, only because $m$ and $s$ started at zero.
With correction: $\hat m = 10/(1-0.9) = 100$, $\hat s = 10/(1-0.999) = 10{,}000$, so $\hat m/\sqrt{\hat s} = 100/100 = 1$.
Step for A $= 0.1\times1 = 0.1$. Do the same for B: also $0.1$. Both weights move the same sensible amount, however different their gradient sizes.

Learning-rate schedules

Parking a car: drive fast on the road, slow down near the space, creep the last metre. A schedule does the same with the learning rate.

The decay $0.05/(1+t/200)$
Step 0: $0.05/(1+0) = 0.05$ (full speed).
Step 200: $0.05/(1+1) = 0.025$ (half).
Step 1,000: $0.05/(1+5) \approx 0.0083$ (one sixth).
Fast at the start, slower and slower later, but never exactly zero, so it can still reach anywhere.

Gradient clipping

A speed limiter on a car: you can still steer anywhere, but you can't go faster than the limit.

Clip to length 1
Gradient $(300, -400)$. Length $=\sqrt{300^2+400^2} = 500$.
Limit $c=1$, so the scale factor is $\min(1, 1/500) = 0.002$.
New gradient $= (300\times0.002,\ -400\times0.002) = (0.6, -0.8)$. Length 1, same direction.
A short gradient, e.g. length 0.5, gets factor $\min(1, 2)=1$: unchanged.
In one breath
Momentum smooths the zig-zag, Adam gives every weight its own step size, schedules shrink the steps so training settles, and clipping caps the occasional giant step. For a first deep network: AdamW, learning rate about $10^{-3}$, warm-up then decay, clipping at 1.
✎ in one line: step downhill, pick the step size carefully, scale the features, and use momentum/Adam and a schedule for big models.
