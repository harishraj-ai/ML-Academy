Interpretability & explainable ML

1Why explain a model?

A loan is refused and the applicant asks why; a regulator asks how decisions are made; a data scientist wonders whether the model learned something real or a shortcut (a pneumonia model that "reads" the hospital's name printed on the X-ray). Accuracy answers none of these.

  • Global: how does the model behave overall? Which features matter, and how?
  • Local: why this prediction for this person?

2Reading linear models properly

Weights are the explanation, but only on comparable scales. Standardise first: each weight then = change in log-odds per one standard deviation.

Example
Breast-cancer data (1 = benign): the five largest standardised weights are all negative; larger "worst" tumour measurements push away from benign.
Correlated features share and swap weight (radius, perimeter and area are nearly the same measurement). Regularization shrinks weights. A weight is association, not cause.

3Permutation importance

How much worse does the model get if a feature's information is destroyed? Shuffle one test column (keeps its distribution, breaks its link to the target), measure the score drop, repeat and average.

Example
Random forest: shuffling "worst radius" drops accuracy most, by 0.021. Drops are small because correlated features cover for each other.

Use test data (training data inflates it with overfitting).

4Partial dependence and ICE

Importance says how much, not how. A PDP sets the feature to $v$ for every row, predicts and averages:

$\text{PD}(v)=\frac1n\sum_if(v,\mathbf{x}_{i,\text{other}})$

An ICE plot draws one curve per row, showing whether people respond differently.

Example
Diabetes progression: the average prediction rises from about 131 to 210 as BMI goes from low to high, with a jump mid-range; ICE curves are spread by about 40–49.

With strongly correlated features, PDPs use unrealistic combinations: prefer ALE plots.

5SHAP values: fair credit

Split prediction − average prediction into one contribution per feature, using the Shapley value from game theory: features are players, the prediction is the payout, and each feature gets its average extra contribution over every order of joining.

$\phi_j=\sum_{S\subseteq F\setminus\{j\}}\frac{|S|!\,(p-|S|-1)!}{p!}\big[v(S\cup\{j\})-v(S)\big]$

The only "fair" split: contributions add up exactly (efficiency), identical features get equal credit, a feature that never matters gets 0.

Examples
Baseline 100, Priya's prediction 130 → her SHAP values sum to 30.
$f=4x_1x_3$ at $x_1=x_3=1$ (baseline 0) → the interaction's 4 is shared: 2 each.

TreeSHAP computes exact values quickly for tree models.

6The Shapley demo

$f=2x_1+3x_2+4x_1x_3$ against baseline (0, 0, 0). Set $x_3=0$ and $x_1$'s share of the interaction disappears; set $x_1=0$ and $x_3$ gets nothing.

7LIME: local surrogates

Explain one prediction with a simple model that imitates the black box nearby: perturb the example, predict the copies, weight by closeness, fit a weighted linear regression. Its slopes are the explanation.

Example
Near one patient: about +22 per standard deviation of s5, 7.7–9.3 for the others.

LIME gives slopes ("if s5 rose a little"); SHAP gives contributions ("how far this patient's s5 moved the prediction from average"). Both valid, different questions. Check LIME is stable across runs.

8How explanations mislead

  • Importance ≠ causation: the model may lean on something correlated with the cause.
  • Correlated features share, split or hide credit; one-at-a-time perturbations create unrealistic inputs.
  • Explanations describe the model, mistakes included. A faithful explanation shows a shortcut: that's how shortcuts are found.
  • Different methods answer different questions: say which one you report.
Support calls and churn
A PDP shows churn rising with support calls. Calls don't necessarily cause churn: unhappy customers call and leave.

For high stakes, consider a model that's simple enough to read directly (a short tree, a sparse linear model, a scorecard).

★Going deeper: when features are correlated

Three methods, three answers

Two witnesses who saw exactly the same thing. Ask "how much does the case rely on witness A?" (shuffle A) and the answer is "a lot". Ask "how much would we lose without witness A?" (drop A) and the answer is "nothing, B can say the same". Both answers are true.

Reading the two rows
Permutation: a 1.045, b 0.129. The forest uses both, a much more.
Drop-column: a 0.004, b 0. Remove either and the model uses the other.
c: 0.117 when dropped, because its information is unique.

Exact SHAP for linear models, and global SHAP

For a straight-line model, a feature's share of a prediction is simple: its weight times how far this row's value is from average. Sum those shares, add the average prediction, and you get exactly the prediction.

One house
Weight for size $w=3$; this house's size 5, average 3: $\phi=3\times2=+6$.
Weight for age $w=-1$; this house 4, average 2: $\phi=-1\times2=-2$.
Average prediction 100 → this prediction $100+6-2=104$. Exactly the model's output.
In one breath
With correlated features, permutation, drop-column and SHAP answer different questions, so say which one you used and report correlated features as a group; for linear models SHAP is simply weight × distance from average, and the shares always add up to the prediction.
✎ in one line: shuffle-and-see for global importance, SHAP for local credit, group correlated features, and never read importance as cause.
