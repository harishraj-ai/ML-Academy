Imbalanced data & anomaly detection

1When what you care about is rare

Fraud ~1 in 1,000 transactions; machine failure 1 in 10,000 readings; a rare disease 1 in 500 patients. A model that never predicts the rare class is 99.9% accurate and useless.

  • Some labelled rare cases → imbalanced classification: right metrics, then thresholds, weights or resampling.
  • Few or no labels → anomaly detection: find points that don't look like the rest.

2Why accuracy fails, in numbers

Example from the lesson (1% positives)
"Always normal": 99.0% accurate, catches 0 of 100 positives.
Logistic regression: 99.5% accurate, catches 52%. Accuracy hides almost everything that matters.

Use instead: recall (share caught), precision (share of alerts that are real), average precision (compare with its baseline, the positive rate: 0.01 here), or a cost metric (rupees saved, alerts per analyst per day).

3Thresholds, weights, resampling

  • Move the threshold: flag above 0.1 instead of 0.5.
  • Class weights: positives count more in the loss (class_weight="balanced").
  • Resampling: oversample positives (repeat) or undersample negatives (drop) in the training data.
Example
Threshold 0.5 → 0.1: recall 0.52 → 0.76 at precision 0.49, with the same average precision (0.746), since the ranking didn't change.
Try in this order
A good model + a threshold tuned on validation data first. Weights and resampling mostly just move the threshold, can hurt the ranking, and distort the probabilities.

4SMOTE

Repeating the same positives invites memorising. SMOTE creates new ones: pick a positive, pick one of its $k$ nearest positive neighbours, place a point at a random spot on the line between them.

Example
9,800 synthetic positives: same recall as oversampling (0.900), slightly better precision (0.169) and average precision (0.515), still below the plain model with a tuned threshold.
Resample only the training folds. Before splitting, near-copies land on both sides → leakage.

5Anomaly detection without labels

Model what's normal and flag what isn't:

  • z-scores: more than ~3 sd from the mean. Assumes one bell; outliers inflate the very sd used to find them.
  • IQR rule: beyond 1.5 × IQR outside the middle half. Robust, one feature at a time.
  • Isolation Forest: random trees with random splits; anomalies are few and different, so they're isolated in very few splits.
  • LOF: compare each point's local density with its neighbours'. Much sparser = anomaly; handles several clusters.

6The demo

Score = distance to the 5th nearest neighbour (the idea behind LOF). Flag more points: recall rises, precision falls.

7Running a detector

  • Get some labels: a few hundred reviewed cases let you measure precision at the top of the list.
  • Split by time: fraud and failures change.
  • Combine: a supervised model for known patterns, unsupervised for new ones; analysts' decisions become the next labels.
  • Set the alert budget: 200 reviews a day → flag the top 200; capacity sets the threshold.
  • Watch for feedback: you only learn about cases you flagged. Randomly review some unflagged ones to see what you miss.

★Going deeper: fixing probabilities, how isolation works

Undoing class weights: the prior correction

Balanced weights make the model act as if positives were 50%, so its probabilities are far too high. With the real positive rate $\pi$:

$\text{odds}_{\text{real}}=\dfrac{p}{1-p}\cdot\dfrac{\pi}{1-\pi},\qquad p_{\text{real}}=\dfrac{\text{odds}_{\text{real}}}{1+\text{odds}_{\text{real}}}$

Example from the lesson
Balanced model: average risk 0.372 vs true rate 0.020, Brier 0.1702. After the correction: average 0.017, Brier 0.0178, almost matching an unweighted model (0.0169).

Apply it (or recalibrate with CalibratedClassifierCV) before using outputs as risks: pricing, expected loss, telling a patient their risk.

Why random splits isolate anomalies

Each tree picks a random feature and a random split value until every point is alone. A far-away point is cut off by one of the first few splits.

Example
Among 500 points: the far point is isolated in 2.3 splits on average, typical points in 14.6.

The path length becomes a 0–1 score, normalised by the expected path for $n$ points (about $2\ln n$). No distances are computed, so it scales linearly and copes with many features. Settings: number of trees and subsample size (256 by default is enough, since anomalies stand out even in small samples).

✎ in one line: forget accuracy, tune the threshold first, resample only inside training, correct the probabilities, and check what you didn't flag.
