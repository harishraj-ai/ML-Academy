Part 6 · Lesson 23

Hyperparameter tuning & model selection

1Parameters vs hyperparameters

Parameters
learned from data during training
(weights, split points)
Hyperparameters
chosen before training, control how it learns
(λ, k, max depth, C and γ, learning rate)

Good hyperparameters often matter more than the algorithm. But every time you try a setting and look at a score, you learn a bit about the evaluation data, so careless tuning gives scores that are too good to be true.

2Validation curves

Vary one hyperparameter; plot training and CV scores.

Example: RBF SVM's γ, breast-cancer data
γ = 0.0001: both low (0.794 / 0.796) → too smooth, underfits.
γ = 1: training perfect, CV collapses to 0.631 → memorises.
Best in between: γ = 0.01, 0.968.

Values span orders of magnitude, so always search on a log scale (0.0001, 0.001, 0.01…).

3Grid search

Try every combination, score each with CV, keep the best, refit on all training data (GridSearchCV). Inside a pipeline, names look like svc__C.

How much work?
4 values of C × 4 of γ = 16 settings × 5 folds = 80 fits + 1 refit = 81.
A third hyperparameter with 5 values: 401. Five hyperparameters of 5 values: 15,626. Grids explode.

4Random search

Sample each hyperparameter from a distribution (loguniform for anything spanning orders of magnitude).

Usually only one or two hyperparameters really matter. A 4×4 grid tries 4 values of each; 16 random draws try 16 values of every one (Bergstra & Bengio, 2012).

Example
16 random draws: CV 0.981, test 0.951, about the same as the grid here. Random search's advantage grows with more hyperparameters.

5The demo

One important knob (left–right), one that barely matters (up–down). Notice how few distinct values of the important knob the grid tests.

6Smarter searches

  • Bayesian optimisation: fit a cheap surrogate of "score vs hyperparameters" (a Gaussian process, or Optuna's TPE), then pick the next setting balancing exploitation (near the best) and exploration (where it's unsure). Shines when each run is expensive.
  • Successive halving: start many candidates on a small budget (few rows / epochs / trees), keep the best third, triple their budget, repeat. In the lesson, 48 candidates start on 20 rows each and 16 survive the first round.

7Report honestly: nested CV

The best search score is the best of many tries on the same folds, so it's optimistic. Wrap the whole search in an outer CV loop.

Example
Nested CV: 0.979 (± 0.007 across outer folds) for the complete "tune, then fit" procedure.

Report that (or a test set used once). The deployed model still comes from one search on all the training data.

8The simplest good model

CV scores are noisy. The one-standard-error rule: pick the simplest model within one standard error of the best.

Example
Tree depth 5: 0.941 (SE 0.012). Depth 4: 0.929, within one SE → prefer the shallower tree.

Also weigh prediction speed and cost, calibration, fairness across groups, and ease of maintenance.

✗ choosing hyperparameters from test scores · ✗ linear scale for λ or learning rate · ✗ scaling/selecting features outside the CV loop · ✗ reporting the best search score as final

★Going deeper: Bayesian optimisation from scratch

The surrogate: a Gaussian process

A GP is a probability distribution over smooth functions. Given a few results it predicts a mean $\mu(x)$ and an uncertainty $\sigma(x)$ everywhere: confident near tried points, unsure far away. Its smoothness comes from a kernel (here Matérn), with the length scale learned from the data.

Choosing the next trial: expected improvement

With best-so-far $f^*$ and $z=(\mu-f^*)/\sigma$:

$\text{EI}(x)=(\mu-f^*)\,\Phi(z)+\sigma\,\phi(z)$

First term: a high predicted score (exploitation). Second: high uncertainty (exploration). Each round: fit the GP, pick the largest EI, evaluate, repeat.

Example from the lesson (gap to the true best, average of 20 runs; a narrow peak over log learning rate)
5 trials: BO 0.130 vs random 0.119 (no better yet: 3 are random starts).
10 trials: BO 0.0103 vs random 0.0510 (5× closer).
15 trials: BO finds the peak every time; random still 0.026 away.

Best when trials are expensive, you can afford only tens of them, and the space is low-dimensional.

In practice

  • Dimensions: GPs up to ~10–20 hyperparameters; Optuna's TPE copes better with many, categorical and conditional ones ("number of layers", then a width per layer).
  • Noise: model it (white-noise term / alpha) or it chases lucky trials.
  • Parallelism: random search parallelises trivially; BO is sequential and needs tricks.
  • Pruning: a smart sampler + early stopping of bad trials (Optuna pruners, Hyperband) gives the biggest savings.
✎ in one line: tune with CV on a log scale, prefer random or Bayesian search, report nested CV, pick the simplest good model.
