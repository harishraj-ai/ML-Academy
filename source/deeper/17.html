Going deeper: choosing components, and non-linear maps

Intermediate · skip on a first read

PCA finds the best flat summary of the data. This section shows how to decide how many components to keep, what reconstruction error tells you, and what to do when the structure is curved: kernel PCA for features, and t-SNE and UMAP for pictures, including how to read those pictures without being misled.

You'll need: this lesson, and eigenvectors and the SVD from Lesson 2's "Going deeper".

How many components?

Keeping $k$ components has an exact cost: the reconstruction error, how far each point is from its projection back into the original space, equals the variance in the components you dropped. Projecting onto the top $k$ principal components gives the smallest possible error of any $k$-dimensional flat subspace (the Eckart–Young result from Lesson 2's "Going deeper"). Two components keep only 28.5% of the variance; 29 components are needed to keep 95%, and the relative reconstruction error is exactly 1 minus the variance kept (0.041 at 30 components, where 0.959 is kept). Common ways to choose $k$:

  • A variance target, such as 90–99%. Scikit-learn accepts it directly: PCA(0.95).
  • An "elbow" in the plot of explained variance against component number.
  • Best of all, when PCA feeds a model: treat $k$ as a hyperparameter and choose it by cross-validation of the whole pipeline.

Reconstruction error has a useful side job: anomaly detection. Points that the main components can't reconstruct well don't follow the usual pattern.

Kernel PCA: principal components in a curved space

PCA can only find flat directions. When classes sit on concentric circles, no straight direction separates them. Kernel PCA applies the kernel trick (Lesson 15's "Going deeper") to PCA: it finds principal components in a high-dimensional feature space, computed entirely through the kernel matrix.

Ordinary PCA's single component is useless for separating the inner and outer circles (0.450, worse than guessing). With an RBF kernel, the first kernel principal component separates them perfectly (1.000): in the kernel's feature space, "distance from the centre" becomes a straight direction. Kernel PCA needs the $n\times n$ kernel matrix, so like kernel SVMs it doesn't scale to very large datasets, and its components are hard to interpret.

t-SNE and UMAP: maps for looking, not features

t-SNE builds a 2-D map that keeps neighbourhoods: points that are close in the original space should stay close on the map. It turns distances into probabilities of being neighbours (in the original space using a normal curve whose width is set by the perplexity, roughly "how many neighbours to care about"; on the map using a heavier-tailed $t$-distribution), then moves the map points to make the two sets of probabilities match. UMAP has a similar goal, is faster, and keeps more of the global layout.

How well does each 2-D map keep similar digits together? A point's 5 nearest map neighbours share its label 97.6% of the time for t-SNE, against 60.3% for PCA's flat 2-D projection. That's why t-SNE pictures of the digits show ten neat islands. But read such maps carefully:

  • Distances between clusters mean little. t-SNE preserves local neighbourhoods, not global distances. Two islands far apart are not necessarily very different.
  • Cluster sizes mean little. t-SNE expands dense clusters and shrinks sparse ones.
  • Perplexity and the random seed change the picture. Try several values before trusting a pattern. Random noise can look clustered at low perplexity.
  • It's for looking, not for modelling. t-SNE has no transform for new points, and its axes have no meaning. Use PCA (or UMAP, which can transform new data) when you need features for a model.

Practical PCA notes

  • Fit PCA inside the pipeline, on training data only, so test data doesn't leak into the components (Lesson 5).
  • Standardise first when features have different units; otherwise the component directions are dominated by the features with the biggest numbers.
  • Whitening (PCA(whiten=True)) rescales each component to variance 1. It helps some models but also amplifies noise in the small components.
  • For huge or sparse data, use TruncatedSVD (works on sparse matrices, like TF-IDF text, where it's called latent semantic analysis), IncrementalPCA (in batches) or randomized SVD.
  • Autoencoders (Lesson 19) are a neural-network generalisation: an encoder squeezes the data through a small middle layer and a decoder reconstructs it. A linear autoencoder with squared error learns the same subspace as PCA.
