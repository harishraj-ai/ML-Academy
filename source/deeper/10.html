Going deeper: regularization in practice

The lesson above explains bias, variance, ridge and lasso. This section measures bias and variance directly, shows the one-line rule behind lasso's zeros, chooses the penalty automatically with cross-validation, explains why lasso is unstable with correlated features (and how elastic net fixes it), and covers two "hidden" regularizers: early stopping and the surprising double-descent curve.

Measuring bias and variance

The decomposition in this lesson says expected test error $=$ bias² $+$ variance $+$ noise. We can measure each part by simulation: draw many fresh training sets from the same source, fit the model to each, and look at the predictions at fixed test points. Their average compared with the truth gives bias²; their spread gives the variance. Below, a degree-9 polynomial is fitted with ridge to 20 noisy points from a sine curve (noise variance $0.3^2 = 0.09$), 300 times for each $\lambda$:

With almost no penalty, bias² is tiny (0.001) but the variance is huge (1.133): each training set gives a wildly different curve. A strong penalty ($\lambda = 10$) flattens every curve, so variance falls to 0.025 but bias² rises to 0.335. The best total, 0.240, is in between at $\lambda = 0.1$. This is the U-shaped trade-off from this lesson, now with real numbers.

Why lasso gives exact zeros: soft-thresholding

Consider one weight with the others held fixed, and suppose least squares alone would set it to $z$ (with standardised features). Adding the penalties gives closed-form answers:

$$\text{ridge: } w = \frac{z}{1 + \lambda}, \qquad \text{lasso: } w = \operatorname{sign}(z)\,\max\big(|z| - \lambda,\ 0\big)$$

Ridge scales every weight down by the same factor; it never reaches zero. Lasso subtracts a fixed amount and stops at zero: any weight whose least-squares value is smaller than $\lambda$ becomes exactly 0. This is called soft-thresholding.

With $\lambda = 1$, lasso turns 3.0 into 2.0, but 0.8 and −0.3 become exactly 0, while ridge halves everything. Lasso solvers such as scikit-learn's use coordinate descent: cycle through the weights, apply this rule to each in turn (using the current residuals), and repeat until nothing changes. It's fast, and it's why the lasso can be fitted for many values of $\lambda$ in one go (the "regularization path").

Choosing the penalty automatically

RidgeCV, LassoCV and ElasticNetCV fit a whole grid of penalties and pick the best by cross-validation, reusing work along the path so it costs little more than a single fit. Elastic net mixes the two penalties: $\lambda\big(\rho\lVert\mathbf{w}\rVert_1 + \frac{1-\rho}{2}\lVert\mathbf{w}\rVert_2^2\big)$, where $\rho$ is l1_ratio.

On the standardised diabetes data, cross-validation picks a fairly light lasso ($\alpha \approx 0.079$, keeping 9 of the 10 weights), and an elastic net that is mostly lasso ($\rho = 0.9$, keeping 8). That makes sense: with only 10 features and 442 patients, little regularization is needed. Remember from Lesson 5's "Going deeper" that the CV score at the chosen penalty is slightly optimistic; nested CV gives the honest estimate.

Lasso and correlated features: why elastic net exists

When two features carry almost the same information, lasso tends to keep one and drop the other, and which one it keeps can flip with small changes in the data. Here, a and b are two noisy measurements of the same quantity, equally useful. We refit lasso on 200 bootstrap samples:

Lasso kept only a 47 times, only b 63 times, and both 90 times. If you reported "lasso selected feature a" from one fit, the next dataset might well say b. The L2 part of elastic net makes the penalty strictly convex, which spreads the weight evenly over correlated features (0.89 each here) and keeps groups of related features together. So: use lasso when you believe only a few features matter and they aren't strongly correlated; use elastic net when features come in correlated groups (genes, pixels, words, survey questions). And never treat a single lasso fit's feature selection as stable truth: check it on bootstrap samples, as above.

Early stopping is regularization too

When a model is trained by gradient descent starting from zero weights, the weights grow gradually. Stopping early, when the validation loss stops improving, keeps them small, much like an L2 penalty. For linear regression the link is exact in a simple case: $k$ gradient-descent steps with learning rate $\eta$ behave approximately like ridge with $\lambda \approx 1/(k\eta)$. Fewer steps means stronger regularization. This is why early stopping is standard for neural networks (Lesson 19) and gradient boosting (Lesson 14), where the number of trees plays the role of the number of steps.

Double descent: when bigger models get better again

The classical U-curve says test error rises once a model is complex enough to fit the noise. Modern experiments found something extra: if you keep increasing the number of parameters past the point where the model can fit the training data exactly (the "interpolation threshold", roughly where parameters equal data points), the test error peaks there and then falls again. This is double descent.

The explanation: right at the threshold there's exactly one way to fit all the points, and it's usually a wild one. With many more parameters than needed, there are infinitely many perfect fits, and gradient descent (or the minimum-norm solution, the pseudo-inverse from Lesson 2's "Going deeper") picks the smoothest one: the one with the smallest weights. That's an implicit regularizer. It helps explain why huge neural networks generalise despite having far more parameters than examples. Explicit regularization (a well-tuned ridge penalty) largely removes the peak.
