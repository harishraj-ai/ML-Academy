15.Going deeper: drift alarms and champion–challenger tests

In plain wordsTwo monitoring traps: with enough data a drift test raises alarms about harmless tiny changes (measure the size of the shift instead), and a new model's small win on a test set is often just luck (check the interval before switching).

Intermediate · skip on a first read

New words for this section
  • KS test: checks whether two samples come from different distributions; gives a p-value.
  • PSI: population stability index: how far a distribution has moved (size, not certainty).
  • Champion / challenger: the model in production / the candidate replacement.
  • Canary / shadow deployment: trying a new model on a small share of traffic / running it silently alongside.

Significant is not the same as important

Picture it

With a precise enough scale, you can prove a bag of sugar weighs 0.1 g less than last week. True, and completely unimportant. Huge samples make tests "significant" for tiny changes; what matters is how big the change is.

The live data here is shifted by a tiny, harmless 0.03 standard deviations. Watch the KS p-value and the PSI as the live sample grows:

import numpy as np
from scipy import stats
rng = np.random.default_rng(1)
train = rng.normal(0, 1, 50000)
for n in [500, 5000, 50000]:
    live = rng.normal(0.03, 1, n)                                    # a tiny, harmless shift
    ks = stats.ks_2samp(train, live)
    edges = np.quantile(train, np.linspace(0, 1, 11)); edges[0], edges[-1] = -np.inf, np.inf
    e, a = np.histogram(train, edges)[0] / len(train), np.histogram(live, edges)[0] / n
    psi = float(np.sum((a - e) * np.log(a / e)))
    print(f"live sample {n:6d}: KS p-value {ks.pvalue:.3g}   PSI {psi:.4f}")

Output:

live sample    500: KS p-value 0.158   PSI 0.0289
live sample   5000: KS p-value 0.0375   PSI 0.0031
live sample  50000: KS p-value 1.08e-06   PSI 0.0021
Worked example — reading it
  1. 500 rows: p = 0.158, no alarm.
  2. 50,000 rows: the same tiny shift gives $p\approx10^{-6}$, an alarm about nothing.
  3. PSI stays tiny (below 0.03) throughout: it measures size, so it isn't fooled.

In production, alert on effect sizes (PSI, the KS statistic itself, the shift in standard deviations) with thresholds tied to impact, not on p-values, or every big feature will alarm every day.

Is the challenger really better?

Picture it

A new player scores two more goals than your star in one friendly match. Before dropping your star, ask whether that gap is bigger than ordinary match-to-match luck.

Bootstrap the test set (resample its rows with replacement many times, scoring both models on the same rows each time) to get an interval for the improvement:

from sklearn.metrics import roc_auc_score
m = 3000
y = rng.integers(0, 2, m)
champion = y * 1.0 + rng.normal(0, 1.2, m)                          # current model's scores
challenger = y * 1.0 + rng.normal(0, 1.1, m)                        # new model, slightly better
diffs = []
for _ in range(1000):                                               # bootstrap the AUC difference
    idx = rng.integers(0, m, m)
    diffs.append(roc_auc_score(y[idx], challenger[idx]) - roc_auc_score(y[idx], champion[idx]))
lo, hi = np.percentile(diffs, [2.5, 97.5])
print("AUC champion", round(roc_auc_score(y, champion), 3), " challenger", round(roc_auc_score(y, challenger), 3))
print("95% interval for the improvement:", round(lo, 3), "to", round(hi, 3))

Output:

AUC champion 0.725  challenger 0.728
95% interval for the improvement: -0.022 to 0.027
Worked example — reading it
  1. Challenger AUC 0.728 vs champion 0.725: +0.003.
  2. 95% interval for the improvement: −0.022 to +0.027.
  3. It includes 0 (and negative values), so the data can't tell them apart.

Switching would add risk for no proven gain. Stronger evidence comes from more test data, paired comparisons on the same rows (as here), and a shadow or canary deployment that measures the business outcome, not just the offline metric.

In one breath

Judge drift by its size (PSI, shift in standard deviations), not by p-values that alarm on anything with enough data; and replace the champion only when the bootstrap interval for the improvement is clearly above zero.

Hidden questions — answer in your head first, then open.

Your drift monitor alerts every day on several features. What's going wrong, and how do you fix it?

The trap: "Retrain every day."

Probably it alerts on p-values from large samples, so trivial shifts are significant. Alert on effect sizes (PSI, KS statistic, standardised mean change) with thresholds tied to business impact, prioritise features by importance to the model, aggregate over sensible windows, and confirm with performance metrics when labels arrive. Tune thresholds on historical data to an acceptable false-alarm rate.

Check your understanding: going deeper

1. With 50,000 live rows, a KS test gives p ≈ 0.000001 for a 0.03-standard-deviation shift. What should you conclude?

Large samples make trivial differences significant.

2. Why is PSI more useful than a p-value for drift alerts?

Effect sizes don't grow just because the sample does.

3. A challenger's AUC is 0.004 higher, with a 95% interval for the gain of −0.02 to 0.03. What should you do?

The improvement isn't distinguishable from noise.

4. Why compare champion and challenger on the same test rows?

Both models face the same hard and easy cases.

5. What's the strongest evidence that a new model is better for the business?

Offline metrics are only a proxy.
