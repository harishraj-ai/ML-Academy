New words for this section
  • Residual: actual value minus prediction: the model's miss for that row.
  • Standard error (SE): how much a weight would wobble if you collected a new sample.
  • t-statistic: weight ÷ SE: how many wobbles away from zero the weight is.
  • Confidence interval: a range of plausible values for the true weight.
  • Multicollinearity: features that move together, so their effects are hard to separate.
  • Leverage: how far a point's inputs are from the rest; far points pull the line strongly.

The four assumptions, and what each one buys you

Picture it

A line always fits; the question is whether its numbers can be trusted. The four assumptions are like a car's safety check: the car may still drive if one fails, but you shouldn't trust the speedometer.

Least squares always gives you a line. Whether you can trust its weights, standard errors and p-values depends on four assumptions about the errors $\varepsilon_i = y_i - (\mathbf{w}\cdot\mathbf{x}_i + b)$, remembered as LINE:

AssumptionIn plain wordsHow to checkIf it fails
LinearityThe average of $y$ really is a straight-line function of the features.Residuals vs predictions show no curve.Add features such as $x^2$ or $\log x$ (section 10), or use a non-linear model.
IndependenceOne error tells you nothing about the next one.Think about how the data was collected; for data in time order, plot residuals over time.Standard errors come out too small. Common with time series and repeated measurements of the same person.
NormalityErrors follow a bell curve.Histogram of residuals.Matters only for exact p-values in small datasets; with a few hundred points it hardly matters.
Equal spreadErrors are about as big for large predictions as for small ones (statisticians call this homoscedasticity).Residuals fan out as predictions grow.Weights are still fine on average, but standard errors are wrong. Fixes below.

Notice what is not on the list: the features and $y$ itself don't need to be bell-shaped; only the errors matter. And if all you want is good predictions, checked on a test set, none of these is strictly required. They matter when you start saying "bmi has a real effect".

Why squared error? Two classic answers

Picture it

If errors follow a bell curve, the most believable line is the one with the smallest total squared miss. Squared error isn't an arbitrary choice; it falls out of the bell curve.

1. It's the maximum-likelihood answer for bell-curve noise. If $y_i = \mathbf{w}\cdot\mathbf{x}_i + b + \varepsilon_i$ with $\varepsilon_i \sim \mathcal{N}(0, \sigma^2)$, the log of the probability of all the data is

$$\log L = -\frac{n}{2}\log(2\pi\sigma^2) - \frac{1}{2\sigma^2}\sum_{i=1}^{n}\big(y_i - \hat{y}_i\big)^2$$

The first part doesn't involve the weights, so making $\log L$ as large as possible is the same as making $\sum (y_i-\hat{y}_i)^2$ as small as possible: least squares is maximum likelihood under normal noise. (With heavier-tailed Laplace noise you get absolute error instead, i.e. median regression.)

2. The Gauss–Markov theorem. If errors have mean zero, are uncorrelated and have equal spread (normality not needed), then among all estimators that are linear in $y$ and unbiased, least squares has the smallest variance: it is "BLUE". The fine print matters: a biased estimator can do better overall, which is what ridge (Lesson 10) does.

How sure are we about each weight? Standard errors, p-values and intervals

Picture it

Ask ten different samples of patients and you'd get ten slightly different weights. The standard error says how much they would typically differ; a weight many standard errors from zero is very unlikely to be luck.

Fit the same model on a different sample and the weights wobble. The standard error (SE) measures how much. For least squares there's an exact formula:

$$\operatorname{Var}(\hat{\mathbf{w}}) = \sigma^2\,(X^\top X)^{-1}, \qquad \hat{\sigma}^2 = \frac{\text{SS}_{\text{res}}}{n - d - 1}$$

In words: the noise level times "how little information the features give about each weight". We divide by $n-d-1$ because $d+1$ weights were fitted from the same data. Each weight's SE is the square root of the matching diagonal entry. From it:

  • t-statistic $t=\hat w/\text{SE}$: how many wobbles the weight is from zero.
  • p-value: if the feature truly had no effect, the chance of a $|t|$ this big by luck.
  • 95% interval $\hat{w} \pm t^{*}\,\text{SE}$, with $t^*\approx1.97$ here (about 1.96 for large $n$).
Worked example — bmi's row by hand
  1. Weight about 520 with SE about 66.6.
  2. $t\approx520/66.6\approx7.81$: almost eight wobbles from zero.
  3. Interval $\approx520\pm1.97\times66.6$: about 389 to 651, nowhere near 0.

From scratch on the diabetes data (442 patients, 10 features); statsmodels prints the same table with sm.OLS(y, sm.add_constant(X)).fit().summary():

import numpy as np
from scipy import stats
from sklearn.datasets import load_diabetes

def ols(X, y):
    """Least squares plus standard errors, t, p-values and 95% intervals."""
    n, d = X.shape
    A = np.column_stack([np.ones(n), X])            # add the bias column
    w = np.linalg.solve(A.T @ A, A.T @ y)           # the usual weights
    resid = y - A @ w
    dof = n - d - 1                                 # data points minus parameters
    sigma2 = resid @ resid / dof                    # estimated noise variance
    se = np.sqrt(np.diag(sigma2 * np.linalg.inv(A.T @ A)))
    t = w / se                                      # how many SEs away from zero
    p = 2 * stats.t.sf(np.abs(t), dof)              # two-sided p-values
    tc = stats.t.ppf(0.975, dof)                    # 95% critical value
    return w, se, t, p, w - tc * se, w + tc * se

data = load_diabetes()
X, y, names = data.data, data.target, data.feature_names
w, se, t, p, lo, hi = ols(X, y)
print(f"{'':6}{'weight':>8}{'SE':>7}{'t':>7}{'p':>7}   95% interval")
for row in zip(["bias"] + names, w, se, t, p, lo, hi):
    print("{:6}{:8.1f}{:7.1f}{:7.2f}{:7.3f}   [{:7.1f}, {:7.1f}]".format(*row))

Three things a p-value does not mean
  • $p = 0.058$ is not "a 5.8% chance the feature is useless". It's the chance of data this extreme if it were useless.
  • A large p-value doesn't prove no effect: often there just isn't enough data, or the feature overlaps another.
  • A tiny p-value doesn't mean a large, useful or causal effect. With a million rows, trivial effects get $p<0.001$.
Worked example — reading three rows
  1. bmi: $t=7.81$, interval 389 to 651. Far from zero → a real effect.
  2. age: weight −10, interval −127 to +107. Crosses zero → can't even tell the direction.
  3. s1: big weight −792 but $p=0.058$, because its SE (416.7) is huge. Next subsection explains why.

When features overlap: multicollinearity and the VIF

Picture it

Two friends always arrive at parties together. If the party gets louder, you can't tell which one caused it. s1 and s2 (two cholesterol measures) are like that: the model knows their joint effect, not each one's.

s1 (total cholesterol) and s2 (LDL, most of total cholesterol) move together: correlation about 0.9. The model predicts well using either, so it can't decide how to split the credit; small changes swing it from one to the other, which shows up as huge standard errors.

The variance inflation factor for feature $j$: predict it from all the other features, note that $R_j^2$, and compute

$$\text{VIF}_j = \frac{1}{1 - R_j^2}$$

The weight's variance is multiplied by the VIF, so its SE by $\sqrt{\text{VIF}}$. Investigate anything above 5–10.

from sklearn.linear_model import LinearRegression

# VIF of feature j = 1 / (1 - R²) when feature j is predicted from all the other features
for j, name in enumerate(names):
    others = np.delete(X, j, axis=1)
    r2_j = LinearRegression().fit(others, X[:, j]).score(others, X[:, j])
    print(f"{name:4} VIF {1 / (1 - r2_j):5.1f}")

# Drop s2 and refit: s1's standard error shrinks, the fit barely changes
keep = [j for j, name in enumerate(names) if name != "s2"]
w2, se2, *_ = ols(X[:, keep], y)
print("s1 with s2:    weight", round(w[5], 1), " SE", round(se[5], 1))
print("s1 without s2: weight", round(w2[5], 1), " SE", round(se2[5], 1))
print("R² with s2:   ", round(LinearRegression().fit(X, y).score(X, y), 4))
print("R² without s2:", round(LinearRegression().fit(X[:, keep], y).score(X[:, keep], y), 4))

The key distinction

Multicollinearity hurts interpretation, not prediction. For predictions only, correlated features are mostly harmless. To say what each feature does, drop or merge overlapping features, collect more varied data, or use ridge (Lesson 10), which shares credit smoothly.

Worked example — VIF by hand
  1. Predict s1 from the other features: suppose $R^2=0.9$. VIF $=1/(1-0.9)=10$.
  2. If $R^2=0.98$: VIF $=1/0.02=50$.
  3. s1's actual VIF is 59.2, so its SE is $\sqrt{59.2}\approx7.7$× larger than it would be alone.
  4. Drop s2: SE falls from 416.7 to 114.0, while $R^2$ barely moves (0.5177 → 0.5155).

Adjusted $R^2$, and why cross-validation is better still

Picture it

Adding a column of random noise is like adding a student who guesses answers to a study group. Training $R^2$ always says the group got "better"; adjusted $R^2$ and cross-validation see through it.

Training $R^2$ can never fall when you add a feature, even pure noise: least squares can always find a little accidental pattern. Adjusted $R^2$ charges for each feature:

$$R^2_{\text{adj}} = 1 - (1 - R^2)\,\frac{n - 1}{n - d - 1}$$

Worked example — the charge in numbers ($n=442$)
  1. 10 features, $R^2=0.518$: $1-0.482\times441/431\approx0.507$.
  2. Suppose 30 features gave $R^2=0.560$: $1-0.440\times441/411\approx0.528$.
  3. A feature must beat chance to raise adjusted $R^2$.

Adding columns of random noise to the diabetes features:

from sklearn.model_selection import cross_val_score

n = len(y)
rng = np.random.default_rng(0)
print("noise cols  train R²  adjusted R²  5-fold CV R²")
for extra in [0, 10, 50, 100]:
    Xe = np.column_stack([X, rng.normal(size=(n, extra))])     # add columns of pure noise
    d = Xe.shape[1]
    r2 = LinearRegression().fit(Xe, y).score(Xe, y)
    adj = 1 - (1 - r2) * (n - 1) / (n - d - 1)
    cv = cross_val_score(LinearRegression(), Xe, y, cv=5, scoring="r2").mean()
    print(f"{extra:10d}  {r2:8.3f}  {adj:11.3f}  {cv:12.3f}")

Output:

noise cols  train R²  adjusted R²  5-fold CV R²
         0     0.518        0.507         0.482
        10     0.530        0.508         0.469
        50     0.582        0.516         0.398

How to read it: training $R^2$ climbs from 0.518 to 0.633 on pure noise; adjusted $R^2$ stays around 0.51; and cross-validated $R^2$ tells the whole truth, falling from 0.482 to 0.277. In ML practice, cross-validation (Lesson 9) is the more reliable test.

When errors fan out: unequal spread and the log transform

Picture it

A guess of a junior's salary might be off by ₹1 lakh; a senior's by ₹5 lakh. Errors that grow with size are natural for money. Taking the log turns "± 25%" into one constant error size.

Money-like targets (salaries, prices, sales) vary in proportion to their size, so residuals fan out and break the "equal spread" assumption. Simulated salary data built that way:

# Salaries whose spread grows with experience (simulated, in lakh per year)
rng = np.random.default_rng(2)
years = rng.uniform(0, 30, size=300)
salary = 4 * np.exp(0.06 * years) * rng.lognormal(0, 0.25, size=300)

def spread(x, target):
    """Fit a line, then compare residual spread for the lowest and highest third of x."""
    m = LinearRegression().fit(x[:, None], target)
    r = target - m.predict(x[:, None])
    low, high = x < np.quantile(x, 1/3), x > np.quantile(x, 2/3)
    return m, r[low].std(), r[high].std()

_, a, b = spread(years, salary)
print(f"raw salary: spread {a:.2f} (junior) vs {b:.2f} (senior)")
m_log, a, b = spread(years, np.log(salary))
print(f"log salary: spread {a:.3f} (junior) vs {b:.3f} (senior)")
k = m_log.coef_[0]
print(f"weight {k:.4f} -> each extra year multiplies salary by {np.exp(k):.3f}")

Output:

raw salary: spread 1.53 (junior) vs 5.20 (senior)
log salary: spread 0.220 (junior) vs 0.249 (senior)
weight 0.0591 -> each extra year multiplies salary by 1.061

How to read it: on the raw scale, senior residuals are 3.4 times more spread out than junior ones; after taking $\log(\text{salary})$ they're nearly equal. The log turns "±25%" into a constant "±0.25".

Reading a log model's weights. If $\log y = w x + b$, raising $x$ by 1 multiplies $y$ by $e^{w}$.

Two practical notes: converting predictions back with $e^{\hat y}$ gives roughly the median, slightly under the average. If you can't transform the target, use robust standard errors (statsmodels fit(cov_type="HC3")) or weighted least squares.

Worked example — reading a log weight
  1. Weight for experience: $w=0.0591$.
  2. $e^{0.0591}\approx1.061$, so each extra year means about 6.1% higher salary.
  3. Shortcut for small $w$: $100w\approx$ the percentage, here 5.9%.

Points that bend the line: leverage, Cook's distance and robust regression

Picture it

A see-saw: a child sitting far from the middle moves it much more than one near the centre. A point far out on the $x$ axis (high leverage) can tilt the whole line, especially if it's also off the line.

Two different things make a point stand out:

  • Outlier: its $y$ is far from the line (large residual).
  • High leverage: its $x$ is far from the others, so the line must pass close to it. Leverage $h_{ii}$ is the $i$-th diagonal entry of the hat matrix $H = X(X^\top X)^{-1}X^\top$ (the matrix that turns $\mathbf{y}$ into predictions); leverages average $(d+1)/n$.

A point is influential when it's both. Cook's distance combines them: how much all predictions would move if that point were deleted:

$$D_i = \frac{e_i^2}{(d+1)\,\hat{\sigma}^2}\cdot\frac{h_{ii}}{(1-h_{ii})^2}$$

In words: (how far off the line) × (how far out in $x$). Flag $D_i>1$, or $D_i>4/n$ for a sensitive check. 20 points follow $y = 2x + 5$ closely; one extra point sits far right, well below:

from sklearn.linear_model import HuberRegressor

rng = np.random.default_rng(1)
x = np.arange(1, 21, dtype=float)
y_ = 2 * x + 5 + rng.normal(0, 2, size=20)         # true line: y = 2x + 5
x = np.append(x, 40.0); y_ = np.append(y_, 20.0)   # one unusual point far to the right

A = np.column_stack([np.ones_like(x), x])
lev = np.diag(A @ np.linalg.inv(A.T @ A) @ A.T)    # leverage = diagonal of the hat matrix
w_ = np.linalg.solve(A.T @ A, A.T @ y_)
e = y_ - A @ w_
p_ = A.shape[1]
s2 = e @ e / (len(y_) - p_)
cooks = e**2 / (p_ * s2) * lev / (1 - lev) ** 2     # Cook's distance

print("slope, least squares with the point:   ", round(w_[1], 2))
print("slope, least squares without the point:", round(LinearRegression().fit(x[:-1, None], y_[:-1]).coef_[0], 2))
print("slope, Huber with the point:           ", round(HuberRegressor().fit(x[:, None], y_).coef_[0], 2))
print("leverage: median", round(np.median(lev), 3), "| unusual point", round(lev[-1], 3))
print("Cook's D: largest other", round(cooks[:-1].max(), 3), "| unusual point", round(cooks[-1], 2))

Output:

slope, least squares with the point:    0.75
slope, least squares without the point: 1.93
slope, Huber with the point:            1.85
leverage: median 0.065 | unusual point 0.576
Cook's D: largest other 0.099 | unusual point 12.73

What to do: first check for a data-entry mistake (wrong units are the classic). If genuine, report with and without it, or use robust regression: the Huber loss treats small residuals with squared error and large ones with absolute error, so one wild point can't dominate (HuberRegressor).

Worked example — what the diagnostics say
  1. With the far point: slope 0.75 instead of about 2.
  2. Its leverage 0.576 is about 9× the median.
  3. Cook's distance 12.73, far above 1; all other points below 0.1.
  4. Huber regression keeps the slope at 1.85, close to the truth.

Categorical features and the dummy-variable trap

Picture it

If every house is exactly one of Central, Suburb or Outskirts, then knowing two of the yes/no columns tells you the third. Keeping all three plus the bias term says the same thing twice.

A category such as a Chennai home's area (Central, Suburb, Outskirts) becomes 0/1 dummy columns (one-hot encoding, Lesson 20). With a bias term you must leave one out: every row has exactly one dummy equal to 1, so the three columns always add up to the column of ones, $X^\top X$ can't be inverted, and there's no unique answer.

Worked example — why the three dummies are redundant
  1. Central row: (1, 0, 0). Suburb: (0, 1, 0). Outskirts: (0, 0, 1).
  2. Each row sums to 1, exactly the bias column.
  3. So Central = 1 − Suburb − Outskirts: one column says nothing new.
import pandas as pd

df = pd.read_csv("houses.csv")
all3 = pd.get_dummies(df["area"], dtype=float)           # Central, Outskirts, Suburb
A = np.column_stack([np.ones(len(df)), df["size_m2"], all3])
print("columns:", A.shape[1], " independent columns (rank):", np.linalg.matrix_rank(A))

Xd = pd.get_dummies(df[["size_m2", "area"]], columns=["area"], drop_first=True, dtype=float)
m = LinearRegression().fit(Xd, df["price_lakh"])
for name, wt in zip(Xd.columns, m.coef_):
    print(f"{name:15}{wt:7.2f}")
print(f"{'bias':15}{m.intercept_:7.2f}")

Output:

columns: 5  independent columns (rank): 4
size_m2           0.61
area_Outskirts  -41.13
area_Suburb     -14.79
bias             22.98

How to read it: with all three dummies, 5 columns but rank 4. Dropping one with drop_first=True fixes it; the dropped category becomes the baseline. (Only 12 houses, so treat the numbers as an illustration.) Scikit-learn's LinearRegression won't crash with all dummies, but the weights aren't unique; with ridge or lasso the penalty makes them unique, so keeping all categories is normal there.

Worked example — reading dummy weights
  1. Drop Central: it becomes the baseline (weight 0).
  2. Outskirts weight −41.1 → about ₹41.1 lakh less than a Central home of the same size.
  3. Suburb weight −14.8 → about ₹14.8 lakh less.

Interview corner · intermediate

Hidden questions — answer in your head first, then open.

What are the assumptions of linear regression, and which of them do you need just to get good predictions?

The trap: Reciting the list without saying what each one is for.

Linearity, independent errors, normally distributed errors and equal error spread (LINE). For predictions checked on a test set, none is strictly required, although a badly wrong linearity assumption will show up as poor test error. The assumptions matter for inference: trusting standard errors, p-values and confidence intervals. Independence and equal spread affect the SEs most; normality matters only in small samples.

A feature's p-value is 0.4. Should you remove it from the model?

The trap: "Yes — it isn't significant."

Not automatically. A large p-value means the data can't pin the effect down, not that the effect is zero. It may overlap with another feature (check its VIF), the sample may be small, or domain knowledge may say it belongs. For prediction, decide with cross-validation; for explanation, report its confidence interval honestly instead of deleting it quietly.

Two features are 95% correlated. What happens to the model's predictions, and to its weights?

The trap: Saying the model becomes inaccurate.

Predictions are usually fine: the model only needs the shared information, and either feature carries it. The individual weights become unstable, with huge standard errors (high VIF), and can even flip sign between samples, so you can't interpret them. Fixes: drop or merge one feature, or use ridge regression, which splits the credit smoothly.

Why do we minimise squared error rather than, say, absolute error?

The trap: "Because squares are easier to differentiate."

That's part of it (it gives a closed-form solution), but the deeper reasons are statistical. If the noise is normal, least squares is the maximum-likelihood estimate. By the Gauss–Markov theorem, it is also the best linear unbiased estimator whenever the errors are uncorrelated with equal spread. Absolute error is the maximum-likelihood choice for heavier-tailed (Laplace) noise and is more robust to outliers; Huber loss is a compromise.

What's the difference between an outlier, a high-leverage point and an influential point?

The trap: Using the three words as if they meant the same thing.

An outlier has an unusual $y$ (large residual). A high-leverage point has unusual $x$ values (large diagonal entry of the hat matrix), so the line is forced to pass near it. An influential point actually changes the fit a lot when removed. That usually takes both: high leverage and off the line. Cook's distance measures influence directly.

You one-hot encode a 3-level category, keep all 3 columns, and fit ordinary least squares with an intercept. What goes wrong?

The trap: Expecting an error message every time.

The 3 dummies always sum to the intercept column, so $X^\top X$ is singular: the dummy-variable trap. The weights have no unique solution. Some solvers (including scikit-learn's) still return an answer, but the individual weights mean nothing. Drop one level (it becomes the baseline), or use regularization, which makes the solution unique.

Check your understanding: going deeper

1. A feature has $\text{VIF} = 10$. Compared with a feature unrelated to the others, its standard error is multiplied by about…

The VIF multiplies the variance of the weight; the standard error is its square root, so it grows by $\sqrt{10}$.

2. Which of these is not an assumption of linear regression?

Only the errors matter (LINE). Features can have any distribution: a 0/1 dummy is fine as a feature.

3. A model predicts $\log(\text{price})$, and the weight on bedrooms is $0.10$. One extra bedroom is linked to a price that is…

Adding 1 to the feature multiplies the price by $e^{0.10} = 1.105$, about 10.5% more.

4. A point has very high leverage but lies exactly on the line through the other points. Its Cook's distance is…

Cook's distance multiplies the squared residual by a leverage factor. A point on the line has residual ≈ 0, so deleting it hardly changes anything. It's unusual, but not influential.

5. A category has 4 values and the model has a bias term. How many dummy columns should ordinary least squares get?

Leave one out as the baseline. All 4 would always add up to the bias column (the dummy-variable trap).
