New words for this section
  • Component: a new direction made from a mix of the original features.
  • Explained variance: the share of the data's spread a component captures.
  • Reconstruction error: what's lost when you squeeze to $k$ components and back.
  • Perplexity: in t-SNE, roughly how many neighbours each point cares about.
  • Whitening: rescaling every component to the same spread.

How many components?

Picture it

Shrinking a photo: keep enough pixels to recognise the face and drop the rest. With PCA, what you lose is exactly the spread (variance) of the components you drop.

Keeping $k$ components has an exact cost: the reconstruction error (how far points are from their squeezed-and-restored versions) equals the variance of the dropped components. And the top $k$ components give the smallest possible error of any flat $k$-dimensional view (Eckart–Young, Lesson 2's Going deeper).

Worked example — explained variance by hand
  1. Component variances 6, 3, 1 (total 10).
  2. Keep 1: $6/10=60\%$ kept, 40% lost.
  3. Keep 2: $9/10=90\%$ kept; reconstruction error = the dropped 1, i.e. 10%.

On the 8×8 handwritten digits (64 pixels):

import numpy as np
from sklearn.datasets import load_digits, make_circles
from sklearn.decomposition import PCA, KernelPCA
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score

# How many components? Variance kept and reconstruction error on the digits (64 pixels)
X, y = load_digits(return_X_y=True)
pca = PCA().fit(X)
cum = np.cumsum(pca.explained_variance_ratio_)
for k in [2, 10, 20, 30, 40]:
    p = PCA(k).fit(X)
    rec = p.inverse_transform(p.transform(X))
    err = np.mean((X - rec) ** 2) / np.mean((X - X.mean(0)) ** 2)
    print(f"{k:2d} components: variance kept {cum[k - 1]:.3f}   relative reconstruction error {err:.3f}")
print("components needed for 95% of the variance:", int(np.searchsorted(cum, 0.95) + 1))

Output:

 2 components: variance kept 0.285   relative reconstruction error 0.715
10 components: variance kept 0.738   relative reconstruction error 0.262
20 components: variance kept 0.894   relative reconstruction error 0.106
30 components: variance kept 0.959   relative reconstruction error 0.041
40 components: variance kept 0.988   relative reconstruction error 0.012
components needed for 95% of the variance: 29

How to read it: 2 components keep only 28.5%; 29 are needed for 95%; and the error is always exactly 1 minus the share kept (0.041 at 30 components, where 0.959 is kept). Ways to choose $k$:

  • A variance target, e.g. 90–99%: PCA(0.95).
  • An "elbow" where the explained-variance curve flattens.
  • Best, when PCA feeds a model: tune $k$ by cross-validating the whole pipeline.

Bonus: reconstruction error is a simple anomaly detector. Points the main components can't rebuild well don't follow the usual pattern.

Kernel PCA: principal components in a curved space

Picture it

Points on two rings, one inside the other: no straight direction separates them. Lift them into a richer space with a kernel and "distance from the centre" becomes a straight direction that PCA can find.

Kernel PCA applies the kernel trick (Lesson 15's Going deeper) to PCA: it finds principal components in a huge feature space, computed entirely through the kernel matrix.

# Kernel PCA: a non-linear version that can "unroll" circles
Xc, yc = make_circles(n_samples=400, factor=0.3, noise=0.05, random_state=0)
for name, emb in [("ordinary PCA", PCA(1)), ("kernel PCA (RBF)", KernelPCA(1, kernel="rbf", gamma=5))]:
    z = emb.fit_transform(Xc)
    acc = cross_val_score(LogisticRegression(), z, yc, cv=5).mean()
    print(f"{name:17}: a linear classifier on the 1 new feature scores {acc:.3f}")

Output:

ordinary PCA     : a linear classifier on the 1 new feature scores 0.450
kernel PCA (RBF) : a linear classifier on the 1 new feature scores 1.000

How to read it: ordinary PCA's one component scores 0.450, worse than guessing. Kernel PCA's first component separates the rings perfectly (1.000). The costs: it needs the $n\times n$ kernel matrix, so it doesn't scale to huge data, and its components are hard to interpret.

t-SNE and UMAP: maps for looking, not features

Picture it

t-SNE is like a seating plan for a wedding: friends sit at the same table, but the distance between tables means very little, and table sizes are rearranged to fit the room. Great for seeing who belongs together; misleading if you measure the room.

t-SNE makes a 2-D map that keeps neighbourhoods. It turns distances into "probability of being neighbours" (in the original space with a bell curve whose width is set by the perplexity; on the map with a heavier-tailed curve), then moves the map points until the two sets of probabilities match. UMAP has a similar goal, is faster, and keeps more of the overall layout.

from sklearn.manifold import TSNE
from sklearn.neighbors import KNeighborsClassifier

# Compare 2-D maps: how well do a point's map neighbours share its digit label?
maps = {"PCA, 2-D": PCA(2).fit_transform(X),
        "t-SNE, 2-D": TSNE(2, perplexity=30, random_state=0, init="pca").fit_transform(X)}
for name, Z in maps.items():
    acc = cross_val_score(KNeighborsClassifier(5), Z, y, cv=5).mean()
    print(f"{name:10}: 5-nearest-neighbour accuracy in the map {acc:.3f}")

Output:

PCA, 2-D  : 5-nearest-neighbour accuracy in the map 0.603
t-SNE, 2-D: 5-nearest-neighbour accuracy in the map 0.976

How to read it: a point's 5 nearest map neighbours share its digit 97.6% of the time with t-SNE vs 60.3% with PCA's 2-D view, which is why t-SNE pictures show ten neat islands. But read them carefully:

  • Gaps between islands mean little. Only local neighbourhoods are kept.
  • Island sizes mean little. Dense clusters are spread out, sparse ones shrunk.
  • Perplexity and the seed change the picture. Try several; random noise can look clustered.
  • It's for looking. t-SNE can't place new points and its axes mean nothing. Use PCA (or UMAP) for model features.

Practical PCA notes

  • Fit PCA inside the pipeline, on training data only (Lesson 5).
  • Standardise first when units differ, otherwise the biggest-numbered feature dominates.
  • Whitening (PCA(whiten=True)) gives every component spread 1; it helps some models but amplifies noise in small components.
  • Huge or sparse data: TruncatedSVD (works on sparse TF-IDF text, "latent semantic analysis"), IncrementalPCA, or randomized SVD.
  • Autoencoders (Lesson 19) generalise PCA with neural networks; a linear autoencoder with squared error learns the same subspace as PCA.
In one breath

Keep enough components to explain most of the variance (what you drop is exactly the error), use kernel PCA for curved structure, use t-SNE or UMAP only to look at data, and always fit PCA on training data after standardising.

Interview corner · intermediate

Hidden questions — answer in your head first, then open.

How do you choose the number of principal components?

The trap: "Always keep 95%."

Look at the cumulative explained-variance curve and the reconstruction error (they're the same information: error = variance dropped). A variance threshold (90–99%) or an elbow is a reasonable start. When PCA feeds a model, the best answer is to treat $k$ as a hyperparameter and pick it by cross-validating the whole pipeline. For visualisation, 2 or 3 components, accepting that much variance is lost.

What are the main pitfalls of interpreting t-SNE plots?

The trap: Reading cluster distances and sizes as meaningful.

t-SNE preserves local neighbourhoods, so between-cluster distances and cluster sizes are unreliable; results depend on perplexity and the random seed; noise can look clustered at low perplexity; and the axes mean nothing. Try several settings, colour by known labels, and confirm structure with other methods. It has no out-of-sample transform, so don't use it to create model features.

How can PCA be used for anomaly detection?

The trap: Only mentioning dimensionality reduction.

Fit PCA on normal data and keep enough components to describe typical variation. For each new point, project and reconstruct it; the reconstruction error measures how badly it fits the usual pattern. A threshold on that error (chosen on validation data) flags anomalies. It works well when normal data really does lie near a lower-dimensional subspace.

Check your understanding: going deeper

1. PCA with $k$ components keeps 93% of the variance. What is the relative reconstruction error?

The reconstruction error equals the variance in the dropped components: $1 - 0.93 = 0.07$.

2. Why can kernel PCA separate concentric circles when PCA can't?

It's PCA plus the kernel trick.

3. In a t-SNE map, two clusters are far apart. You can conclude that…

Global distances and cluster sizes on a t-SNE map are not reliable.

4. What does t-SNE's perplexity roughly control?

Low perplexity focuses on very local structure; high perplexity on broader structure.

5. Which method should you use to create features for a downstream model?

PCA has a transform for new data and stable, meaningful axes; t-SNE is for visualisation.
