New words for this section
  • Smoothing $\alpha$: pretend every word was already seen $\alpha$ extra times in each class.
  • Vocabulary $V$: the number of different words.
  • Log-odds: the log of (chance spam ÷ chance not spam).
  • Bigram: two neighbouring words treated as one feature, like "not good".
  • TF-IDF: word count, weighted down for words that appear in almost every document.
  • Generative / discriminative: models how each class produces data / models only where the boundary is.

Where smoothing comes from

Picture it

Naive Bayes multiplies one probability per word. If any word has probability 0, the whole product is 0, whatever the other words say. One unseen word acts like a veto. Smoothing removes the veto by giving every word a small starting count.

import numpy as np
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.naive_bayes import MultinomialNB

texts = ["win cash prize now", "cheap meds win big", "claim your free prize", "free cash offer now",
         "meeting moved to monday", "lunch on monday?", "project report attached", "see you at the meeting"]
labels = np.array([1, 1, 1, 1, 0, 0, 0, 0])                # 1 = spam
vec = CountVectorizer().fit(texts)
Xc = vec.transform(texts)
for alpha in [1e-10, 1.0]:
    nb = MultinomialNB(alpha=alpha).fit(Xc, labels)
    p = nb.predict_proba(vec.transform(["free lunch on monday", "win a free meeting"]))[:, 1]
    print(f"alpha {alpha:g}: P(spam) for the two new messages {p.round(3)}")

Output:

alpha 1e-10: P(spam) for the two new messages [0. 1.]
alpha 1: P(spam) for the two new messages [0.184 0.735]

How to read it: with essentially no smoothing ($\alpha=10^{-10}$) the answers are absurd, exactly 0 and 1, each decided by one unseen word. With $\alpha=1$ (Laplace smoothing) they become sensible: 0.184 and 0.735. The formula is

$$P(\text{word } j \mid c) = \frac{\text{count}_{j,c} + \alpha}{\text{total}_c + \alpha V}$$

Worked example — add-one smoothing
  1. "meeting" appeared 0 times among 20 spam words; vocabulary $V=10$.
  2. Without smoothing: $0/20=0$, a veto.
  3. With $\alpha=1$: $(0+1)/(20+10)=1/30\approx0.033$.
  4. A word seen 4 times: $(4+1)/30\approx0.17$ instead of $4/20=0.20$, pulled slightly towards average.

This isn't an arbitrary hack. It is exactly the Bayesian answer when you start with a prior belief that all words are equally likely (a Dirichlet prior, the many-word version of the Beta prior in Lesson 4's Going deeper). $\alpha$ is a regularization strength: tune it by cross-validation (0.01 to 1 is common for text).

Reading what the model learned

Picture it

Think of a spam score that starts at a fixed value. Each word in the message adds or subtracts its own fixed amount. Reading those amounts tells you exactly why a message was flagged.

For each word, $\log P(\text{word}\mid\text{spam}) - \log P(\text{word}\mid\text{ham})$ is how much it adds to the spam log-odds each time it appears:

# Which words push towards spam? The log-ratio log P(word | spam) − log P(word | ham)
nb = MultinomialNB(alpha=1.0).fit(Xc, labels)
ratio = nb.feature_log_prob_[1] - nb.feature_log_prob_[0]
words = vec.get_feature_names_out()
order = np.argsort(ratio)
print("most spam-like:", [(str(words[i]), float(round(ratio[i], 2))) for i in order[::-1][:4]])
print("most ham-like: ", [(str(words[i]), float(round(ratio[i], 2))) for i in order[:4]])

Output:

most spam-like: [('win', 1.07), ('cash', 1.07), ('now', 1.07), ('prize', 1.07)]
most ham-like:  [('monday', -1.12), ('meeting', -1.12), ('at', -0.72), ('attached', -0.72)]
Worked example — scoring a message
  1. Message: "win cash monday".
  2. Start from the prior log-odds, say 0 (equal classes).
  3. Add $1.07+1.07-1.12=1.02$. Positive → leans spam.
  4. Odds $e^{1.02}\approx2.8$, so about $2.8/3.8\approx74\%$ spam.

Notice the score is a weighted sum of word counts plus a constant: multinomial naive Bayes is a linear classifier, like logistic regression, but its weights come from counting instead of optimisation.

A realistic text pipeline

Picture it

Single words lose meaning: "not good" becomes "not" + "good", which sounds positive. And words like "the" appear everywhere, so they tell you nothing. A real pipeline fixes both.

  • Bigrams: word pairs as extra features, so "not good" stays together.
  • TF-IDF: term frequency × inverse document frequency. Words found in almost every document get a small weight; distinctive words a large one.
  • Complement naive Bayes: estimates each class's statistics from all the other classes. More stable when classes are imbalanced, and often better on text.
Worked example — the IDF part
  1. 1,000 documents. "the" is in all 1,000: IDF $=\log(1000/1000)=0$, ignored.
  2. "refund" is in 10: IDF $=\log(1000/10)=\log100\approx4.6$, a strong signal.
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.pipeline import make_pipeline
from sklearn.naive_bayes import ComplementNB

# A text pipeline: words and word pairs, TF-IDF weighting, then naive Bayes
pipe = make_pipeline(TfidfVectorizer(ngram_range=(1, 2)), ComplementNB(alpha=0.5)).fit(texts, labels)
for msg in ["claim your cash now", "report for the monday meeting"]:
    print(f"{msg!r:34} -> {'spam' if pipe.predict([msg])[0] else 'ham'}")
print("number of features (words and word pairs):", len(pipe[0].get_feature_names_out()))

Output:

'claim your cash now'              -> spam
'report for the monday meeting'    -> ham
number of features (words and word pairs): 47

Even with 8 training messages, the pipeline classifies both new messages correctly using 47 features (words plus word pairs). On real data with thousands of documents it trains in seconds and is a hard baseline to beat. Try logistic regression or a linear SVM on the same TF-IDF features too; modern alternatives use learned embeddings or a fine-tuned transformer (Lesson 19).

Generative vs discriminative models

Picture it

Two ways to tell spam from real mail. A generative model learns how each kind of email is written (what words spammers use, what words colleagues use), then asks which writer more likely wrote this one. A discriminative model never learns how emails are written; it only learns where to draw the line between them.

Naive Bayes learns $P(\mathbf{x}\mid y)$ and $P(y)$ and uses Bayes' theorem to get $P(y\mid\mathbf{x})$. Logistic regression models $P(y\mid\mathbf{x})$ directly. They can even be exact counterparts: Gaussian naive Bayes with a shared variance per feature gives a log-odds that is linear in $\mathbf{x}$, the same form as logistic regression.

A well-known study (Ng and Jordan, 2001) found that naive Bayes reaches its own best error with far fewer examples, while logistic regression needs more but ends lower when the independence assumption is wrong. In practice: with very few labelled examples, or as a quick baseline, try naive Bayes; with plenty of data, a discriminative model usually wins. Today's generative AI is the generative idea at enormous scale: models that can produce new text or images.

In one breath

Smoothing removes the veto of unseen words and is really a Bayesian prior; each word adds a fixed amount to the spam score, so the model is easy to read; real pipelines add bigrams and TF-IDF; and naive Bayes learns fast from little data, while logistic regression wins with more.

Interview corner · intermediate

Hidden questions — answer in your head first, then open.

Naive Bayes vs logistic regression for text: how do you choose?

The trap: Saying one is always better.

Naive Bayes trains by counting, needs very little data to reach its best accuracy, and handles huge vocabularies cheaply, but its independence assumption double-counts correlated words, so its probabilities are over-confident and its final accuracy is often lower. Logistic regression (or a linear SVM) on the same TF-IDF features usually wins with enough data and gives better-calibrated probabilities. Try both: they're cheap. NB is great as a baseline, for tiny datasets, or for streaming updates.

What is TF-IDF and why use it instead of raw counts?

The trap: Only giving the acronym.

Term frequency × inverse document frequency: a word's count in a document, multiplied by $\log(N/\text{df})$, where df is the number of documents containing it (implementations add smoothing). Very common words get weights near 0; distinctive words get more. Vectors are usually normalised to unit length, so long documents don't dominate. It gives linear models and kNN a much better representation than raw counts.

Why is the smoothing parameter α a regularization hyperparameter?

The trap: Thinking it only avoids division by zero.

It pulls every class's word distribution towards uniform, like a prior. A large α means estimates trust the prior more, giving simpler, less confident models (more bias, less variance); a tiny α trusts sparse counts, giving extreme, overfit probabilities. So it's tuned by cross-validation like any regularization strength.

Check your understanding: going deeper

1. Laplace smoothing in naive Bayes is the same as…

It's the posterior mean under a symmetric Dirichlet prior.

2. What does TF-IDF do to a word that appears in almost every document?

The inverse-document-frequency factor $\log(N/\text{df})$ is near 0 for very common words.

3. Multinomial naive Bayes's decision rule is…

The log-odds is a constant plus a sum of (log-ratio × count) over words.

4. Which model is generative?

It models $P(\mathbf{x}\mid y)$ for each class, then applies Bayes' theorem.

5. With only 30 labelled examples and 1,000 word features, a quick strong baseline is…

Generative models like naive Bayes typically reach their best accuracy with far fewer examples.
