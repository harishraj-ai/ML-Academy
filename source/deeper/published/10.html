New words for this section
  • Bias: being wrong on average, usually because the model is too simple.
  • Variance: how much the model changes when trained on different data.
  • Penalty strength $\lambda$ (alpha): how hard the weights are pushed towards 0.
  • Standardised: every feature rescaled to mean 0 and spread 1.
  • Bootstrap sample: a resample of the data, with repeats allowed.
  • Interpolation: fitting every training point exactly.

Measuring bias and variance

Picture it

Throw darts many times. Bias is how far the average landing spot is from the bullseye. Variance is how scattered the darts are. A model trained on many different training sets is like many darts.

Test error splits into three parts: bias² + variance + noise. We can measure each by simulation: draw many fresh training sets from the same source, fit the model on each, and look at the predictions at fixed test points. Their average vs the truth gives bias²; their spread gives variance. Below, a degree-9 polynomial with ridge is fitted to 20 noisy points from a sine curve (noise variance $0.3^2=0.09$), 300 times for each $\lambda$:

import numpy as np
from sklearn.preprocessing import PolynomialFeatures
from sklearn.linear_model import Ridge
from sklearn.pipeline import make_pipeline

# Measure bias² and variance directly: refit on 300 fresh training sets
rng = np.random.default_rng(0)
f = lambda x: np.sin(2 * np.pi * x)                   # the true curve
x_test = np.linspace(0, 1, 50)
for lam in [1e-6, 1e-3, 1e-1, 10]:
    preds = []
    for _ in range(300):
        x = rng.uniform(0, 1, 20); y = f(x) + rng.normal(0, 0.3, 20)
        m = make_pipeline(PolynomialFeatures(9), Ridge(alpha=lam)).fit(x[:, None], y)
        preds.append(m.predict(x_test[:, None]))
    preds = np.array(preds)
    bias2 = np.mean((preds.mean(axis=0) - f(x_test)) ** 2)
    var = np.mean(preds.var(axis=0))
    print(f"lambda {lam:7.0e}: bias² {bias2:.3f}   variance {var:.3f}   expected error {bias2 + var + 0.09:.3f}")

Output:

lambda   1e-06: bias² 0.001   variance 1.133   expected error 1.224
lambda   1e-03: bias² 0.028   variance 0.153   expected error 0.270
lambda   1e-01: bias² 0.100   variance 0.050   expected error 0.240
lambda   1e+01: bias² 0.335   variance 0.025   expected error 0.450
Worked example — reading the rows
  1. $\lambda=10^{-6}$ (almost no penalty): bias² 0.001, variance 1.133. Every curve is different and wild.
  2. $\lambda=10$ (strong penalty): variance 0.025, but bias² 0.335. Every curve is flat and wrong.
  3. $\lambda=0.1$: bias² 0.100 + variance 0.050 + noise 0.09 = 0.240, the best total.

This is the U-shaped trade-off from the lesson, with real numbers.

Why lasso gives exact zeros: soft-thresholding

Picture it

Ridge turns every weight's volume down by the same percentage: loud stays fairly loud, quiet becomes quieter, but nothing goes silent. Lasso subtracts a fixed amount from every weight: anything quieter than that amount becomes completely silent.

Take one weight with the others fixed, and say least squares alone would set it to $z$. Adding the penalty gives:

$$\text{ridge: } w = \frac{z}{1 + \lambda}, \qquad \text{lasso: } w = \operatorname{sign}(z)\,\max\big(|z| - \lambda,\ 0\big)$$

Read the lasso formula as: "take the size $|z|$, subtract $\lambda$, stop at 0, then put the sign back". This is called soft-thresholding.

# Lasso's key step: soft-thresholding, used by coordinate descent
soft = lambda z, t: np.sign(z) * np.maximum(np.abs(z) - t, 0)
for z in [3.0, 0.8, -0.3, -2.5]:
    print(f"least-squares value {z:5.1f} -> lasso value {soft(z, 1.0) + 0.0:5.1f}    ridge value {z / (1 + 1.0):5.2f}")

Output:

least-squares value   3.0 -> lasso value   2.0    ridge value  1.50
least-squares value   0.8 -> lasso value   0.0    ridge value  0.40
least-squares value  -0.3 -> lasso value   0.0    ridge value -0.15
least-squares value  -2.5 -> lasso value  -1.5    ridge value -1.25
Worked example — the four rows with $\lambda=1$
  1. 3.0: lasso $3-1=2.0$; ridge $3/2=1.5$.
  2. 0.8: lasso $\max(0.8-1,0)=0$; ridge $0.4$.
  3. −0.3: lasso 0; ridge −0.15.
  4. −2.5: lasso $-(2.5-1)=-1.5$; ridge −1.25.

Ridge never gives exactly 0; lasso does for every $|z|<1$.

Lasso solvers use coordinate descent: go through the weights one at a time, apply this rule using the current errors, and repeat until nothing changes. It's fast enough to fit many values of $\lambda$ in one go (the "regularization path").

Choosing the penalty automatically

Picture it

Try a whole ladder of penalty strengths, score each with cross-validation, and keep the best. The CV versions of ridge and lasso do this for you, reusing work between steps so it's barely slower than one fit.

Elastic net mixes both penalties: $\lambda\big(\rho\lVert\mathbf{w}\rVert_1 + \frac{1-\rho}{2}\lVert\mathbf{w}\rVert_2^2\big)$. Read $\rho$ (l1_ratio) as "how much lasso": 1 = pure lasso, 0 = pure ridge.

from sklearn.linear_model import LassoCV, ElasticNetCV
from sklearn.datasets import load_diabetes
from sklearn.preprocessing import StandardScaler

X, y = load_diabetes(return_X_y=True)
X = StandardScaler().fit_transform(X)
lasso = LassoCV(cv=5, random_state=0).fit(X, y)
enet = ElasticNetCV(l1_ratio=[0.1, 0.5, 0.9], cv=5, random_state=0).fit(X, y)
print("lasso: best alpha", round(lasso.alpha_, 3), " non-zero weights", np.sum(lasso.coef_ != 0), "of 10")
print("elastic net: best alpha", round(enet.alpha_, 3), " l1_ratio", enet.l1_ratio_, " non-zero", np.sum(enet.coef_ != 0))

Output:

lasso: best alpha 0.079  non-zero weights 9 of 10
elastic net: best alpha 0.217  l1_ratio 0.9  non-zero 8

How to read it: on the diabetes data, CV picks a light lasso (alpha 0.079, keeping 9 of 10 weights) and an elastic net that is 90% lasso (keeping 8). With 10 features and 442 patients little penalty is needed. Remember from Lesson 5's Going deeper: the CV score at the chosen setting is slightly optimistic; nested CV gives the honest figure.

Lasso and correlated features: why elastic net exists

Picture it

Two equally good twins apply for one job. Lasso hires exactly one of them, almost at random, and the choice can flip if you ask again. Elastic net hires both and splits the salary.

Here a and b are two noisy measurements of the same thing. Lasso is refitted on 200 bootstrap samples:

# Lasso with two almost identical features, on bootstrap samples: which one does it keep?
rng = np.random.default_rng(1)
from sklearn.linear_model import Lasso
n = 200
z = rng.normal(size=n)                                    # one underlying quantity…
a = z + rng.normal(0, 0.05, n); b = z + rng.normal(0, 0.05, n)   # …measured twice
yy = 3 * z + rng.normal(0, 1, n)
picks = {"only a": 0, "only b": 0, "both": 0}
for _ in range(200):
    i = rng.integers(0, n, n)
    w = Lasso(alpha=1.0).fit(np.column_stack([a, b])[i], yy[i]).coef_
    key = "both" if (w != 0).all() else ("only a" if w[0] != 0 else "only b")
    picks[key] += 1
print("lasso, 200 bootstrap samples:", picks)
from sklearn.linear_model import ElasticNet
w = ElasticNet(alpha=1.0, l1_ratio=0.5).fit(np.column_stack([a, b]), yy).coef_
print("elastic net weights on the full data:", w.round(2))

Output:

lasso, 200 bootstrap samples: {'only a': 47, 'only b': 63, 'both': 90}
elastic net weights on the full data: [0.89 0.89]
Worked example — reading the counts
  1. Only a kept: 47 times. Only b kept: 63 times. Both: 90 times.
  2. So "lasso picked a" from one fit is close to a coin flip.
  3. Elastic net gives both 0.89: the credit is shared evenly.

The L2 part of elastic net spreads weight over correlated features and keeps related groups together. Use lasso when you believe only a few, unrelated features matter; use elastic net when features come in correlated groups (genes, pixels, words, survey questions). Never treat one lasso fit's selection as stable: check it on bootstrap samples, as above.

Early stopping is regularization too

Picture it

Training starts with all weights at zero, and they grow step by step. Stop early and they haven't had time to grow big, just as if a penalty had held them back.

For linear regression the link is exact in a simple case: $k$ gradient-descent steps with learning rate $\eta$ behave roughly like ridge with $\lambda \approx 1/(k\eta)$.

Worked example — steps as a penalty
  1. $\eta=0.01$, $k=100$ steps: $\lambda\approx1/(100\times0.01)=1$.
  2. $k=1{,}000$ steps: $\lambda\approx0.1$, a weaker penalty.
  3. So more steps = less regularization.

That's why early stopping is standard for neural networks (Lesson 19) and gradient boosting (Lesson 14), where the number of trees plays the role of the number of steps.

Double descent: when bigger models get better again

Picture it

Test error first falls as the model grows, then rises as it starts fitting noise, peaking where it can just barely fit every training point. Keep growing it and, surprisingly, the error falls again.

Why? Right at the threshold there's exactly one way to fit every point, and it's usually wild. With many more parameters there are infinitely many perfect fits, and gradient descent (or the pseudo-inverse from Lesson 2's Going deeper) picks the one with the smallest weights, the smoothest. That's a hidden regularizer, and it helps explain why huge neural networks generalise. A well-tuned ridge penalty largely removes the peak.

In one breath

Bias is the average miss and variance the wobble, and you can measure both; lasso subtracts and so zeroes small weights while ridge only shrinks; choose the penalty by cross-validation; use elastic net for correlated features; early stopping acts like a penalty; and very large models can improve again past the interpolation peak.

Interview corner · intermediate

Hidden questions — answer in your head first, then open.

Describe how coordinate descent solves the lasso.

The trap: Saying it uses gradient descent (the L1 penalty isn't differentiable at 0).

Cycle through the weights one at a time. For weight $j$, compute the least-squares value it would take given the current residuals (with the other weights fixed), then apply soft-thresholding: shrink it towards 0 by $\lambda$ and set it to exactly 0 if it would cross. Update the residuals and move on. Repeat until the weights stop changing. Each step is closed-form, so it's fast, and warm starts make fitting a whole path of $\lambda$ values cheap.

How would you check whether the features lasso selected are trustworthy?

The trap: Trusting a single fit's non-zero weights.

Refit on many bootstrap samples (or CV folds) and record how often each feature is selected. This is the idea of stability selection. Features chosen in, say, over 80% of fits are robust; ones that flip are usually members of a correlated group. Check correlations or VIFs, and consider elastic net or reporting the group rather than one member.

Can you show that bias and variance trade off, rather than just asserting it?

The trap: Only drawing the U-curve.

Simulate: draw many training sets from the same distribution, fit the model to each, and evaluate at fixed test points. Bias² is the squared gap between the average prediction and the truth; variance is the spread of the predictions across fits. Sweeping model complexity or $\lambda$ shows bias² falling and variance rising as the model becomes more flexible, with the total error minimised in between.

Is early stopping really a form of regularization? Explain.

The trap: "It just saves time."

Yes. Starting from small weights, gradient descent first fits the strongest, smoothest patterns (large-eigenvalue directions) and only later the weak, noisy ones. Stopping early leaves the weights small along those weak directions, which is the same effect ridge has. For linear least squares the equivalence is approximately $\lambda \approx 1/(k\eta)$ for $k$ steps. The number of epochs (or of boosting rounds) is therefore a regularization hyperparameter, chosen on validation data.

Check your understanding: going deeper

1. With $\lambda = 2$, what does lasso's soft-thresholding turn a least-squares value of $1.5$ into?

$|1.5| - 2 < 0$, so the weight becomes exactly 0. (Ridge would give $1.5/3 = 0.5$.)

2. As $\lambda$ grows, what happens to bias² and variance?

A stronger penalty makes models simpler and more alike: more bias, less variance.

3. Why prefer elastic net over lasso when features come in correlated groups?

Lasso's choice within a correlated group is unstable; elastic net tends to keep the group together.

4. How is early stopping related to ridge regression?

Roughly, $k$ steps with learning rate $\eta$ act like ridge with $\lambda \approx 1/(k\eta)$.

5. In double descent, where does test error peak?

At the interpolation threshold there's a single, usually wild, exact fit. With many more parameters, the smoothest exact fit is chosen.
