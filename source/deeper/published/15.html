New words for this section
  • Margin: the empty road between the classes; the SVM makes it as wide as possible.
  • Slack $\xi_i$: how far point $i$ breaks into the margin.
  • Support vector: a point on or inside the margin; only these shape the boundary.
  • Dual problem: the same task rewritten with one weight $\alpha_i$ per training point.
  • Kernel: a similarity score that equals a dot product of hidden features.
  • Hinge loss: zero when a point is safely on the right side; grows when it isn't.

The dual problem and the KKT conditions

Picture it

Building a road between two villages: only the houses right at the edge of the road decide where it goes. Move a house far from the road and nothing changes. The dual problem makes this exact: every point gets a weight $\alpha_i$, and only the edge points get a weight above zero.

The SVM's goal, in words: make the road wide (small $\lVert\mathbf{w}\rVert$) while paying $C$ for every unit a point breaks into it ($\xi_i$). In symbols: minimise $\frac12\lVert\mathbf{w}\rVert^2 + C\sum_i \xi_i$ subject to $y_i(\mathbf{w}\cdot\mathbf{x}_i + b) \ge 1 - \xi_i$, $\xi_i\ge0$, with labels $\pm1$.

Using Lagrange multipliers (one $\alpha_i$ per point) and eliminating $\mathbf{w}$ and $b$ gives the equivalent dual problem:

$$\max_{\boldsymbol\alpha}\ \sum_i \alpha_i - \frac12\sum_{i,j}\alpha_i\alpha_j\,y_iy_j\,(\mathbf{x}_i\cdot\mathbf{x}_j) \quad\text{subject to } 0 \le \alpha_i \le C,\ \ \sum_i \alpha_i y_i = 0$$

and the weights come back as $\mathbf{w} = \sum_i \alpha_i y_i \mathbf{x}_i$: a weighted sum of training points. The KKT conditions (Lagrange multipliers for inequalities) tell us two things:

  • Only support vectors matter. Points safely outside the margin get $\alpha_i=0$ and vanish from $\mathbf{w}$. Points exactly on the margin have $0<\alpha_i<C$; points inside it or on the wrong side have $\alpha_i=C$.
  • The data appears only through dot products $\mathbf{x}_i\cdot\mathbf{x}_j$, in training and in prediction, $f(\mathbf{x}) = \sum_i \alpha_i y_i\,(\mathbf{x}_i\cdot\mathbf{x}) + b$. Swap that dot product for a kernel and you have the kernel trick.
Worked example — a prediction from three support vectors
  1. Support vectors with $\alpha_iy_i$ = +0.5, +0.5, −1.0 and $b=0.2$.
  2. Dot products with the new point: 2, 1, 0.5.
  3. $f=0.5\times2+0.5\times1-1.0\times0.5+0.2=1.2$. Positive → class +1.
  4. All the other training points had $\alpha=0$: no work needed for them.

The kernel trick, checked

Picture it

Instead of building a bigger map with many extra features and measuring there, use a shortcut formula that gives exactly the same answer from the original map. You get the benefit of the big map without ever drawing it.

The kernel $K(\mathbf{x}, \mathbf{z}) = (\mathbf{x}\cdot\mathbf{z} + 1)^2$ in 2-D equals an ordinary dot product of 6 features: $\phi(\mathbf{x}) = (1, \sqrt2 x_1, \sqrt2 x_2, x_1^2, x_2^2, \sqrt2 x_1x_2)$. Multiplying out $(x_1z_1 + x_2z_2 + 1)^2$ term by term gives exactly $\phi(\mathbf{x})\cdot\phi(\mathbf{z})$.

Worked example — the shortcut by hand
  1. $\mathbf{x}=(1,2)$, $\mathbf{z}=(3,1)$: $\mathbf{x}\cdot\mathbf{z}=3+2=5$.
  2. Kernel: $(5+1)^2=36$. One 2-D dot product and a square.
  3. The long way builds 6 features for each point and multiplies them: also 36.
import numpy as np

# The kernel trick: (x·z + 1)² equals the dot product of explicit degree-2 features
def phi(v):
    a, b = v
    return np.array([1, np.sqrt(2) * a, np.sqrt(2) * b, a * a, b * b, np.sqrt(2) * a * b])

x, z = np.array([1.0, 2.0]), np.array([3.0, -1.0])
print("kernel (x·z + 1)²:     ", (x @ z + 1) ** 2)
print("explicit φ(x)·φ(z):    ", round(phi(x) @ phi(z), 10))

Output:

kernel (x·z + 1)²:      4.0
explicit φ(x)·φ(z):     4.0

The code checks the same thing on other points: both ways give 4.0. For degree $p$ in $d$ dimensions the hidden feature space grows like $d^p$, and the RBF kernel corresponds to infinitely many features, yet the kernel costs one distance. A function can be a kernel exactly when every table of its values $K(\mathbf{x}_i,\mathbf{x}_j)$ is positive semi-definite (Mercer's condition, Lesson 2's Going deeper).

How C and gamma interact

Picture it

With the RBF kernel, every training point casts a "hill of influence". gamma sets how narrow each hill is (big gamma = tiny, pointy hills). C sets how strict you are about mistakes. Tiny hills plus strictness gives a boundary that wraps around single points: memorising.

The kernel is $K = \exp(-\gamma\lVert\mathbf{x}-\mathbf{z}\rVert^2)$.

Worked example — how gamma shrinks influence
  1. Two points at distance 2, so squared distance 4.
  2. $\gamma=0.1$: $e^{-0.4}\approx0.67$, still very similar.
  3. $\gamma=1$: $e^{-4}\approx0.018$, nearly unrelated.
  4. $\gamma=30$: $e^{-120}\approx0$; each point only "sees" itself.

So C and gamma must be tuned together, on a log grid:

from sklearn.datasets import make_moons
from sklearn.model_selection import train_test_split
from sklearn.svm import SVC

X, y = make_moons(n_samples=400, noise=0.3, random_state=0)
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.5, random_state=0)
print("    C   gamma   support vectors   train   test")
for C in [0.1, 1, 100]:
    for gamma in [0.1, 1, 30]:
        m = SVC(C=C, gamma=gamma).fit(Xtr, ytr)
        print(f"{C:5} {gamma:7}   {m.n_support_.sum():15d}   {m.score(Xtr, ytr):5.3f}   {m.score(Xte, yte):5.3f}")

Output:

    C   gamma   support vectors   train   test
  0.1     0.1               158   0.810   0.860
  0.1       1               127   0.885   0.895
  0.1      30               193   0.535   0.470
    1     0.1                95   0.860   0.870
    1       1                69   0.905   0.910
    1      30               158   0.915   0.900
  100     0.1                64   0.900   0.875

  • Large gamma + large C (30, 100): training 1.000, test 0.845. Memorised.
  • Large gamma + small C (30, 0.1): collapses to 0.470, nearly one class everywhere.
  • Moderate both ($C=1$, $\gamma=1$): 0.910, the best.

The number of support vectors is a handy warning light: when nearly every training point is one (193 of 200 here), the model hasn't found a simple boundary.

Hinge loss: the SVM as regularized loss minimisation

Picture it

Logistic regression keeps nudging even confident, correct points further from the line. The hinge loss stops caring the moment a point is safely past the margin. Otherwise the two are very similar.

The SVM can be rewritten without any constraints:

$$\min_{\mathbf{w}, b}\ \frac{1}{2C}\lVert\mathbf{w}\rVert^2 + \sum_i \max\big(0,\ 1 - y_i(\mathbf{w}\cdot\mathbf{x}_i + b)\big)$$

Read it as "a ridge-style penalty + hinge loss". $y_i f(\mathbf{x}_i)$ is how far the point is on the correct side.

Worked example — hinge loss for three points
  1. $yf=1.5$ (safely right): $\max(0,1-1.5)=0$.
  2. $yf=0.4$ (right, but inside the margin): $1-0.4=0.6$.
  3. $yf=-0.3$ (wrong side): $1+0.3=1.3$.

Logistic regression uses $\log(1+e^{-yf})$ instead, a smooth version that never reaches 0. So a linear SVM and L2-regularized logistic regression are close cousins:

from sklearn.svm import LinearSVC
from sklearn.linear_model import LogisticRegression

# Hinge loss and log loss give very similar linear boundaries
Xl, yl = make_moons(n_samples=400, noise=0.3, random_state=1)
svm = LinearSVC(C=1.0).fit(Xl, yl)
lr = LogisticRegression(C=1.0).fit(Xl, yl)
unit = lambda w: w / np.linalg.norm(w)
print("boundary direction, linear SVM:     ", unit(svm.coef_[0]).round(3))
print("boundary direction, logistic regr.: ", unit(lr.coef_[0]).round(3))
print("agreement on predictions:", np.mean(svm.predict(Xl) == lr.predict(Xl)))

Output:

boundary direction, linear SVM:      [ 0.384 -0.923]
boundary direction, logistic regr.:  [ 0.384 -0.923]
agreement on predictions: 1.0

On 400 points the two boundaries point the same way to three decimals and agree on every prediction. The real differences: the SVM ignores confident points, giving sparse support vectors but no probabilities; logistic regression uses every point and gives calibrated probabilities (Lesson 8's Going deeper). With kernels, the SVM's sparsity is what makes prediction fast.

Scaling up, and support vector regression

Picture it

A kernel SVM compares every training point with every other one. That's fine for a few thousand points, but with a million it's a trillion comparisons.

  • Cost. The kernel matrix is $n\times n$: about $O(n^2)$ memory and $O(n^2)$ to $O(n^3)$ time. Beyond about 100,000 points use a linear SVM (LinearSVC, SGDClassifier(loss="hinge")) or approximate the kernel with random features (RBFSampler, Nystroem) plus a linear model.
  • Support vector regression (SVR) puts a tube of width $\varepsilon$ around the predictions. Errors inside the tube cost nothing; only points outside it become support vectors.
Worked example — the size problem
  1. 10,000 points: $10^8$ kernel values, about 0.8 GB as 8-byte numbers. Manageable.
  2. 100,000 points: $10^{10}$ values, about 80 GB. Too much.
In one breath

Only the points on or inside the margin (support vectors) shape the SVM; kernels give the power of huge feature spaces for the cost of a similarity; tune C and gamma together on a log grid; the SVM is hinge loss plus a ridge penalty, a close cousin of logistic regression; and for big data use linear SVMs or kernel approximations.

Hidden questions — answer in your head first, then open.

Explain the SVM dual problem and why it matters.

The trap: Saying it's "just another way to write it".

Introducing Lagrange multipliers $\alpha_i$ for the margin constraints and eliminating $\mathbf{w}$ gives a problem over the $\alpha_i$ with box constraints $0 \le \alpha_i \le C$. It matters for two reasons: the KKT conditions make most $\alpha_i$ zero, so the solution depends only on the support vectors; and the data enters only through dot products, which can be replaced by any valid kernel, giving non-linear boundaries without computing high-dimensional features.

What makes a function a valid kernel?

The trap: "Any similarity function works."

Mercer's condition: it must be symmetric, and for any set of points the matrix of its values must be positive semi-definite. Then it equals a dot product in some (possibly infinite-dimensional) feature space. Sums, positive multiples and products of valid kernels are valid. Arbitrary similarity scores can fail this, making the SVM optimisation ill-posed.

Linear SVM or logistic regression: how do you choose?

The trap: Claiming one is always more accurate.

Accuracy is usually very close, because both are linear models with a regularized convex loss (hinge vs log loss). Choose logistic regression when you need calibrated probabilities or easy interpretation of odds; a linear SVM when you only need decisions and want a pure max-margin boundary, or in very high-dimensional sparse text where it's a strong default. Kernel SVMs are a different choice, for small to medium data with non-linear boundaries.

Check your understanding: going deeper

1. In the SVM dual, a training point safely outside the margin has…

Only support vectors (on or inside the margin) have non-zero $\alpha_i$.

2. Why can the SVM use kernels?

Swap every $\mathbf{x}_i\cdot\mathbf{x}_j$ for $K(\mathbf{x}_i, \mathbf{x}_j)$.

3. An RBF SVM has 100% training accuracy and much lower test accuracy. Which change is most likely to help?

Large gamma and C give a wiggly, overfit boundary.

4. The hinge loss for a point with $y\,f(\mathbf{x}) = 2$ is…

$\max(0, 1 - 2) = 0$: confidently correct points cost nothing.

5. Which statement about linear SVMs and logistic regression is true?

Both minimise a regularized loss; log loss is a smooth version of the hinge.
