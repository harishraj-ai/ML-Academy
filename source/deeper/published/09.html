17.Going deeper: comparing models honestly

In plain wordsHow to compare models without fooling yourself: error bars on every score, a paired test that only looks at disagreements (McNemar), setting the threshold from what mistakes cost, and why ROC-AUC looks fine while precision collapses when positives are rare.

New words for this section
  • Estimate: a number computed from a sample, which would change with a different sample.
  • Bootstrap: resample the test cases with repeats allowed, recompute, and repeat many times.
  • Paired comparison: both models judged on exactly the same cases.
  • p-value: if there were no real difference, the chance of a result at least this lopsided.
  • Prevalence: the share of positives.
  • Average precision (AP): the area under the precision–recall curve.

Every score needs an error bar

Picture it

A test set is like one exam paper. A student who scores 92% might score 89% or 95% on a different paper with similar questions. A model's test score wobbles in the same way, and the error bar says by how much.

Worked example — how much one case is worth
  1. 171 test cases.
  2. One case $=1/171\approx0.6$ percentage points of accuracy.
  3. So 95.3% vs 94.7% can be a single case's difference.
  4. Formula for accuracy's wobble: $\sqrt{p(1-p)/n}=\sqrt{0.95\times0.05/171}\approx0.017$, about ±1.7 points.

For AUC, F1 or precision there's no simple formula, so use the bootstrap: resample the 171 test cases with replacement, recompute the score, repeat thousands of times, and take the middle 95%. When comparing two models, bootstrap the difference on the same resampled cases, because both models tend to do well or badly on the same easy or hard cases.

Here logistic regression and a depth-3 decision tree (Lesson 13) are compared on the same 171 breast-cancer test cases:

import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline
from sklearn.linear_model import LogisticRegression
from sklearn.tree import DecisionTreeClassifier
from sklearn.metrics import roc_auc_score

X, y = load_breast_cancer(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)
logreg = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000)).fit(Xtr, ytr)
tree = DecisionTreeClassifier(max_depth=3, random_state=0).fit(Xtr, ytr)
p_lr, p_tr = logreg.predict_proba(Xte)[:, 1], tree.predict_proba(Xte)[:, 1]

rng = np.random.default_rng(0)
boot = []
for _ in range(2000):
    i = rng.integers(0, len(yte), len(yte))            # resample test cases with replacement
    if len(np.unique(yte[i])) == 2:
        boot.append(roc_auc_score(yte[i], p_lr[i]) - roc_auc_score(yte[i], p_tr[i]))
print("AUC: logistic", round(roc_auc_score(yte, p_lr), 3), " tree", round(roc_auc_score(yte, p_tr), 3))
print("95% bootstrap interval for the difference:", np.round(np.percentile(boot, [2.5, 97.5]), 3))

Output:

AUC: logistic 0.996  tree 0.904
95% bootstrap interval for the difference: [0.046 0.15 ]

How to read it: AUC 0.996 vs 0.904. The 95% interval for the difference, 0.046 to 0.15, doesn't include 0, so the gap is very unlikely to be luck of this test set. If the interval had crossed 0, the honest conclusion would be "no clear winner".

Paired tests: McNemar's test

Picture it

To find out which of two judges is better, only look at the cases where they disagreed. If they were equally good, each disagreement would be like a coin flip: sometimes one is right, sometimes the other.

from scipy import stats

# McNemar's test: do the two models make different numbers of mistakes on the SAME cases?
right_lr, right_tr = logreg.predict(Xte) == yte, tree.predict(Xte) == yte
b = np.sum(right_lr & ~right_tr)          # logistic right, tree wrong
c = np.sum(~right_lr & right_tr)          # tree right, logistic wrong
print("accuracy: logistic", round(right_lr.mean(), 3), " tree", round(right_tr.mean(), 3))
print("cases only logistic got right:", b, "  only the tree got right:", c)
print("McNemar exact p-value:", round(stats.binomtest(b, b + c, 0.5).pvalue, 4))

Output:

accuracy: logistic 0.959  tree 0.901
cases only logistic got right: 11   only the tree got right: 1
McNemar exact p-value: 0.0063
Worked example — McNemar by hand
  1. Disagreements: 11 only logistic right, 1 only the tree right; 12 in total.
  2. If equally good, it's 12 coin flips. Chance of 11 or more heads: $(12+1)/2^{12}=13/4096\approx0.0032$.
  3. Either direction counts (two-sided): $2\times0.0032\approx$ 0.0063, the p-value shown.
  4. So logistic regression is very likely more accurate here.

Notice that the overall accuracies (0.959 vs 0.901) don't decide this; the number of disagreements does. With cross-validation the folds overlap, which makes ordinary t-tests over-confident; the corrected resampled t-test or the 5×2 cross-validation test are designed for that case.

Choosing the threshold from costs

Picture it

Missing a tumour is far worse than sending someone for an extra test. So a doctor should order the test even when the chance of a tumour is fairly small. The threshold is a business (or medical) decision, not a statistics one.

If a missed positive costs $c_{FN}$ and a false alarm costs $c_{FP}$: flagging a case with probability $p$ costs $c_{FP}(1-p)$ on average (it might be negative), and not flagging costs $c_{FN}\,p$ (it might be positive). Flag when not flagging would cost more:

$$p > \frac{c_{FP}}{c_{FP} + c_{FN}}$$

Worked example — threshold for missed tumour = 20, false alarm = 1
  1. Threshold $=1/(1+20)=1/21\approx0.048$.
  2. A case with probability 0.1: flagging costs $1\times0.9=0.9$; not flagging costs $20\times0.1=2$. Flag it.
  3. A case with 0.03: flagging costs 0.97; not flagging costs 0.6. Don't flag.

This only works if the probabilities are calibrated (Lesson 8's Going deeper). Now the real data:

# Choosing the threshold from costs: a missed cancer (false negative) costs 20, a false alarm costs 1
y_bad = 1 - yte                            # in this dataset 0 = malignant, so flip: 1 = malignant
p_bad = 1 - p_lr
for t in [0.5, 0.2, 0.1, 0.05]:
    flag = p_bad >= t
    fn, fp = np.sum(~flag & (y_bad == 1)), np.sum(flag & (y_bad == 0))
    print(f"threshold {t:4.2f}: missed {fn:2d}, false alarms {fp:2d}, total cost {20 * fn + fp}")
print("theory: flag when p is above cost_FP / (cost_FP + cost_FN), which is", round(1 / 21, 3))

Output:

threshold 0.50: missed  3, false alarms  4, total cost 64
threshold 0.20: missed  2, false alarms  7, total cost 47
threshold 0.10: missed  1, false alarms 11, total cost 31
threshold 0.05: missed  0, false alarms 18, total cost 18
theory: flag when p is above cost_FP / (cost_FP + cost_FN), which is 0.048

How to read it: at the default 0.5, three tumours are missed (cost $3\times20=60$) plus 4 false alarms (cost 4): total 64. At 0.05, close to the theoretical 0.048, nothing is missed and there are 18 false alarms: total cost 18, less than a third. In a real project, choose the threshold on validation data and confirm on the test set.

ROC-AUC vs average precision when positives are rare

Picture it

An alarm that wrongly rings for 1 in 100 innocent people sounds good. But if only 1 in 1,000 people is guilty, almost every alarm is false. ROC-AUC doesn't notice this; precision does.

ROC curves use two rates measured within each class (true-positive rate among positives, false-positive rate among negatives), so they don't change when positives get rarer. Precision mixes the classes, so it does. Below, the model's scores are exactly as good in every row; only the share of positives changes:

from sklearn.metrics import average_precision_score

# Same model quality, rarer positives: scores of positives ~ N(1.5, 1), negatives ~ N(0, 1)
rng = np.random.default_rng(1)
for n_pos in [10000, 1000, 100]:
    s = np.r_[rng.normal(1.5, 1, n_pos), rng.normal(0, 1, 10000)]
    t = np.r_[np.ones(n_pos), np.zeros(10000)]
    print(f"positives {t.mean():6.1%}: ROC-AUC {roc_auc_score(t, s):.3f}   average precision {average_precision_score(t, s):.3f}   (random model's AP {t.mean():.3f})")

Output:

positives  50.0%: ROC-AUC 0.857   average precision 0.855   (random model's AP 0.500)
positives   9.1%: ROC-AUC 0.860   average precision 0.451   (random model's AP 0.091)
positives   1.0%: ROC-AUC 0.867   average precision 0.136   (random model's AP 0.010)
Worked example — why precision collapses
  1. 10,000 people, 1% positive: 100 positives, 9,900 negatives.
  2. The model catches 80 positives and wrongly flags 5% of negatives: 495.
  3. Precision $=80/(80+495)\approx0.14$: only 1 alert in 7 is real.
  4. Same model with 50% positives: 4,000 caught vs 250 false → precision 0.94.

How to read the output: ROC-AUC stays near 0.86 in every row; average precision falls from 0.855 to 0.136. They answer different questions: ROC-AUC asks "is a random positive ranked above a random negative?", average precision asks "when the model raises an alert, how often is it right?". For fraud, defects or rare diseases the second is what users experience. Always compare AP with its baseline, the share of positives (a random model's AP).

In one breath

Every score is an estimate, so give it an error bar; compare models on the same cases with a paired bootstrap or McNemar's test; set the threshold from the cost of each mistake; with rare positives report average precision next to its baseline; and always include a simple baseline.

Interview corner · intermediate

Hidden questions — answer in your head first, then open.

Model A scores 0.851 accuracy and model B 0.846 on the same test set. Which do you ship?

The trap: Picking A because the number is bigger.

First check whether the difference is real: use a paired test on the same cases (McNemar, or a paired bootstrap of the difference). With a few thousand test cases, 0.5 points is often within noise. If there's no clear difference, choose on other grounds: simplicity, speed, cost of errors on the business metric, calibration, fairness across groups, or how easy each is to maintain and explain.

How do you choose a classification threshold?

The trap: "Use 0.5" or "maximise F1" by default.

Ideally from costs: with calibrated probabilities, flag when $p > c_{FP}/(c_{FP} + c_{FN})$. Without clear costs, use an operating constraint, such as recall of at least 95% or at most 100 alerts per day, and choose the threshold on validation data, then confirm on the test set. Revisit it when the base rate changes, since precision depends on it.

When would you report average precision (PR-AUC) instead of ROC-AUC?

The trap: Saying ROC-AUC is "wrong" for imbalanced data.

When positives are rare and what matters is the quality of the alerts. ROC-AUC is unaffected by class balance, so it can look high while most alerts are false; average precision reflects that directly. Report AP together with its baseline (the positive rate). ROC-AUC is still useful for ranking quality and for comparing across datasets with different balance.

Why can't you use an ordinary t-test on the 10 fold scores of 10-fold cross-validation to compare two models?

The trap: Thinking the 10 scores are independent samples.

The training sets of different folds overlap by about 89%, so the fold scores are correlated and their variance is underestimated. A standard t-test then claims significance far too often. Use the corrected resampled t-test (Nadeau–Bengio), the 5×2 cross-validation test, or repeated CV with a correction, or compare on a single large held-out set with a paired test.

Check your understanding: going deeper

1. Two models disagree on 30 test cases: model A is right on 16 of them and model B on 14. What does McNemar's test suggest?

A 16–14 split is just what coin flips would give. Only the disagreements matter, and they are nearly balanced.

2. A false negative costs 9 and a false positive costs 1. With calibrated probabilities, flag cases with $p$ above…

$c_{FP}/(c_{FP} + c_{FN}) = 1/10 = 0.1$.

3. Positives become 10 times rarer, but the model's score distributions for each class stay the same. ROC-AUC will…

TPR and FPR are each measured within one class, so class balance doesn't change the ROC curve. Precision and average precision do fall.

4. On a dataset with 2% positives, a model's average precision is 0.10. Compared with random guessing, that is…

A random model's AP equals the positive rate, 0.02, so 0.10 is five times that, though still low in absolute terms.

5. To compare two models' AUCs with the bootstrap, you should…

Pairing removes the shared variation from the test set's difficulty, so the comparison is much more sensitive.
