New words for this section
  • Hidden state: what you can't see (the weather).
  • Observation: what you can see (your friend's activity).
  • Forward pass $\alpha$: a summary of all evidence up to today.
  • Backward pass $\beta$: a summary of all evidence after today.
  • EM: repeat: guess the hidden parts, then refit the parameters.

Each day's probabilities: forward–backward

Picture it

To guess whether it rained on Wednesday, use what happened before Wednesday and after it: if Thursday was a cleaning day too, rain on Wednesday becomes more likely. Forward–backward combines evidence from both directions for every day.

Viterbi gives one best path. Often you want the probability of each state on each day, given all observations. The forward pass $\alpha$ summarises the past, the backward pass $\beta$ the future, and their product, normalised, gives $P(z_t \mid x_{1:n})$.

Worked example — combining both directions for one day
  1. Forward (past) evidence says: rainy 0.4, sunny 0.6.
  2. Backward (future) evidence: the future is twice as likely if today is rainy (0.2 vs 0.1).
  3. Multiply: rainy $0.4\times0.2=0.08$, sunny $0.6\times0.1=0.06$.
  4. Normalise: rainy $0.08/0.14\approx0.57$. The future tipped the balance.
import numpy as np
pi = np.array([0.6, 0.4]); T = np.array([[0.8, 0.2], [0.3, 0.7]]); E = np.array([[0.6, 0.3, 0.1], [0.1, 0.4, 0.5]])
obs = [0, 1, 1, 2, 1, 0]                                   # Walk Shop Shop Clean Shop Walk
def forward_backward(o):
    n = len(o); a = np.zeros((n, 2)); b = np.ones((n, 2))
    a[0] = pi * E[:, o[0]]
    for t in range(1, n): a[t] = (a[t - 1] @ T) * E[:, o[t]]
    for t in range(n - 2, -1, -1): b[t] = T @ (E[:, o[t + 1]] * b[t + 1])
    post = a * b
    return post / post.sum(axis=1, keepdims=True)
print("P(rainy) each day:", np.round(forward_backward(obs)[:, 1], 3).tolist())

Output:

P(rainy) each day: [0.14, 0.417, 0.588, 0.741, 0.488, 0.157]

How to read it: P(rain) rises through two shopping days to 0.741 on the cleaning day, then falls as activities return to shopping and walking. Day 5's 0.488 is genuinely uncertain, something Viterbi's single path hides. Use these per-day probabilities for decisions with costs; they're also the "expectation" step of Baum–Welch.

Learning from observations alone: Baum–Welch

Picture it

Like EM for clustering: guess which hidden state each day was in, count up how often states followed each other and what each state led your friend to do, refit the numbers from those counts, and repeat until they settle.

  1. E-step: forward–backward with the current parameters gives the expected state each day and the expected number of each transition.
  2. M-step: re-estimate the parameters from those expected counts.
Worked example — one M-step count
  1. Forward–backward says: over all days, about 120 "rainy → rainy" transitions and 40 "rainy → sunny" are expected.
  2. New P(rainy → rainy) $=120/(120+40)=0.75$.
  3. Repeat with the new parameters; each round increases the likelihood.

Here it starts from a rough guess and sees only 3,000 activities:

rng = np.random.default_rng(0)
z = [0]
for _ in range(2999): z.append(rng.choice(2, p=T[z[-1]]))
o = np.array([rng.choice(3, p=E[s]) for s in z])
# Baum–Welch from the observations only, starting from a rough guess
Th, Eh, ph = np.array([[0.6, 0.4], [0.4, 0.6]]), np.array([[0.4, 0.3, 0.3], [0.2, 0.3, 0.5]]), np.array([0.5, 0.5])
for it in range(50):
    n = len(o); a = np.zeros((n, 2)); b = np.ones((n, 2)); c = np.zeros(n)
    a[0] = ph * Eh[:, o[0]]; c[0] = a[0].sum(); a[0] /= c[0]
    for t in range(1, n): a[t] = (a[t - 1] @ Th) * Eh[:, o[t]]; c[t] = a[t].sum(); a[t] /= c[t]
    for t in range(n - 2, -1, -1): b[t] = Th @ (Eh[:, o[t + 1]] * b[t + 1]) / c[t + 1]
    gam = a * b
    xi = np.einsum("ti,ij,tj->ij", a[:-1], Th, Eh[:, o[1:]].T * b[1:] / c[1:, None])
    Th = xi / xi.sum(axis=1, keepdims=True)
    Eh = np.array([[gam[o == k, i].sum() for k in range(3)] for i in range(2)]) / gam.sum(axis=0)[:, None]
    ph = gam[0]
print("log-likelihood after 50 iterations:", round(float(np.log(c).sum()), 1))
print("learned transitions:", np.round(Th, 2).tolist())
print("learned emissions:  ", np.round(Eh, 2).tolist())

Output:

log-likelihood after 50 iterations: -3208.4
learned transitions: [[0.75, 0.25], [0.25, 0.75]]
learned emissions:   [[0.65, 0.29, 0.07], [0.16, 0.39, 0.45]]

How to read it: without a single weather label, it learns transitions of 0.75/0.25 (true 0.8/0.2) and emissions close to the truth. Not exact, because it learns from noisy observations only. Scaling by $c_t$ at each step stops probabilities underflowing to 0 on long sequences. Like all EM methods it can stop at a local optimum, so run it from several starting guesses and keep the highest likelihood.

In one breath

Forward–backward combines evidence from before and after each day to give every day's state probabilities; Baum–Welch uses those to learn the model's numbers from unlabelled sequences, from several starting guesses.

Hidden questions — answer in your head first, then open.

Explain the difference between filtering, smoothing and decoding in an HMM.

The trap: Treating them as the same thing.

Filtering computes P(z_t | x_1..x_t), the current state given the past only (the forward algorithm, normalised): used for real-time monitoring. Smoothing computes P(z_t | x_1..x_n), using past and future (forward–backward): more accurate, for analysis after the fact. Decoding finds the single most likely whole sequence of states (Viterbi), which can differ from picking each day's most likely state.

Check your understanding: going deeper

1. What does forward–backward give that Viterbi doesn't?

Viterbi gives one path without uncertainty.

2. In forward–backward, the backward pass summarises…

Forward covers the past; backward the future.

3. Baum–Welch is an example of…

It alternates expected counts and re-estimation.

4. Why scale the forward probabilities at each step?

Products of many probabilities get tiny.

5. Why run Baum–Welch from several starting points?

Keep the run with the highest likelihood.
