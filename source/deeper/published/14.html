New words for this section
  • Correlation $\rho$: how similar two models' mistakes are (1 = identical, 0 = unrelated).
  • Out-of-bag (OOB): rows a tree didn't see in its bootstrap sample; used as a free validation set.
  • Learning rate / shrinkage: how much of each new boosting tree's correction is kept.
  • Gradient $g$ / curvature $h$: slope and bend of the loss for one row.
  • Out-of-fold prediction: a prediction made by a model that never trained on that row.

Why averaging works: correlation is the limit

Picture it

Asking 100 people to guess a jar of sweets works because their errors cancel out. But if they all copied the same person, you just have one guess written 100 times. Averaging only helps as much as the guessers think independently.

If $B$ models each have variance $\sigma^2$ and every pair has correlation $\rho$, their average has variance

$$\operatorname{Var}(\text{average}) = \rho\,\sigma^2 + \frac{1-\rho}{B}\,\sigma^2$$

The second part shrinks as you add trees; the first part never does. Correlation sets the floor.

Worked example — the floor in numbers ($\sigma^2=1$, 100 trees)
  1. Independent trees ($\rho=0$): $0+1/100=0.01$.
  2. $\rho=0.83$ (plain bagging here): $0.83+0.17/100\approx0.83$.
  3. $\rho=0.70$: $\approx0.70$. Lower correlation, lower floor.

That's why a random forest lets each split look at only a random subset of features (max_features): it makes trees disagree more.

import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier

X, y = load_breast_cancer(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)
# max_features controls how different the trees are
for mf in [1.0, 0.5, "sqrt", 1]:
    rf = RandomForestClassifier(n_estimators=300, max_features=mf, oob_score=True, random_state=0, n_jobs=-1).fit(Xtr, ytr)
    preds = np.array([t.predict(Xte) for t in rf.estimators_])
    corr = np.corrcoef(preds)[np.triu_indices(len(preds), 1)].mean()
    print(f"max_features {str(mf):5}: tree-to-tree correlation {corr:.2f}   out-of-bag accuracy {rf.oob_score_:.3f}   test {rf.score(Xte, yte):.3f}")

Output:

max_features 1.0  : tree-to-tree correlation 0.83   out-of-bag accuracy 0.960   test 0.930
max_features 0.5  : tree-to-tree correlation 0.82   out-of-bag accuracy 0.957   test 0.942
max_features sqrt : tree-to-tree correlation 0.80   out-of-bag accuracy 0.967   test 0.953
max_features 1    : tree-to-tree correlation 0.70   out-of-bag accuracy 0.965   test 0.936

How to read it: using all features (1.0, plain bagging), trees correlate 0.83 and test accuracy is 0.930. With $\sqrt{30}\approx5$ features per split, correlation drops to 0.80 and accuracy rises to 0.953. With just 1 feature, correlation falls to 0.70 but each tree is so weak that accuracy dips (0.936). The default "sqrt" is a good middle. The OOB accuracy tracks the right ordering without a separate validation set.

Tuning gradient boosting: learning rate and early stopping

Picture it

Correcting an essay with many small careful edits usually beats a few big rewrites. A smaller learning rate keeps only part of each tree's correction, so you need more trees, but the result is usually better. Early stopping tells you when to stop adding them.

from sklearn.ensemble import HistGradientBoostingClassifier

for lr in [1.0, 0.3, 0.1, 0.03]:
    gb = HistGradientBoostingClassifier(learning_rate=lr, max_iter=2000, early_stopping=True,
                                        validation_fraction=0.2, n_iter_no_change=30, random_state=0).fit(Xtr, ytr)
    print(f"learning rate {lr:4}: trees used {gb.n_iter_:4d}   test accuracy {gb.score(Xte, yte):.3f}")

Output:

learning rate  1.0: trees used   35   test accuracy 0.924
learning rate  0.3: trees used   49   test accuracy 0.942
learning rate  0.1: trees used   83   test accuracy 0.947
learning rate 0.03: trees used  203   test accuracy 0.936
Worked example — reading the rows
  1. Rate 1.0: stops after 35 trees, 0.924.
  2. Rate 0.1: 83 trees, 0.947.
  3. Rate 0.03: 203 trees, 0.936 (differences this small are within test-set noise).

Rule of thumb: halving the learning rate roughly doubles the trees needed.

The usual recipe: pick a modest learning rate (0.05–0.1), let early stopping choose the number of trees, then tune tree size (depth or leaves) and regularization.

What XGBoost, LightGBM and CatBoost add

Picture it

Plain boosting knows which way is downhill (the slope). XGBoost also knows how curved the ground is, so it knows how far to step. And it charges a fee for every new leaf, so it only grows branches that clearly pay off.

Plain gradient boosting fits each new tree to the slopes of the loss. XGBoost adds three things:

  • Newton steps. It uses each row's slope $g_i$ and curvature $h_i$ (Lesson 3's Going deeper). The best value for a leaf is then $w^* = -\dfrac{\sum g_i}{\sum h_i + \lambda}$.
  • Built-in penalty. A cost $\gamma$ per leaf plus $\frac{\lambda}{2}\sum w_j^2$ on leaf values. A split happens only if its gain beats $\gamma$, which prunes automatically.
  • Engineering: learns where missing values go, runs in parallel, handles sparse data.
Worked example — one leaf value
  1. Three rows in a leaf with slopes $g=-2, -1, 0$ (sum −3) and curvatures $h=1,1,1$ (sum 3). Penalty $\lambda=1$.
  2. $w^*=-(-3)/(3+1)=0.75$.
  3. Without the penalty it would be $3/3=1$; $\lambda$ shrinks leaf values, like ridge.

LightGBM speeds this up by binning each feature (about 255 bins) and growing the leaf with the biggest gain first. Scikit-learn's HistGradientBoostingClassifier, used above, follows the same design. CatBoost handles categories directly with leak-safe target statistics. On most tables the three are close; tuning matters more than the library.

Stacking: combining different models

Picture it

A team captain who listens to several experts and learns how much to trust each. To judge them fairly, the captain must test them on questions they didn't prepare for, otherwise everyone looks brilliant.

Stacking trains several different models, then a simple "blender" (often logistic regression) that learns how to weight them. The blender must learn from out-of-fold predictions; otherwise it sees predictions on rows the models memorised, which is leakage (Lesson 5).

from sklearn.ensemble import StackingClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.neighbors import KNeighborsClassifier

base = [("forest", RandomForestClassifier(n_estimators=300, random_state=0)),
        ("boost", HistGradientBoostingClassifier(random_state=0)),
        ("knn", make_pipeline(StandardScaler(), KNeighborsClassifier(15)))]
for name, m in base:
    print(f"{name:7}: test accuracy {m.fit(Xtr, ytr).score(Xte, yte):.3f}")
stack = StackingClassifier(base, final_estimator=LogisticRegression(max_iter=1000), cv=5).fit(Xtr, ytr)
print(f"stacked: test accuracy {stack.score(Xte, yte):.3f}   blender weights {stack.final_estimator_.coef_.round(2)}")

Output:

forest : test accuracy 0.953
boost  : test accuracy 0.942
knn    : test accuracy 0.942
stacked: test accuracy 0.942   blender weights [[2.84 2.28 3.05]]

How to read it: the stack scores 0.942, no better than the forest alone (0.953). That's a common, honest result. Stacking helps most when the base models are strong and make different kinds of mistakes, and with 171 test cases small gains are invisible anyway. It's popular in competitions; in production the extra complexity often isn't worth it.

In one breath

Averaging helps only as much as trees disagree, so forests randomise features; use a modest learning rate with early stopping; XGBoost-style libraries add Newton steps and a price per leaf; and stack only strong models that make different mistakes, using out-of-fold predictions.

Interview corner · intermediate

Hidden questions — answer in your head first, then open.

What does XGBoost do differently from classic gradient boosting?

The trap: "It's just faster."

It optimises a regularized objective with a second-order (Newton) approximation: each point contributes a gradient $g_i$ and curvature $h_i$, leaf values have the closed form $-\sum g/(\sum h + \lambda)$, and a split's gain must exceed $\gamma$ (a cost per leaf). It also learns default directions for missing values, uses column and row subsampling, and is engineered for parallel, sparse and out-of-core data.

How would you tune a gradient-boosted model in limited time?

The trap: Grid-searching everything at once.

Fix a moderate learning rate (0.05–0.1) and use early stopping on a validation set to pick the number of trees. Then tune tree complexity (max_depth or num_leaves, min samples per leaf), then subsampling (rows and columns) and L2 regularization, using random or Bayesian search with cross-validation. Finally, lower the learning rate, raise the tree limit, and refit with early stopping for a small final gain.

Why does a random forest choose features randomly at each split, in terms of the variance formula?

The trap: "To be random."

The variance of an average of $B$ trees is $\rho\sigma^2 + (1-\rho)\sigma^2/B$. Adding trees only shrinks the second term; the first, set by the correlation $\rho$ between trees, remains. Bootstrap samples alone leave trees highly correlated, because the strongest features dominate every tree's top splits. Random feature subsets lower $\rho$, and so the floor, at the cost of slightly weaker individual trees.

Check your understanding: going deeper

1. Averaging 1,000 trees that are perfectly correlated ($\rho = 1$) reduces variance by…

$\rho\sigma^2 + (1-\rho)\sigma^2/B = \sigma^2$ when $\rho = 1$. Identical trees give no benefit.

2. In a random forest, lowering max_features…

Fewer candidate features per split means more disagreement between trees, at the cost of individual accuracy.

3. If you halve gradient boosting's learning rate, you usually need about…

Each tree corrects half as much. Let early stopping pick the exact number.

4. XGBoost's leaf value $w^* = -\sum g_i / (\sum h_i + \lambda)$ uses…

It's a regularized Newton step for each leaf.

5. Why must a stacking blender be trained on out-of-fold predictions?

Base models fit their own training rows too well; the blender needs predictions like those on new data.
