Going deeper: indexes, NULL logic and rolling features

Intermediate · skip on a first read

Three things that separate working SQL from good SQL: making queries fast on big tables (indexes and query plans), understanding how NULL really behaves (it trips up even experienced analysts), and building rolling time-window features with window frames, which is how many production feature pipelines are written.

You'll need: this lesson.

Indexes and query plans

Without help, the database answers "find house 42's viewings" by reading every row: a full scan. An index is a sorted lookup structure (usually a B-tree) on one or more columns; with it the database can jump straight to the matching rows in about $\log n$ steps instead of $n$. EXPLAIN QUERY PLAN shows which strategy the database chose:

On 200,000 viewings, the plan changes from SCAN (read everything) to SEARCH ... USING COVERING INDEX (jump to house 42's 37 rows). "Covering" means the index alone contains every column the query needs, so the table itself isn't read at all. Index the columns you filter and join on most. Indexes cost disk space and slow down inserts, so don't index everything. On analytical warehouses (BigQuery, Snowflake) the equivalents are partitioning and clustering, and you pay per data scanned, so filtering on the partition column (usually a date) saves real money.

NULL: three-valued logic

In SQL, NULL means "unknown", and a comparison with an unknown value is itself unknown, neither true nor false. WHERE keeps only rows where the condition is true:

Row 1 (discount 10) passes discount > 5. But NOT (discount > 5) returns only row 3, not rows 2, 3 and 4: for the NULL rows, "unknown" negated is still unknown. discount = NULL matches nothing at all; only IS NULL finds the missing values. Aggregates skip NULLs: COUNT(discount) is 2, not 4, and AVG averages only the two known values (5.0), which is different from treating missing as 0 (that would give 2.5). Decide explicitly what missing means, and use COALESCE(discount, 0) only when it truly means zero.

Rolling features with window frames

A window frame such as ROWS BETWEEN 6 PRECEDING AND CURRENT ROW limits the window to the current row and the six before it, giving a rolling 7-day total. LAG fetches the previous row's value. Together they produce standard time-series features (Lesson 26) directly in the database:

On day 9, views_7d is 9: the views from days 3 to 9 ($1 + 0 + 3 + 1 + 0 + 0 + 4$). Day 1 has no previous day, so views_yesterday is NULL (shown as NaN in pandas). Two cautions for ML: if the prediction for day $d$ is made at the start of day $d$, the frame must end at the previous row (1 PRECEDING), not CURRENT ROW, or the day's own views leak in. And ROWS counts rows, not days: with missing days, use RANGE BETWEEN 6 PRECEDING AND CURRENT ROW on a numeric day column, or fill in the missing days first.
